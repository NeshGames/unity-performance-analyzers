# unity-performance-analyzers — AI repository index

This repository is optimized for maintenance by coding agents rather than for public product
marketing. **Do not treat this README as a source of truth for rule metadata, release versions,
preset contents, or performance claims.**

## Mission

`unity-performance-analyzers` is a Unity 6 Roslyn analyzer package plus `upa-cli`.
It catches performance, correctness, ecosystem and WebGL problems early enough for an agent to
fix them before a Unity build or CI gate.

Current platform contract:

- Unity 6 only; older Unity compatibility is intentionally not a goal.
- Analyzer target: `netstandard2.0`.
- Roslyn dependency floor: 4.3.1.
- Compiler-load smoke: Roslyn 4.3.1 and 4.10.
- Diagnostics are English; per-rule documentation may have translations.
- Primary consumers: Unity compile, `upa-cli`, Claude Code and Codex.

## Change workflow

The exact validation commands live in [AGENTS.md](AGENTS.md). The expected sequence is:

```text
understand existing contract
→ change the smallest source of truth
→ add/update regression tests
→ add Unity/IL2CPP evidence when the claim is about performance
→ regenerate generated artifacts
→ build + test
→ compiler-load smoke
→ update [Unreleased]
```

### Changing a rule

Before modifying a `UPA####` analyzer:

- read its English rule page;
- inspect its existing tests and any corpus/measurement evidence;
- preserve the bias toward false negatives when a suggested rewrite could alter behaviour;
- keep hot-path classification in `HotPathDetector`;
- keep package detection in `UpaProfile`;
- record release-tracking changes when Roslyn requires them;
- never reuse a retired rule ID for a different meaning.

A new performance rule is not ready merely because the Roslyn analysis is plausible. It needs a
Unity IL2CPP measurement with a control before being enabled in a shipping preset.

### Changing CLI or CI

`upa-cli` is a first-class agent interface. Preserve these semantics unless the change is
deliberately breaking and documented:

- exit 0: clean;
- exit 1: diagnostics met the failure threshold;
- exit 2: usage/execution/analyzer/whole-assembly failure;
- JSON output must remain machine-readable on stdout;
- partial compilation must never be presented as authoritative clean analysis.

## Generated files

Do not hand-edit files generated by `UnityPerformanceAnalyzers.RuleManifest`, especially:

- `package/Samples~/Ruleset Presets/*.ruleset`;
- `sandbox/UnityProject/Assets/Default.ruleset`;

The root README is deliberately **not generated**.

## Things agents should not add back

Unless the maintainer explicitly changes direction, do not reintroduce:

- support for Unity versions older than Unity 6;
- IDE-only code fixes, localization surfaces, or configuration UI;
- a duplicated root-language README;
- generated rule tables in the root README;
- a hand-maintained rule catalog in prose;
- performance rules justified only by .NET/IL reasoning without Unity IL2CPP evidence;
- compatibility branches, presets, output formats or release machinery for hypothetical users.
