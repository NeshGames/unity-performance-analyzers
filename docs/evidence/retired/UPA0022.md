# Retired evidence — UPA0022 Enum.HasFlag

UPA0022 was retired because its performance premise does not hold on the Unity runtimes this
repository targets. The live analyzer, resources, tests, presets and rule page were removed in
AF-05A; the diagnostic ID remains reserved in `RetiredRuleIds`.

## Measurement that retired the rule

The original rule assumed `Enum.HasFlag` boxed its receiver and argument and should be rewritten
as a bitwise check. Mono has special-cased the same-type call since 4.0 and IL2CPP since Unity
2021.2, replacing it with a bitwise AND.

Measured with 200,000 iterations and three repeats:

| Runtime | `x.HasFlag(y)` allocation | `x.HasFlag(y)` | `(x & y) == y` |
|---|---:|---:|---:|
| Unity 2022.3, Mono | 0 B | 5.20 ns | 5.38 ns |
| Unity 6, Mono | 0 B | 5.55 ns | 5.02 ns |
| Unity 2022.3, IL2CPP | 0 B | 1.20 ns | 1.58 ns |
| Unity 6, IL2CPP | 0 B | 1.18 ns | 1.59 ns |

On IL2CPP, the rewrite UPA0022 used to recommend was slower and less readable. That is enough to
retire a performance rule whose suggested rewrite cannot demonstrate a benefit.

A conditional expression passed inline to `HasFlag` can still leave an argument box; that is an
allocation concern for UPA0006 rather than a reason to restore UPA0022.
