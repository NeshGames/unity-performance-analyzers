# Retired evidence — UPA0021 magnitude/Distance rewrite

UPA0021 was retired in AF-05B. Its live analyzer, tests, resources, preset rows and rule pages
were removed; the diagnostic ID remains permanently reserved in `RetiredRuleIds`.

## Unity IL2CPP measurement

The sandbox compares `Vector3.Distance(a, b) < 5f` with
`(a - b).sqrMagnitude < 25f` over 200,000 iterations:

| Runtime | `Vector3.Distance` comparison | `sqrMagnitude` comparison | difference |
|---|---:|---:|---:|
| Unity 2022.3 IL2CPP | 2.84 ns/op | 1.77 ns/op | 1.07 ns/op |
| Unity 6 IL2CPP | 2.76 ns/op | 2.04 ns/op | 0.72 ns/op |

Source measurements:

- `sandbox/UnityProject/Measurements/allocation-2022.3.62f2-IL2CPP-NET_Standard_2_0.txt`
- `sandbox/UnityProject/Measurements/allocation-6000.5.3f1-IL2CPP-NET_Standard_2_0.txt`

The premise is therefore true: avoiding the square root is faster. The absolute Unity 6 payoff,
however, is under one nanosecond per comparison.

## Why the diagnostic was removed

The rule was not limited to a proven hot path, so it could spend review attention throughout
gameplay code for a sub-nanosecond saving. More importantly, the general advice is not
semantics-preserving for every runtime threshold. A negative threshold changes meaning when
squared; for example, `magnitude > threshold` is always true for a negative threshold, while
`sqrMagnitude > threshold * threshold` is not.

For an agent-first suite, that combination — tiny absolute benefit, broad scope, and a rewrite
with a semantic caveat — is not strong enough to justify a diagnostic. Code that performs very
large numbers of distance comparisons should be optimized from profiler evidence rather than by
a universal rule.
