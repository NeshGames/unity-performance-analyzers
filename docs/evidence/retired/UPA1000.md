# Retired evidence — UPA1000 Leaf class not sealed

UPA1000 was retired because the repository could not measure a stable performance benefit from
sealing leaf classes. The live analyzer, resources, tests, presets and rule page were removed in
AF-05A; the diagnostic ID remains reserved in `RetiredRuleIds`.

## Measurement that retired the rule

The rule assumed that marking a leaf class `sealed` would let runtime/IL2CPP devirtualize calls.
A one-derived-class probe could not distinguish the variants because whole-program analysis can
already devirtualize a hierarchy with one implementation. A wider probe with four derived classes,
repeated eight times on IL2CPP, produced:

| | sealed | unsealed |
|---|---:|---:|
| Mean | 2.70 ns | 3.00 ns |
| Range | 2.18–3.46 ns | 2.81–3.45 ns |

The 0.30 ns mean difference sat inside a 1.28 ns spread, and the ordering reversed in one run.
That does not prove sealing can never help; it means the analyzer could not demonstrate a benefit
large or stable enough to justify a whole-codebase diagnostic.

Using `sealed` to communicate design intent remains valid. It is no longer a performance rule in
this package.
