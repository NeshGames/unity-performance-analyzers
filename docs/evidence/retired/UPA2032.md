# UPA2032 retirement evidence

UPA2032 reported string IDs passed to DOTween `SetId` and filtered operations because DOTween
documents integer IDs as faster than string IDs.

The rule had no Unity/IL2CPP measurement showing an actionable cost at realistic call counts.
String IDs are a supported API choice with readability and debugging benefits, and the rule already
shipped at Info / disabled-by-default because the difference only matters when filtering is frequent.

Without measured player-build impact, this is a style preference rather than a performance
guardrail an agent should normally act on. The rule was therefore retired during AF-06.

The diagnostic ID remains reserved and must not be reused.
