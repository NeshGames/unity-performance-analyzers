# UPA1000 — Leaf class not sealed(已廢止)

> [English](UPA1000.md) | 繁體中文

| | |
|---|---|
| 類別 | Correctness |
| 預設嚴重度 | Warning |
| 預設啟用 | 否 |

## 狀態

**已廢止。除非專案自行開啟,否則不回報任何東西;隨套件出貨的每一份 preset 都設為 `none`。**
編號保留,因為規則編號永不回收。

## 廢止的原因

本規則主張葉端類別應該 `sealed`,好讓執行期與 IL2CPP 把該型別上的虛擬派送換成直接呼叫。
這個主張從未被量測過;真的量了以後,**量不出來**。

第一份探針拿一個 sealed 的葉類別對上只有**一個**衍生類別的未 sealed 版本,結果是沒有差別
——那份探針無論如何都只會得到這個結果:全程式分析在只有一個實作的繼承鏈上,不管宣告怎麼寫
都能去虛擬化。改用**四個**衍生類別、在 IL2CPP 上重跑八次:

| | sealed | unsealed |
|---|---|---|
| 平均 | 2.70 ns | 3.00 ns |
| 範圍 | 2.18–3.46(散布 1.28) | 2.81–3.45(散布 0.64) |

0.30 ns 的差距落在 1.28 ns 的散布之內,而且八次裡有一次順序反轉。這不是反證——sealed 在
這份探針碰不到的情境裡仍可能有用——但它同樣不是證明,而一條在整個程式碼庫上以型別為單位
回報的規則,應該要能說出它替你買到了什麼。

把葉端類別 `sealed` 仍然是合理的設計,「這個型別不打算被繼承」本身也是有意義的表達。
只是本套件不再為此發出警告。

## 想要它回來

明確設定嚴重度即可恢復原行為:compilation 內宣告的具象 class(非 `abstract`、非 `static`),
compilation 內沒有以它為基底的型別,且自身未宣告 `virtual` 成員。

```ini
dotnet_diagnostic.UPA1000.severity = warning
```

Unity 建置時嚴重度必須來自 ruleset 而非 `.editorconfig`,見套件內附的 preset。

開啟之後,原本的排除與限制仍然成立:自身宣告 `virtual` 成員的類別不報(`sealed` 它們是
CS0549)、`abstract` 與 `static` 類別不報、struct 隱含 sealed,而分析一次只看得到一個
compilation —— 被其他組件繼承的 `public` 型別,在這裡看起來就是葉端。

## 相關規則

- 無。`UNT####` 規則不涵蓋 sealing。
