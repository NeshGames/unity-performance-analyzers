# UPA1000 — Leaf class not sealed

> [English](UPA1000.md) | 繁體中文

| | |
|---|---|
| 類別 | Correctness |
| 預設嚴重度 | Warning |
| 預設啟用 | 否 |

## 成因

一個具體 class(非 `abstract`、非 `static`)未標記 `sealed`,在 compilation 內沒有
任何衍生型別,而且自身未宣告任何 `virtual` 成員。

## 規則說明

當 class 被 sealed 後,runtime 與 IL2CPP 編譯器可以把針對它的虛擬分派改為直接呼叫,
並啟用進一步的 inlining,因為不可能存在衍生型別。對葉節點 class 而言,加上 `sealed`
是一項零語意成本的改善,同時也表明了設計意圖。這同樣適用於 `MonoBehaviour` 的子類別——
Unity 並不要求它們可被繼承。

排除項目:

- 自身宣告了 `virtual`(非 `override`)成員的 class:對其加上 sealed 會是編譯錯誤
  (CS0549),而且尚未被使用的擴充點可能是刻意保留的。
- `abstract` 與 `static` class;struct 隱含即為 sealed。

**已知限制**:分析範圍僅限單一 compilation。`public` 型別可能被其他 assembly 繼承,
而本規則看不到這種情況——遊戲程式碼的 assembly 很少被外部繼承,但若這正是你的設計,
請抑制此診斷。

本規則**預設停用**,因為它會以型別為粒度回報整個 codebase;各 preset 會將其分級為
`suggestion` / `warning`。

## 如何修正

```csharp
// Before
public class PlayerMover : MonoBehaviour { }

// After
public sealed class PlayerMover : MonoBehaviour { }
```

## 何時抑制

對於刻意作為其他 assembly 擴充點的型別(公開的 plugin API、被需要 proxy 的序列化器
或 mocking framework 使用的型別),可以抑制。

## 如何設定或抑制

- 啟用本規則(預設為關閉):在 `.editorconfig` 設定 `dotnet_diagnostic.UPA1000.severity = warning`
- 單一型別:以 `#pragma warning disable UPA1000` / `#pragma warning restore UPA1000` 包住宣告
- 整個專案:設定 `dotnet_diagnostic.UPA1000.severity = none`

## 可設定項

無。

## 相關規則

- 無。`UNT####` 規則並未涵蓋 sealed 相關檢查。
