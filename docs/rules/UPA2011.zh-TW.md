# UPA2011 — Coroutine IEnumerator Unity message or method

> [English](UPA2011.md) | 繁體中文

| | |
|---|---|
| 類別 | Ecosystem |
| 預設嚴重度 | Warning |
| 預設啟用 | 否 |

## 成因

宣告於 `MonoBehaviour` 衍生型別上的方法回傳非泛型的
`System.Collections.IEnumerator`——即 coroutine 的形式,包含 coroutine 形式的 Unity
訊息,例如 `IEnumerator Start()`。

## 規則說明

每次啟動 coroutine 都會配置編譯器產生的列舉器狀態機,而每次 `StartCoroutine`
呼叫還會額外配置一個 `Coroutine` 句柄物件;實值型別的 yield(`yield return 0`)會裝箱。
對於頻繁啟動 coroutine 的程式碼——每次生成的特效、反覆的 UI 轉場——這是持續產生的垃圾。
Coroutine 也會隨其宿主物件無聲地停止,且無法回傳值或傳遞例外,而這些 async
替代方案都能妥善處理。

診斷**只在宣告處回報一次**——`StartCoroutine` 呼叫點刻意不回報,因此一個 coroutine
無論被多少地方啟動都只產生一則診斷。

不回報:

- 非 `MonoBehaviour` 型別上的 `IEnumerator` 方法——一般的列舉器模式。
- 回傳 `IEnumerator<T>` 的方法——典型的資料迭代,不是 coroutine。

本規則**預設停用**:是否遷移離開 coroutine 是整個程式碼庫的技術棧選擇。
訊息對於該採用哪種 async 解決方案保持中立。

## 如何修正

依情況擇一:

- **不需要 `yield`**——改成一般方法。
- **逐幀/時間序列**——使用由 player loop 驅動的 async 方法(搭配 UniTask 使用
  `async UniTaskVoid`,或在 Unity 2023.1+ 使用 `Awaitable`)。
- **保留 coroutine**——若它是冷路徑(只啟動一次,例如場景生命週期的迴圈),就地抑制。

## 何時抑制

對於每個物件生命週期只啟動一次的 coroutine,或刻意以 coroutine 為標準做法的程式碼庫,可予以抑制。

## 如何設定或抑制

- 啟用本規則(預設關閉):在 `.editorconfig` 設定 `dotnet_diagnostic.UPA2011.severity = warning`
- 單一方法:以 `#pragma warning disable UPA2011` / `#pragma warning restore UPA2011` 包住宣告
- 整個專案:設定 `dotnet_diagnostic.UPA2011.severity = none`

## 可設定項

無。

## 相關規則

- UPA2010 建議 async 方法以 UniTask 取代 `Task`(僅在引用 UniTask 時啟用)。
- UPA2012 涵蓋 `async void` 與未 await 的射後不理呼叫。
