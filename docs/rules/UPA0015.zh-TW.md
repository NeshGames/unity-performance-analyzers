# UPA0015 — 逐幀方法內存取 Camera.main

> [English](UPA0015.md) | 繁體中文

| | |
|---|---|
| 類別 | 效能 |
| 預設嚴重度 | 資訊(Info) |
| 預設啟用 | 是 |

## 成因

在逐幀熱路徑內讀取了 `UnityEngine.Camera.main` 屬性。所謂逐幀熱路徑,是指
`MonoBehaviour` 衍生型別上的熱門 Unity 訊息(如 `Update`、`FixedUpdate`、`LateUpdate`),
或標記了熱路徑屬性(如 `[HotPath]`)的方法。

診斷訊息為:

> 'Camera.main' performs a lookup comparable to GetComponent on every access. Cache the camera in a field during Awake or Start.

## 規則說明

`Camera.main` 會回傳第一個帶有 `MainCamera` 標籤且啟用中的攝影機。每次存取都會執行
一次查找:Unity 官方文件指出「accessing this property has a small CPU overhead,
comparable to calling `GameObject.GetComponent`」,並建議「where CPU performance is
important, consider caching this property」
([Unity Scripting API,Camera.main](https://docs.unity3d.com/ScriptReference/Camera-main.html))。

Unity 2020.2 及之後的版本會在內部快取主攝影機查找——同一份文件頁面提到
「internally, Unity caches all GameObjects with the MainCamera tag」,並從該快取回傳
第一個有效結果。因此每次存取的殘餘成本很小,這也是本規則以**資訊(Info)**等級回報、
而非警告的原因:它指出的是一個容易達成的微優化,不是嚴重問題。在 Unity 2020.2 之前的
版本,這個存取是一次完整的標籤搜尋,此建議的份量會更重。

只有熱路徑方法本身的主體(包含其中的 lambda 與區域函式)會被分析。
從熱路徑呼叫的輔助方法內部的存取刻意不回報——
本 analyzer 寧可漏報,也不誤報。

## 如何修正

在 `Awake` 或 `Start` 中把攝影機快取到欄位,並在熱路徑上使用該欄位。

修正前:

```csharp
public class Billboard : MonoBehaviour
{
    void LateUpdate()
    {
        transform.rotation = Camera.main.transform.rotation;
    }
}
```

修正後:

```csharp
public class Billboard : MonoBehaviour
{
    Camera _mainCamera;

    void Awake()
    {
        _mainCamera = Camera.main;
    }

    void LateUpdate()
    {
        transform.rotation = _mainCamera.transform.rotation;
    }
}
```

若主攝影機會在執行期改變(切換攝影機、載入場景),請在切換點更新快取欄位,
而不是每幀重新讀取 `Camera.main`。

## 何時抑制

當主攝影機會在執行期改變、且沒有方便的更新時機時,可以抑制——此時重新讀取
`Camera.main` 是比較簡單的做法,而且在 Unity 2020.2+ 上成本也算低。
認為快取查找的殘餘成本可以接受的專案,也可以把本規則整個專案設為 `none`。

## 如何設定或抑制

- 單一存取點:以 `#pragma warning disable UPA0015` / `#pragma warning restore UPA0015` 包住
- 整個專案:在 `.editorconfig` 設定 `dotnet_diagnostic.UPA0015.severity = none`(團隊想強制時也可提升為 `warning`)
- 依路徑:隨附的 preset 已放寬 `[**/Editor/**/*.cs]` 下的規則;可為工具程式碼或產生的程式碼加入類似區段
- 熱路徑判定:調整下方的 `upa_hot_path_*` 選項

## 可設定項

熱路徑判定是共用的,可透過 `.editorconfig` 設定:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerformanceCritical
upa_hot_path_include_lambdas = true
```
