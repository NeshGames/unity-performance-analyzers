# UPA0019 — Boxed value yielded from coroutine

> English | [繁體中文](UPA0019.zh-TW.md)

| | |
|---|---|
| Category | Performance |
| Default severity | Warning |
| Enabled by default | Yes |

## Cause

In a method on a `MonoBehaviour`-derived type whose return type is the non-generic
`System.Collections.IEnumerator`, a `yield return` statement yields a value-type
expression — for example `yield return 0`, `yield return false`, or
`yield return someStruct`.

Not reported:

- `yield return null` — the allocation-free one-frame wait
- yielding a `YieldInstruction` (`WaitForSeconds`, `WaitForFixedUpdate`, ...) or a
  `CustomYieldInstruction` (`WaitUntil`, `WaitWhile`, ...) — those are reference types and
  the intended coroutine vocabulary
- `IEnumerator` methods on types not derived from `MonoBehaviour` — data enumerators,
  where the yielded values carry meaning to the consumer

This rule is not limited to per-frame hot paths; a coroutine resumes on its own schedule
regardless of where it was started.

## Rule description

The non-generic `IEnumerator.Current` is typed `object`, so yielding a value type boxes it
on every resume: "boxing and unboxing are computationally expensive processes. When a
value type is boxed, a new object must be allocated and constructed" —
[Microsoft Learn, Boxing and Unboxing](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/types/boxing-and-unboxing).

The allocation buys nothing: Unity's coroutine scheduler treats a boxed value that is not
a yield instruction the same as `null`, a one-frame wait. The manual makes the
allocation-free choice explicit: "A `yield return null` does not allocate but yield
instructions like `new WaitForSeconds` do" —
[Unity Manual, Write and run coroutines](https://docs.unity3d.com/6000.5/Documentation/Manual/Coroutines.html).
In a coroutine that runs for many frames, the boxed yield is steady garbage with no
behavioral difference from `yield return null`.

The diagnostic message reads: "Yielding '{0}' boxes the value on every resume, and Unity
treats it the same as null. Yield null to wait one frame."

## How to fix violations

### The code fix

The IDE offers "Yield null instead", which replaces the yielded value with `null`. Or edit by
hand:

Before:

```csharp
IEnumerator FadeOut()
{
    while (_alpha > 0f)
    {
        _alpha -= Time.deltaTime;
        yield return 0;   // boxes an int on every resume
    }
}
```

After:

```csharp
IEnumerator FadeOut()
{
    while (_alpha > 0f)
    {
        _alpha -= Time.deltaTime;
        yield return null;
    }
}
```

## When to suppress warnings

Suppress when the `IEnumerator` method happens to live on a `MonoBehaviour` but is not
started as a coroutine — your own code enumerates it and reads the yielded values.
Consider moving such enumerators to a plain type instead, which also removes the report.

## How to configure or suppress

- Single call site: wrap it in `#pragma warning disable UPA0019` / `#pragma warning restore UPA0019`
- Whole project: set `dotnet_diagnostic.UPA0019.severity = suggestion` (or `none`) in `.editorconfig`
- By path: the shipped presets relax rules under `[**/Editor/**/*.cs]`; add similar sections for tooling or generated code

## Configuration

None.
