# UPA0003 — String-based shader or animator property access

> [English](UPA0003.md) | 繁體中文

| | |
|---|---|
| 類別 | 效能 |
| 預設嚴重度 | 警告(Warning) |
| 預設啟用 | 是 |

## 成因

以字串字面值或編譯期常數作為名稱引數,呼叫了
`Material.Set*/Get*/HasProperty`、`MaterialPropertyBlock.Set*/Get*`、
`Shader.SetGlobal*/GetGlobal*` 或
`Animator.Play/CrossFade/CrossFadeInFixedTime/Set*/Get*/ResetTrigger`
的字串版多載。

## 規則說明

這些 API 同時接受屬性/狀態名稱字串或整數 ID。字串版多載每次呼叫都要把名稱轉換成 ID;
整數版多載則完全跳過這個轉換。Unity 提供 `Shader.PropertyToID` 與
`Animator.StringToHash`,讓轉換只做一次、之後重複使用轉換出的 ID。

本規則預設**不**限定於熱路徑:字串的解析發生在**每一次呼叫**,與呼叫點在不在 `Update` 裡無關;
而這些 API 幾乎總是重複呼叫(材質更新、效果參數、動畫狀態切換)。
把判準收在熱路徑上,會漏掉那些「距逐幀方法一層」的呼叫,而它們通常正是在那裡。
設定 `upa_shader_property_hot_path_only = true` 可縮小範圍。

名稱引數為非常數運算式的呼叫不會被回報——該值可能是資料驅動的,無法靜態快取。
`Shader.PropertyToID` 與 `Animator.StringToHash` 本身永遠不會被回報。
Shader keyword 相關 API(`EnableKeyword` 等)在 v0.1 不在範圍內。

## 如何修正

把每個名稱解析一次存進 `static readonly int`,並改用整數版多載。

修正前:

```csharp
class Effect : MonoBehaviour
{
    void Apply(Material mat)
    {
        mat.SetFloat("_Alpha", 0.5f);
        _animator.Play("Idle");
    }
}
```

修正後:

```csharp
class Effect : MonoBehaviour
{
    private static readonly int Alpha = Shader.PropertyToID("_Alpha");
    private static readonly int Idle = Animator.StringToHash("Idle");

    void Apply(Material mat)
    {
        mat.SetFloat(Alpha, 0.5f);
        _animator.Play(Idle);
    }
}
```

shader 屬性與 animator 狀態走的是**不同的**雜湊函式——`Shader.PropertyToID` 與
`Animator.StringToHash`,不可互換。

用一個全專案共用的 `static class ShaderProperty { ... }` 收攏所有 id 也是常見慣例,
效果完全相同:字串只雜湊一次,而不是每次呼叫都雜湊。那屬於結構選擇,
所以自動修正不會替你做這個決定。

### 關於 code fix

名稱是**字串字面值**時,IDE 會提供 *Cache the property ID in a static field*:
在呼叫所在的型別加上欄位、依 API 選對雜湊函式、並把呼叫改成整數多載。
欄位名取自字面值、去掉前導底線——`"_PositionBuffer"` 變成 `PositionBuffer`。

若那個名字在呼叫點的作用域裡已經有意義,欄位會加上 `Id`。這並不罕見:
`"_Color"` 是常見的屬性名,而叫 `Color` 的欄位會在整個型別內遮蔽 `UnityEngine.Color`,
所以 `"_Color"` 會變成 `ColorId`。

Fix All 在同一型別內**同一個名稱只產生一個欄位**。這件事比聽起來重要:
單一效果檔可能有數十筆這種呼叫、但只用到少數幾個不同名稱,
逐筆各生一個欄位會變成「一個呼叫一個欄位」而不是「一個名稱一個欄位」。

名稱是**編譯期常數但非字面值**時**不提供**:

```csharp
const string AlphaProperty = "_Alpha";
mat.SetFloat(AlphaProperty, 0.5f);        // 會回報,但沒有自動修正
```

這種常數往往正是專案自己集中管理名稱的方式,而 fix 沒有辦法把它和「不小心寫成常數」
分開。請自行快取:`static readonly int Alpha = Shader.PropertyToID(AlphaProperty);`

## 何時抑制

在呼叫次數微不足道的一次性 editor 工具或除錯工具中,
或某屬性刻意只在初始化時存取一次、加入快取類別只會徒增間接層而無益處時,
可以抑制此警告。

## 如何設定或抑制

- 單一呼叫點:以 `#pragma warning disable UPA0003` / `#pragma warning restore UPA0003` 包住
- 整個專案:在 `.editorconfig` 設定 `dotnet_diagnostic.UPA0003.severity = suggestion`(或 `none`)
- 依路徑:隨附的 preset 已放寬 `[**/Editor/**/*.cs]` 下的規則;可為工具程式碼或產生的程式碼加入類似區段
- 範圍:設定 `upa_shader_property_hot_path_only = true` 可把本規則限定於每幀熱路徑

## 可設定項

```ini
# Narrow the rule to per-frame hot paths only (default: false)
upa_shader_property_hot_path_only = false
```

## 相關規則

- `UNT0041`(Microsoft.Unity.Analyzers)只在偵測到重複時才涵蓋重複的字串版 `Animator`
  呼叫。UPA0003 會回報任何常數字串用法,兩者可以共存;
  若不想要這種重疊,可透過 `.editorconfig` 抑制其中一條。
