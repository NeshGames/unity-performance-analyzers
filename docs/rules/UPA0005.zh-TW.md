# UPA0005 — Direct UnityEngine.Debug logging call

> [English](UPA0005.md) | 繁體中文

| | |
|---|---|
| 類別 | 效能 |
| 預設嚴重度 | 警告(Warning) |
| 預設啟用 | 否 |

## 成因

直接呼叫了 `UnityEngine.Debug` 的記錄方法(`Log`、`LogWarning`、`LogError`、
`LogFormat`、`LogWarningFormat`、`LogErrorFormat`、`LogException`、`LogAssertion`、
`LogAssertionFormat`),而不是透過標記了 `[System.Diagnostics.Conditional]`
的包裝方法。

## 規則說明

直接的 `Debug.Log` 呼叫會留在 release 組建中,而它的引數運算式——
字串串接、插值、值的 boxing——即使記錄輸出本身被剝除或忽略,
仍會在每次呼叫時被求值並配置。當記錄改走標記了 `[Conditional("SYMBOL")]`
的包裝方法時,在未定義該符號的組建中,編譯器會把整個呼叫
**連同其引數運算式**一併移除,release 組建因此完全不付出成本。

`Debug.Assert` / `Debug.AssertFormat` 不會被回報:Unity 已把它們標記為
`[Conditional("UNITY_ASSERTIONS")]`。位於本身帶有 `[Conditional]` 屬性的方法內的呼叫
也不會被回報——那個方法*就是*包裝器。

本規則**預設停用**:它只有在專案已有包裝類別時才有意義,
否則每個發現都是無法修正的雜訊。等包裝器存在後,
再透過 preset 或 `.editorconfig` 啟用。

## 如何修正

讓記錄走條件式包裝器。

修正前:

```csharp
void OnPickup(Item item)
{
    Debug.Log("picked up " + item.name);
}
```

修正後:

```csharp
public static class GameLog
{
    [System.Diagnostics.Conditional("ENABLE_LOG")]
    public static void Info(string message) => Debug.Log(message);
}

void OnPickup(Item item)
{
    GameLog.Info("picked up " + item.name);
}
```

## 何時抑制

在 editor 專用工具(隨附的 preset 已放寬 `**/Editor/**` 路徑)
或不會隨產品出貨的臨時診斷程式碼中,可以抑制此警告。

## 如何設定或抑制

- 啟用本規則(預設關閉):在 `.editorconfig` 設定 `dotnet_diagnostic.UPA0005.severity = warning`
- 單一呼叫點:以 `#pragma warning disable UPA0005` / `#pragma warning restore UPA0005` 包住
- 整個專案:設定 `dotnet_diagnostic.UPA0005.severity = none`
- 包裝型別:把你的包裝類別名稱列在 `upa_log_wrapper_types`,其內部的呼叫就不會被回報

## 可設定項

```ini
# Types whose bodies are treated as logging wrappers (comma-separated short names)
upa_log_wrapper_types = Log,GameLog
```

## 相關規則

- 無。`UNT####` 規則未涵蓋條件式記錄包裝器。
