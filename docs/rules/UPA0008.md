# UPA0008 — stackalloc inside a loop

> English | [繁體中文](UPA0008.zh-TW.md)

| | |
|---|---|
| Category | Performance |
| Default severity | Warning |
| Enabled by default | Yes |

## Cause

A `stackalloc` expression sits inside a `for`, `foreach`, `while`, or `do` loop within the
same method body.

## Rule description

Memory reserved with `stackalloc` is released when the enclosing method returns — not when
the current iteration or block ends. Inside a loop, every iteration reserves a fresh
region while all previous regions stay live, so the stack footprint grows with the
iteration count and can overflow the stack entirely for large buffers or long loops.

The boundary is the method body: a `stackalloc` at the top level of a **local function or
lambda** that is *called* from a loop is not reported, because that memory is reclaimed
each time the nested function returns.

## How to fix violations

Hoist the buffer out of the loop and reuse it.

Before:

```csharp
for (int i = 0; i < segments; i++)
{
    Span<float> weights = stackalloc float[16];
    Compute(i, weights);
}
```

After:

```csharp
Span<float> weights = stackalloc float[16];
for (int i = 0; i < segments; i++)
{
    weights.Clear();
    Compute(i, weights);
}
```

## When to suppress warnings

Suppress when the loop provably runs a tiny, fixed number of iterations with a small
buffer and hoisting would complicate lifetime handling — and the stack budget has been
considered explicitly.

## How to configure or suppress

- Single call site: wrap it in `#pragma warning disable UPA0008` / `#pragma warning restore UPA0008`
- Whole project: set `dotnet_diagnostic.UPA0008.severity = suggestion` (or `none`) in `.editorconfig`
- By path: the shipped presets relax rules under `[**/Editor/**/*.cs]`; add similar sections for tooling or generated code

## Configuration

None.
