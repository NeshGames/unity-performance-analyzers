# UPA0017 — Array-returning GetComponents overload in per-frame method

> English | [繁體中文](UPA0017.zh-TW.md)

| | |
|---|---|
| Category | Performance |
| Default severity | Warning |
| Enabled by default | Yes |

## Cause

An array-returning overload of `GetComponents`, `GetComponentsInChildren`, or
`GetComponentsInParent` (on either `UnityEngine.Component` or `UnityEngine.GameObject`)
is called inside a per-frame hot path: a hot Unity message such as `Update`,
`FixedUpdate`, or `LateUpdate` on a `MonoBehaviour`-derived type, or a method marked with
a hot-path attribute such as `[HotPath]`.

Only the overloads that return an array are reported. The `List<T>`-taking overloads
return `void` and fill a caller-provided list, so they do not report.

The diagnostic message is:

> '{0}' allocates a new array on every call. Use the List&lt;T&gt; overload with a list cached in a field instead.

where `{0}` is the method name, for example `GetComponentsInChildren`.

## Rule description

The array-returning overloads allocate a fresh managed array on every call. This is the
general contract for array-valued Unity APIs — "all Unity APIs that return arrays create
a new copy of the array each time they're accessed"
([Unity Manual, Garbage collection best practices](https://docs.unity3d.com/2022.3/Documentation/Manual/performance-garbage-collection-best-practices.html)) —
so calling one every frame produces steady garbage proportional to the number of matches.

Unity provides the `List<T>` overloads precisely for this case: the supplied list is
resized to the number of results and its previous contents are overwritten, which,
per the API documentation, "allows you to avoid allocating new List objects for each call
to the method"
([Unity Scripting API, Component.GetComponents](https://docs.unity3d.com/ScriptReference/Component.GetComponents.html)).
With the list cached in a field, the per-frame allocation disappears entirely once the
list has grown to its steady-state capacity.

The correct fix introduces a reusable `List<T>` field, which is a type-level change rather
than a call-site rewrite.

Only the body of the hot-path method itself (including its lambdas and local functions) is
analyzed. Calls inside helper methods invoked from a hot path are deliberately not reported
— this analyzer prefers missed reports over false positives.

## How to fix violations

Switch to the `List<T>` overload and cache the list in a field.

Before:

```csharp
public class ColliderScanner : MonoBehaviour
{
    void Update()
    {
        foreach (var collider in GetComponentsInChildren<Collider>())
        {
            Process(collider);
        }
    }
}
```

After:

```csharp
public class ColliderScanner : MonoBehaviour
{
    readonly List<Collider> _colliders = new List<Collider>();

    void Update()
    {
        GetComponentsInChildren(_colliders);
        foreach (var collider in _colliders)
        {
            Process(collider);
        }
    }
}
```

If the component set does not change between frames, consider resolving it once in
`Awake` or `Start` instead of re-querying every frame.

## When to suppress warnings

Suppress when the call is on a cold branch that runs rarely despite being located in a
hot method, or when the returned array intentionally escapes the method (stored or handed
to an API that takes ownership) and a shared list would be incorrect.

## How to configure or suppress

- Single call site: wrap it in `#pragma warning disable UPA0017` / `#pragma warning restore UPA0017`
- Whole project: set `<Rule Id="UPA0017" Action="Info" />` (or `None`) in `Assets/Default.ruleset`
- By assembly: place a custom `Default.ruleset` in that asmdef folder and set this rule to `None`; it overrides the project-wide ruleset for that assembly
- Hot-path classification: adjust the `upa_hot_path_*` options below

## Configuration

The hot-path classification is shared and set in the universal options file `Assets/Rules.UnityPerformanceAnalyzers.additionalfile`. Pass the same file to `upa-cli` with `--additionalfile`:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerformanceCritical
upa_hot_path_include_lambdas = true
```

## Related rules

- UPA0001 covers the rest of the `GetComponent` family on hot paths, including the
  `List<T>` overloads this rule recommends — they allocate nothing but still perform the
  native lookup every frame. The array-returning overloads are this rule's alone: UPA0001
  stands aside on them, so a call is reported once, not twice. Switching this rule off by
  ruleset, `/nowarn` or `.editorconfig` hands those calls back to UPA0001; a
  `#pragma warning disable UPA0017` does not, because UPA0001 cannot see a pragma, so the
  call it covers goes unreported by both.
- UPA0018 covers other allocating array-returning Unity APIs (`Input.touches`,
  `Animator.parameters`, and similar) with documented non-allocating counterparts.
