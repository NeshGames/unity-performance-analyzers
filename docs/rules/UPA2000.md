# UPA2000 — String concatenation in per-frame method

> English | [繁體中文](UPA2000.zh-TW.md)

| | |
|---|---|
| Category | Ecosystem |
| Default severity | Warning |
| Enabled by default | No |

## Cause

A string is built inside a per-frame hot path: a `+` concatenation whose result is a
string, a `+=` append, or a string interpolation (`$"..."`).

## Rule description

Every string in .NET is immutable, so concatenation, appends, and interpolation each
allocate a new string on every execution. Inside methods that Unity runs every frame —
score displays, timers, debug overlays — this produces garbage every frame, feeding the
non-generational GC the same way the allocations UPA0006 reports do.

The advice in the message adapts to the project (the rule itself always runs):

- **Without ZString**: cache strings that do not change, or build changing ones with a
  reusable `StringBuilder` outside the hot path.
- **With ZString referenced**: use ZString to format without intermediate string
  allocations.

Scope boundaries, deliberately drawn:

- **Compile-time constant folding is not reported** — `"a" + "b"` and `const`
  combinations are folded by the compiler and allocate nothing at runtime.
- **`string.Format` / `string.Concat` / `string.Join` calls** are out of scope in v0.1.
- A chained concatenation (`"a: " + a + b`) is reported once, on the whole expression.
- **Boxing of value-type operands** (`"x" + n` boxing `n`) is reported separately by
  UPA0006. The double report is intentional: they are distinct allocations, and a
  ZString-style rewrite removes both at once.

The rule is **disabled by default** (ecosystem block policy): whether string building is
banned on hot paths is a codebase discipline choice. Presets enable it.

## How to fix violations

Before:

```csharp
void Update()
{
    scoreLabel.text = "score: " + score;
}
```

After (cache and rebuild only on change):

```csharp
void OnScoreChanged(int score)
{
    scoreLabel.SetText("score: {0}", score);   // TMP_Text.SetText formats without garbage
}
```

Or with ZString:

```csharp
using Cysharp.Text;

void OnScoreChanged(int score)
{
    scoreLabel.text = ZString.Concat("score: ", score);
}
```

The best fix is often to move the string building out of the per-frame path entirely —
rebuild the text only when the underlying value changes.

## When to suppress warnings

Suppress on cold branches inside hot methods (rare state transitions, debug-only paths)
where the string is built provably infrequently.

## How to configure or suppress

- Enable the rule (it is off by default): `dotnet_diagnostic.UPA2000.severity = warning` in `.editorconfig`
- Single call site: wrap it in `#pragma warning disable UPA2000` / `#pragma warning restore UPA2000`
- Whole project: set `dotnet_diagnostic.UPA2000.severity = none`
- Hot-path classification: adjust the shared `upa_hot_path_*` options (see UPA0006)

## Configuration

Hot-path classification is shared and configurable via `.editorconfig`:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate
upa_hot_path_attributes = HotPath,PerfCritical
upa_hot_path_include_lambdas = true
```

## Related rules

- UPA0006 reports the boxing of value-type operands inside a concatenation.
- UPA0002 reports `name` / `tag` reads, which also allocate a string per access.
