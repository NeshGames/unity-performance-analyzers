# UPA3004 — Blocking wait on asynchronous operation

> English | [繁體中文](UPA3004.zh-TW.md)

| | |
|---|---|
| Category | Platform |
| Default severity | Warning |
| Enabled by default | No |
| Active only when | the compilation defines `UPA_TARGET_WEBGL` |

## Cause

A blocking wait on an asynchronous operation in a compilation that defines
`UPA_TARGET_WEBGL`:

- `AsyncOperationHandle.WaitForCompletion()` / `AsyncOperationHandle<TObject>.WaitForCompletion()`
  (Addressables; checked only when the package is referenced)
- `Task.Wait()`, `Task.WaitAll(...)`, `Task.WaitAny(...)`
- `Task<TResult>.Result`
- `GetAwaiter().GetResult()` on the `Task`/`ValueTask` awaiter family, including the
  `ConfigureAwait(...)` variants

## Rule description

Unity WebGL players run on a single thread. When the main thread blocks waiting for an
asynchronous operation, the continuation that would complete that operation can never
run — the wait is not slow, it is a deadlock, and the application freezes.

These patterns often appear to work on desktop platforms, where a thread pool completes
the operation in the background. That makes them a porting trap: the code ships, and only
the WebGL build hangs. UPA3000 reports APIs that create threads; this rule reports the
complementary mistake of synchronously waiting on asynchronous results.

Unity's own guidance is not WebGL-specific: "Never use `Task.Result` or `Task.Wait` on
the main thread (causes deadlocks)" —
[Unity Manual, Programming best practices](https://docs.unity3d.com/6000.5/Documentation/Manual/programming-best-practices.html).
This rule stays scoped to WebGL builds, where the deadlock is unconditional.

The rule runs only when `UPA_TARGET_WEBGL` is defined and is disabled by default —
enable it via the `webgl-addon` preset.

## How to fix violations

Await the operation instead of blocking on it:

```csharp
// Bad: freezes a WebGL player.
var sprite = handle.WaitForCompletion();
var data = LoadAsync().Result;

// Good: the operation can complete because the main thread keeps running.
var sprite = await handle.Task;
var data = await LoadAsync();
```

In a coroutine, yield until `IsDone`/`IsCompleted` rather than blocking.

## When to suppress warnings

- The task is provably completed at the access site (for example, guarded by
  `task.IsCompleted`). The rule performs no flow analysis, so this safe pattern still
  reports — suppress it locally.
- Code paths already gated behind `#if !UNITY_WEBGL` platform defines.

## How to configure or suppress

- Enable the rule (it is off by default): `dotnet_diagnostic.UPA3004.severity = warning` in `.editorconfig` (the `webgl-addon` preset does this)
- Single site: `#pragma warning disable UPA3004` / `#pragma warning restore UPA3004`
- Whole project: set `dotnet_diagnostic.UPA3004.severity = none`

## Configuration

None beyond the `UPA_TARGET_WEBGL` define.
