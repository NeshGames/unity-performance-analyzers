# UPA2010 — User-authored async method returns Task

> [English](UPA2010.md) | 繁體中文

| | |
|---|---|
| 類別 | Ecosystem |
| 預設嚴重度 | Warning |
| 預設啟用 | 否 |
| 啟用條件 | 該 assembly 引用 UniTask |

## 成因

在引用 UniTask 的 assembly 中,由使用者自行撰寫的 `async` 方法宣告(包含區域函式)回傳
`System.Threading.Tasks.Task` 或 `Task<T>`。

## 規則說明

每次呼叫 async `Task` 方法都會配置 `Task` 物件,而實際發生讓渡(yield)的 await
會把狀態機裝箱到堆積上。UniTask 提供為 Unity player loop 打造的零配置對應型別
(`UniTask`、`UniTask<T>`、`UniTaskVoid`),因此在已經採用 UniTask 的專案裡,
使用者自行撰寫的 `async Task` 方法通常是疏忽。

本規則**在未引用 UniTask 的 assembly 中完全不執行**——回報你無法採取行動的建議,
比保持沉默更糟。

以下情況刻意排除:

- **覆寫(override)與介面實作**(隱含或明確)——簽章由基底宣告決定,無法單方面更改。
- **Async lambda**——委派型別由使用端 API 決定。
- **非 async 且回傳 `Task` 的方法**——轉發/包裝方法本身不會配置狀態機。

## 如何修正

```csharp
// Before
async Task LoadAsync()
{
    await UniTask.Yield();
}

// After
async UniTask LoadAsync()
{
    await UniTask.Yield();
}
```

射後不理(fire-and-forget)的進入點建議改用 `async UniTaskVoid`(見 UPA2012)。
只有在會被第三方程式碼使用的邊界上才保留 `Task`。

## 何時抑制

在會被預期取得 `Task` 的程式碼使用的公開 API 介面上抑制(函式庫、測試框架、非 Unity 呼叫端)。

## 如何設定或抑制

- 啟用本規則(預設關閉):在 `.editorconfig` 設定 `dotnet_diagnostic.UPA2010.severity = warning`
- 單一方法:以 `#pragma warning disable UPA2010` / `#pragma warning restore UPA2010` 包住宣告
- 整個專案:設定 `dotnet_diagnostic.UPA2010.severity = none`

## 可設定項

無。UniTask 是否存在以引用的 assembly 名稱(`UniTask`)判斷。

## 相關規則

- UPA2012 涵蓋 `async void` 與未 await 的射後不理呼叫。
