# UPA2012 — Async void or unawaited fire-and-forget

> English | [繁體中文](UPA2012.zh-TW.md)

| | |
|---|---|
| Category | Ecosystem |
| Default severity | Warning |
| Enabled by default | No |

## Cause

One of two shapes, reported under the same rule ID:

- **A.** An `async void` method declaration.
- **B.** An expression-statement invocation returning `Task`, `Task<T>`, `UniTask`, or
  `UniTask<T>` whose result is discarded — not awaited, not stored, not `.Forget()`.

## Rule description

Exceptions thrown by an `async void` method cannot be caught by any caller, and its
completion cannot be observed. A task discarded at the call site swallows its exceptions
just as silently, and hides ordering bugs — the caller continues before the work
finishes. Both are debugging black holes that surface as "nothing happened, no error".

The rule always runs; a referenced UniTask assembly only switches the advice
(`Task`/await phrasing versus `UniTaskVoid`/`Forget` phrasing).

Not reported:

- **Event-handler-signature async void** (`(object sender, EventArgs e)`, including
  derived `EventArgs`) — the established .NET convention.
- **Awaited calls** and results that are **assigned, returned, or passed on** — observed.
- **`.Forget()`** — UniTask's explicit fire-and-forget.
- **`_ = FooAsync();`** — the discard states the intent explicitly.

Deliberate scope limit: form B only looks at bare expression statements. A task stored
in a variable and awaited on only some paths needs control-flow analysis to judge, and
is beyond this rule's deliberately simple scope.

## How to fix violations

```csharp
// A: async void → awaitable return type
async void Fire() { ... }              // Before
async Task FireAsync() { ... }         // After (await or store at call sites)
async UniTaskVoid Fire() { ... }       // After, with UniTask — call Fire().Forget()

// B: discarded call → observe or make the intent explicit
FooAsync();                            // Before
await FooAsync();                      // After
FooAsync().Forget();                   // After, with UniTask, when fire-and-forget is intended
```

### `.Forget()` versus `_ =`

`.Forget()` is defined on `UniTask`, `UniTask<T>` and `UniTaskVoid` only — not on `Task` — and
needs `using Cysharp.Threading.Tasks;`, which a call site may never have needed before. It is
what UniTask defines for fire-and-forget: the task's exceptions reach UniTask's unhandled
exception handler instead of disappearing. `_ = FooAsync();` says the lost exceptions were a
decision; write it only when they were. Changing an `async void` signature reaches every
caller, so update the call sites in the same change.

## When to suppress warnings

Rarely needed — every exclusion above is an explicit way to state intent, and rewriting
to `_ = FooAsync();` is always available. Suppress only in generated or interop code you
cannot rewrite.

## How to configure or suppress

- Enable the rule (it is off by default): `<Rule Id="UPA2012" Action="Warning" />` in `Assets/Default.ruleset`
- Single site: wrap it in `#pragma warning disable UPA2012` / `#pragma warning restore UPA2012`
- Whole project: set `<Rule Id="UPA2012" Action="None" />` in `Assets/Default.ruleset`

## Configuration

None. The UniTask advice switch is by referenced assembly name (`UniTask`).

## Related rules

- UPA2010 suggests UniTask over `Task` for async method declarations.
- CS4014 (compiler) warns on unawaited calls inside async methods; this rule also covers
  non-async callers and UniTask, and stays silent on explicit discards.
