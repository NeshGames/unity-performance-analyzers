# UPA0016 — SendMessage / BroadcastMessage 呼叫

> [English](UPA0016.md) | 繁體中文

| | |
|---|---|
| 類別 | 效能 |
| 預設嚴重度 | 警告(Warning) |
| 預設啟用 | 是 |

## 成因

呼叫了宣告在 `UnityEngine.Component` 或 `UnityEngine.GameObject` 上的
`SendMessage`、`SendMessageUpwards` 或 `BroadcastMessage`——不限於程式碼的任何位置。
與本套件的多數規則不同,本規則**不限定在逐幀熱路徑**:無論呼叫位於何處,
成本與正確性風險都存在。

診斷訊息為:

> '{0}' uses reflection-based message dispatch, which is orders of magnitude slower than a direct call. Call the method directly, or use an interface or UnityEvent.

其中 `{0}` 是方法名稱,例如 `SendMessage`。

## 規則說明

這些 API 以方法名稱字串透過反射派送:接收者是在執行期掃描各元件、
尋找名稱相符的方法來定位的。Microsoft 的 Unity 效能指引建議移除它們,
並指出「these functions can be on the order of 1000x slower than direct function calls」
([Microsoft Learn,Performance recommendations for Unity](https://learn.microsoft.com/en-us/windows/mixed-reality/develop/unity/performance-recommendations-for-unity))。
`BroadcastMessage` 與 `SendMessageUpwards` 還會走訪 transform 階層,
派送成本會隨造訪的物件數量倍增。

效能成本只是問題的一半。字串派送同時把編譯器排除在外:目標方法被改名或拼錯時,
程式碼仍能順利編譯,只會在執行期才失敗,而且 IDE 的導覽與重構工具看不到這條呼叫邊。
由於這兩個問題與呼叫頻率無關,本規則在所有位置回報,而不只是熱路徑。

## 如何修正

把字串派送改為靜態型別的機制:

修正前:

```csharp
void OnHit(GameObject target)
{
    target.SendMessage("ApplyDamage", 10f);
}
```

修正後——透過元件引用直接呼叫:

```csharp
void OnHit(GameObject target)
{
    if (target.TryGetComponent<Health>(out var health))
    {
        health.ApplyDamage(10f);
    }
}
```

當呼叫端不應依賴具體型別時,改以介面派送:

```csharp
public interface IDamageable
{
    void ApplyDamage(float amount);
}

void OnHit(GameObject target)
{
    if (target.TryGetComponent<IDamageable>(out var damageable))
    {
        damageable.ApplyDamage(10f);
    }
}
```

需要讓設計者在編輯器中接線的通知,則公開 `UnityEvent`,由 Inspector 連接監聽者。

## 何時抑制

與只提供 message receiver 作為進入點的第三方或舊有元件互通時,
或在一次性的編輯器工具中(派送成本無關緊要、字串耦合也被侷限住)時,可以抑制。

## 如何設定或抑制

- 單一呼叫點:以 `#pragma warning disable UPA0016` / `#pragma warning restore UPA0016` 包住
- 整個專案:在 `.editorconfig` 設定 `dotnet_diagnostic.UPA0016.severity = suggestion`(或 `none`)
- 依路徑:隨附的 preset 已放寬 `[**/Editor/**/*.cs]` 下的規則;可為工具程式碼或產生的程式碼加入類似區段

## 可設定項

無。本規則刻意忽略熱路徑判定——它在所有位置回報。
