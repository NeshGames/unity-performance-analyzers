# UPA0004 — Instantiating accessor used in per-frame method

> [English](UPA0004.md) | 繁體中文

| | |
|---|---|
| 類別 | 效能 |
| 預設嚴重度 | 警告(Warning) |
| 預設啟用 | 是 |

## 成因

在每幀熱路徑內讀取了 `UnityEngine.Renderer.material`、`UnityEngine.Renderer.materials`
或 `UnityEngine.MeshFilter.mesh` 的 getter。所謂每幀熱路徑,是指
`MonoBehaviour` 衍生型別上的熱門 Unity 訊息(如 `Update`、`FixedUpdate`、`LateUpdate`),
或標記了熱路徑屬性(如 `[HotPath]`)的方法。`SkinnedMeshRenderer` 等衍生型別也在涵蓋範圍內,
因為這些存取子會解析回其宣告型別。

## 規則說明

精確說明這些存取子的代價——它們並不是「每幀一次配置」:

1. `Renderer.material` 與 `MeshFilter.mesh` 會在**第一次**存取時複製共用資產並快取該實例;
   之後的存取回傳同一個實例。呼叫端擁有那份複本,必須手動銷毀
   (`Destroy(instance)`),否則會洩漏。
2. 每次存取——不論是否第一次——仍是一次原生屬性呼叫,在每幀路徑上是可避免的成本。
3. `Renderer.materials`(複數)則**每次存取都回傳一個新配置的陣列**。

`sharedMaterial` / `sharedMaterials` / `sharedMesh` 存取子不會建立複本,
不會被回報——當你的意圖就是修改共用資產時,請使用它們。

## 如何修正

在熱路徑外把實例快取到欄位,並在 `OnDestroy` 中釋放。

修正前:

```csharp
void Update()
{
    _renderer.material.color = _currentColor;
}
```

修正後:

```csharp
Material _material;

void Awake()
{
    _material = _renderer.material;
}

void Update()
{
    _material.color = _currentColor;
}

void OnDestroy()
{
    Destroy(_material);
}
```

## 何時抑制

當 renderer 的 material 組合確實會在幀與幀之間變動、必須重新取得目前實例,
或在每幀成本與實例生命週期已由其他地方管理的 editor 工具中時,可以抑制此警告。

## 如何設定或抑制

- 單一呼叫點:以 `#pragma warning disable UPA0004` / `#pragma warning restore UPA0004` 包住
- 整個專案:在 `Assets/Default.ruleset` 設定 `<Rule Id="UPA0004" Action="Info" />`(或 `None`)
- 依 assembly:在該 asmdef 資料夾放一份自訂 `Default.ruleset`,把本規則設為 `None`;它只覆寫該 assembly
- 熱路徑判定:調整下方的 `upa_hot_path_*` 選項

## 可設定項

熱路徑判定是共用的,設定在通用選項檔 `Assets/Rules.UnityPerformanceAnalyzers.additionalfile`(同樣的 `key = value` 行也可寫進透過 `upa-cli --editorconfig` 傳入的 `.editorconfig`):

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerformanceCritical
upa_hot_path_include_lambdas = true
```
