# UPA0006 — Reference type allocated in per-frame method

> English | [繁體中文](UPA0006.zh-TW.md)

| | |
|---|---|
| Category | Performance |
| Default severity | Warning |
| Enabled by default | Yes |

## Cause

A managed heap allocation happens inside a per-frame hot path: an object creation of a
reference type (`new List<int>()`), an array creation (`new int[16]`), a boxing
conversion of a value type (`object o = 42;`, a struct passed to an `object` or interface
parameter), or a value-type string-interpolation hole (`$"hp {hp}"` with `hp` an `int`).

## Rule description

Unity's garbage collector is non-generational: collection cost scales with the whole
managed heap, and the collection moment is driven by allocation rate. Per-frame
allocations therefore surface as periodic frame spikes whose timing you do not control.
Keeping hot paths allocation-free is the standard discipline this rule enforces.

Boxing is included because it is the most invisible allocation — there is no `new` in the
source. It commonly hides in conversions to `object` or interface parameters, in
non-generic collections, and in `enum` values passed to non-generic APIs.
String-interpolation holes are the same trap: the compiler lowers `$"hp {hp}"` to a
`string.Format` call whose argument is `object`, boxing the `int`. Unity's
garbage-collection guidance singles boxing out as "one of the most common sources of
unintended temporary memory allocations" and notes that C# IDEs and compilers do not
issue warnings about it
([Unity Manual 2022.3, Garbage collection best practices](https://docs.unity3d.com/2022.3/Documentation/Manual/performance-garbage-collection-best-practices.html);
see also [Boxing and Unboxing (C#), Microsoft Learn](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/types/boxing-and-unboxing)).

Scope boundaries, deliberately drawn:

- **Value-type `new` is not reported** — structs do not allocate on the managed heap.
- **`throw new Exception(...)` is not reported** — exceptional paths are expected to be
  rare; throwing every frame is a different bug.
- **Lambdas and closures** are UPA0007's territory; **string concatenation and
  interpolation** are UPA2000's; method-group delegate creations and `params` array
  expansions are out of scope in v0.1.
- Note one interaction: the implicit `params` array itself is not reported, but a value
  type **boxed into that array** still is — that boxing is a real allocation.
- Similarly, a value type boxed into a string concatenation (`"x" + n`) is reported here
  even though the concatenation itself belongs to UPA2000. The two are distinct
  allocations, and a ZString-style rewrite removes both at once.
- The same split applies to interpolation: a value-type hole (`$"hp {hp}"`) is reported
  here as `boxed int`, while the string the interpolation builds belongs to UPA2000.
  String-typed holes do not report. An explicit cast inside a hole (`$"{(object)hp}"`)
  is reported by the boxing-conversion path, so each hole reports once; holes whose
  expression has a type-parameter type are not reported.

This is the widest-triggering rule in the package. Cold branches inside hot methods
(one-time lazy initialization, rare debug snapshots) will be reported even though they run
rarely — the analyzer does not do flow analysis. Use the suppression options below for
those cases.

## How to fix violations

Hoist the allocation out of the hot path and reuse the instance.

Before:

```csharp
void Update()
{
    var results = new List<RaycastHit>();
    Scan(results);
}
```

After:

```csharp
readonly List<RaycastHit> _results = new List<RaycastHit>();

void Update()
{
    _results.Clear();
    Scan(_results);
}
```

For boxing, prefer generic overloads (`Consume<T>(T value)` instead of
`Consume(object value)`) or generic collections.

For interpolation holes, hoist the formatting off the hot path and cache the result —
rebuild the string only when the value changes:

Before:

```csharp
void Update()
{
    hpLabel.text = $"hp {hp}";   // boxes hp every frame, then allocates the string
}
```

After (format on change, off the hot path):

```csharp
void OnHpChanged(int newHp)
{
    hpLabel.text = $"hp {newHp}";
}
```

Alternatively, format through an explicitly non-boxing path: `$"hp {hp.ToString()}"`
makes the hole string-typed (no box; the `ToString` string itself is UPA2000's
territory), and generic garbage-free formatters such as ZString avoid both allocations
at once.

## When to suppress warnings

Suppress on cold branches that provably run rarely (lazy initialization guards, debug-only
paths), or when a pooled/cached design would cost more complexity than the allocation is
worth in that specific spot.

## How to configure or suppress

- Single call site: wrap it in `#pragma warning disable UPA0006` / `#pragma warning restore UPA0006`
- Whole project: set `dotnet_diagnostic.UPA0006.severity = suggestion` (or `none`) in `.editorconfig`
- By path: the shipped presets relax rules under `[**/Editor/**/*.cs]`; add similar sections for tooling or generated code
- Hot-path classification: adjust the `upa_hot_path_*` options below

## Configuration

The hot-path classification is shared and configurable via `.editorconfig`:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerfCritical
upa_hot_path_include_lambdas = true
```
