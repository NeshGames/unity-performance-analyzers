# UPA0008 — stackalloc inside a loop

> [English](UPA0008.md) | 繁體中文

| | |
|---|---|
| 類別 | 效能 |
| 預設嚴重度 | 警告(Warning) |
| 預設啟用 | 是 |

## 成因

`stackalloc` 運算式位於同一個方法主體內的 `for`、`foreach`、`while` 或 `do`
迴圈之中。

## 規則說明

以 `stackalloc` 保留的記憶體要等外圍方法返回時才釋放——
而不是在當前迭代或區塊結束時。在迴圈裡,每次迭代都會保留一塊新的區域,
而先前所有的區域仍然存活,因此堆疊(stack)佔用量隨迭代次數增長,
在緩衝區較大或迴圈較長時甚至可能把堆疊整個溢位。

界線是方法主體:位於**區域函式或 lambda** 頂層、只是被迴圈*呼叫*的 `stackalloc`
不會被回報,因為那塊記憶體在巢狀函式每次返回時就會被回收。

## 如何修正

把緩衝區提升到迴圈外並重複使用。

修正前:

```csharp
for (int i = 0; i < segments; i++)
{
    Span<float> weights = stackalloc float[16];
    Compute(i, weights);
}
```

修正後:

```csharp
Span<float> weights = stackalloc float[16];
for (int i = 0; i < segments; i++)
{
    weights.Clear();
    Compute(i, weights);
}
```

## 何時抑制

當迴圈可證明只執行極少且固定的次數、緩衝區很小、
外提反而會讓生命週期處理變複雜——且堆疊預算已被明確評估過時,
可以抑制此警告。

## 如何設定或抑制

- 單一呼叫點:以 `#pragma warning disable UPA0008` / `#pragma warning restore UPA0008` 包住
- 整個專案:在 `.editorconfig` 設定 `dotnet_diagnostic.UPA0008.severity = suggestion`(或 `none`)
- 依路徑:隨附的 preset 已放寬 `[**/Editor/**/*.cs]` 下的規則;可為工具程式碼或產生的程式碼加入類似區段

## 可設定項

無。
