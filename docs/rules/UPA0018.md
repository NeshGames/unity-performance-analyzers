# UPA0018 — Allocating array-returning Unity API in per-frame method

> English | [繁體中文](UPA0018.zh-TW.md)

| | |
|---|---|
| Category | Performance |
| Default severity | Warning |
| Enabled by default | Yes |

## Cause

One of the following Unity members is used inside a per-frame hot path: a hot Unity
message such as `Update`, `FixedUpdate`, or `LateUpdate` on a `MonoBehaviour`-derived type,
or a method marked with a hot-path attribute such as `[HotPath]`.

| Member | Non-allocating replacement |
|---|---|
| `Input.touches` | `Input.touchCount` with `Input.GetTouch(i)` |
| `Animator.parameters` | `Animator.parameterCount` with `Animator.GetParameter(i)` |
| `Animator.GetCurrentAnimatorClipInfo(int)` | `GetCurrentAnimatorClipInfo(int, List<AnimatorClipInfo>)` with a cached list |
| `Renderer.sharedMaterials` | `Renderer.GetSharedMaterials(List<Material>)` |
| `Camera.allCameras` | `Camera.GetAllCameras(Camera[])` |
| `Texture2D.GetPixels` / `GetPixels32` / `GetRawTextureData()` (non-generic) | `GetRawTextureData<T>()`, which returns a `NativeArray<T>` view without copying |

Only reads are reported. Assigning to a settable entry (for example
`renderer.sharedMaterials = array`) does not allocate and is not reported. The replacements
are never reported themselves — the generic `GetRawTextureData<T>()` and the `List` overload
of `GetCurrentAnimatorClipInfo` share their names with listed members, and the rule
distinguishes them.

## Rule description

Unity's garbage collection guidance is explicit: "All Unity APIs that return arrays create
a new copy of the array each time they're accessed" —
[Unity Manual, Garbage collection best practices](https://docs.unity3d.com/2022.3/Documentation/Manual/performance-garbage-collection-best-practices.html).
Reading such a property on a per-frame path therefore produces steady garbage, even when
the result is only inspected and immediately discarded.

The rule checks a closed deny-list rather than trying to catch every array-returning API:
each listed entry has a documented counterpart that avoids the copy, either through indexed
access ([`Animator.parameterCount`](https://docs.unity3d.com/ScriptReference/Animator-parameterCount.html)
with `GetParameter`) or by filling a caller-provided buffer
([`Renderer.GetSharedMaterials`](https://docs.unity3d.com/ScriptReference/Renderer.GetSharedMaterials.html)
"if you ... want to avoid allocating a new array with every access";
[`Camera.GetAllCameras`](https://docs.unity3d.com/ScriptReference/Camera.GetAllCameras.html)
"without allocating a new array"). The diagnostic message names the replacement for the
entry it reports.

Every entry and its replacement were measured in this project's sandbox on Unity 2022.3 and
Unity 6, across Mono and IL2CPP, before being listed. The replacements measured at zero
allocation — advice that costs the same as the thing it replaces would not be worth a
diagnostic.

Several prominent array-returning APIs are deliberately excluded because other rules
already own them — see Related rules.

## How to fix violations

Switch to the counterpart the message names. For indexed access:

Before:

```csharp
void Update()
{
    foreach (var touch in Input.touches)
    {
        Handle(touch);
    }
}
```

After:

```csharp
void Update()
{
    for (var i = 0; i < Input.touchCount; i++)
    {
        Handle(Input.GetTouch(i));
    }
}
```

For `Renderer.GetSharedMaterials(List<Material>)` and `Camera.GetAllCameras(Camera[])`,
pass a list or array cached in a field so the buffer is reused across frames. Note that
`GetAllCameras` throws when the supplied array is smaller than `Camera.allCamerasCount`.

## When to suppress warnings

Suppress on cold branches inside hot methods (rare state transitions, debug-only paths)
where the read provably runs infrequently, or in editor tooling where per-frame allocation
pressure is not a concern.

## How to configure or suppress

- Single call site: wrap it in `#pragma warning disable UPA0018` / `#pragma warning restore UPA0018`
- Whole project: set `dotnet_diagnostic.UPA0018.severity = suggestion` (or `none`) in `.editorconfig`
- By path: the shipped presets relax rules under `[**/Editor/**/*.cs]`; add similar sections for tooling or generated code
- Hot-path classification: adjust the `upa_hot_path_*` options below

## Configuration

The hot-path classification is shared and configurable via `.editorconfig`:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerfCritical
upa_hot_path_include_lambdas = true
```

## Related rules

- `UNT0028` (Microsoft.Unity.Analyzers) owns the allocating physics queries; they are
  excluded from this rule's deny-list.
- `UNT0042` (Microsoft.Unity.Analyzers) owns the `Mesh` array properties; also excluded
  here.
- UPA0004 owns `Renderer.material` / `Renderer.materials`; only `sharedMaterials` belongs
  to this rule.
- UPA0017 owns the array-returning `GetComponents` overloads.
- UPA0030 owns the equivalent members in the .NET base class library. The split is by what a
  member belongs to — `UnityEngine.*` here, BCL there — so no call is reported by both.
