# UPA1001 — Non-exhaustive enum switch

> English | [繁體中文](UPA1001.zh-TW.md)

| | |
|---|---|
| Category | Correctness |
| Default severity | Warning |
| Enabled by default | Yes |

## Cause

A `switch` statement or `switch` expression over an enum does not handle every declared
member — and there is no `default` branch / `_` discard arm (or there is one, but
`upa_enum_switch_allow_default` is set to `false`).

## Rule description

Adding an enum member without updating every switch over that enum is one of the most
common sources of silent misbehavior in game code: state machines skip the new state,
item and damage types fall through unhandled, platform branches quietly do nothing.
Nothing crashes; behavior is just wrong.

The compiler only checks exhaustiveness for switch **expressions**, and stops as soon as
you add a `_` arm (CS8509). Switch **statements** are never checked. This rule covers
both, and can optionally keep naming the missing members even when a default arm exists.

Not analyzed, deliberately:

- **`[Flags]` enums** — bitwise combinations make exhaustiveness meaningless.
- **Switches with `when` guards, relational/range patterns, or non-constant labels** —
  coverage cannot be judged statically, so the whole switch is skipped rather than
  guessed at.
- **Non-enum switches.**

Members sharing a value (`Default = 0, Legacy = 0`) count as covered together, and the
missing-member list in the message truncates after five names.

## How to fix violations

```csharp
// Before: State.Dead was added last sprint, this switch never learned about it
switch (state)
{
    case State.Idle:    Wait();  break;
    case State.Running: Move();  break;
}

// After
switch (state)
{
    case State.Idle:    Wait();  break;
    case State.Running: Move();  break;
    case State.Dead:    Despawn(); break;
}
```

Adding a `default` arm also satisfies the rule (under the default configuration) — do
that when "everything else behaves the same" is genuinely the intent, not as a way to
silence the warning.

## When to suppress warnings

Suppress when a switch intentionally handles only a small relevant subset and a default
arm would be misleading. Prefer adding a deliberate `default` over suppressing.

## How to configure or suppress

- Strict mode: `upa_enum_switch_allow_default = false` in `.editorconfig` reports missing
  members even when a `default`/`_` arm exists (IDE only — Unity builds always use the
  default `true`, see the Q2 note in the README)
- Single switch: wrap it in `#pragma warning disable UPA1001` / `#pragma warning restore UPA1001`
- Whole project: set UPA1001 to `None` in your ruleset

## Configuration

```ini
upa_enum_switch_allow_default = true   # default; false = default/_ arms do not count
```
