# UPA2031 — Discarded infinite tween without SetLink

> English | [繁體中文](UPA2031.zh-TW.md)

| | |
|---|---|
| Category | Ecosystem |
| Default severity | Warning |
| Enabled by default | No |
| Active only when | the assembly references DOTween |

## Cause

A fluent chain creates an infinite tween — `SetLoops` called with a negative constant
loop count — the chain's result is discarded (the statement is a bare expression
statement), and no call in the chain is `SetLink`.

## Rule description

Two documented DOTween behaviors combine here: auto-kill disposes a tween when it
completes, and a negative loop count makes the tween loop indefinitely
([DOTween documentation](https://dotween.demigiant.com/documentation.php)). An infinite
tween does not reach completion, so auto-kill does not fire. When the chain's result is
also discarded, no code holds a handle that could kill the tween: it keeps running after
its target is destroyed, wasting per-frame work and surfacing as errors or leaks
depending on safe-mode settings.

`SetLink(gameObject)` binds the tween's lifetime to a GameObject, killing it when that
object is destroyed
([DOTween documentation](https://dotween.demigiant.com/documentation.php)) — chains
carrying a `SetLink` are exempt for exactly that reason.

Not reported:

- Chains whose result is stored, passed as an argument, returned, or yielded — the
  consumer can kill the tween itself.
- Chains containing `SetLink` anywhere.
- Finite loop counts, and loop counts that are not compile-time constants.

The rule reports anywhere, not only on hot paths — a leaked infinite tween costs the
same wherever it was created. It **runs only when the assembly references DOTween**
(both the free and the Pro distribution ship an assembly with that name) and stays
**disabled by default** (ecosystem block policy); presets enable it.

## How to fix violations

Either store the tween and kill it with its owner:

```csharp
Tween _spin;

void Start()
{
    _spin = transform
        .DORotate(new Vector3(0f, 360f, 0f), 2f, RotateMode.FastBeyond360)
        .SetLoops(-1);
}

void OnDestroy()
{
    _spin.Kill();
}
```

Or link its lifetime to the GameObject:

```csharp
void Start()
{
    transform
        .DORotate(new Vector3(0f, 360f, 0f), 2f, RotateMode.FastBeyond360)
        .SetLoops(-1)
        .SetLink(gameObject);
}
```

### The code fix

The IDE offers the second form: `.SetLink(gameObject)` appended to the end of the chain. It
is pure addition — not a character of the existing expression changes, and the chain's value
was already unused, which is the only situation this rule reports in.

It is not offered where `gameObject` is not in scope: outside a `Component`, or inside a
static method. There the tween's owner is a question only you can answer, so the diagnostic
stands and the choice between the two forms above is yours.

## When to suppress warnings

Suppress when the tween's lifetime is genuinely managed elsewhere — for example it
carries an ID via `SetId` and a manager kills it with `DOTween.Kill(id)`. The analyzer
does not track cross-method lifetime management.

## How to configure or suppress

- Enable the rule (it is off by default): `dotnet_diagnostic.UPA2031.severity = warning` in `.editorconfig`
- Single call site: wrap it in `#pragma warning disable UPA2031` / `#pragma warning restore UPA2031`
- Whole project: set `dotnet_diagnostic.UPA2031.severity = none`
