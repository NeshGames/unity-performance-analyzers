# UPA3001 — Sockets API unsupported on WebGL

> English | [繁體中文](UPA3001.zh-TW.md)

| | |
|---|---|
| Category | Platform |
| Default severity | Warning |
| Enabled by default | No |
| Active only when | the compilation defines `UPA_TARGET_WEBGL` |

## Cause

Use of any type from the `System.Net.Sockets` namespace — method calls, instance
construction, or static member access — in a compilation that defines `UPA_TARGET_WEBGL`.

## Rule description

Browsers do not expose raw socket access to page code, so `Socket`, `TcpClient`,
`UdpClient`, and the rest of `System.Net.Sockets` fail at runtime in Unity WebGL builds.
Networking on WebGL goes through the browser: HTTP via `UnityWebRequest`, persistent
connections via a WebSocket solution.

The rule group runs only when `UPA_TARGET_WEBGL` is defined and is disabled by default —
enable it via the `webgl-addon` preset.

## How to fix violations

- Request/response traffic → `UnityWebRequest`.
- Persistent bidirectional connections → a WebSocket-based transport (most Unity
  networking stacks provide a WebSocket option for WebGL).

## When to suppress warnings

Suppress code paths already gated behind `#if !UNITY_WEBGL` platform defines.

## How to configure or suppress

- Enable the rule (it is off by default): `dotnet_diagnostic.UPA3001.severity = warning` in `.editorconfig` (the `webgl-addon` preset does this)
- Single site: `#pragma warning disable UPA3001` / `#pragma warning restore UPA3001`
- Whole project: set `dotnet_diagnostic.UPA3001.severity = none`

## Configuration

None beyond the `UPA_TARGET_WEBGL` define.
