# UPA1000 — Leaf class not sealed (deprecated)

> English | [繁體中文](UPA1000.zh-TW.md)

| | |
|---|---|
| Category | Correctness |
| Default severity | Warning |
| Enabled by default | No |

## Status

**Deprecated. It reports nothing unless a project turns it on, and every shipped preset
sets it to `none`.** The id is kept because rule ids are never recycled.

## Why it was withdrawn

The rule said a leaf class should be `sealed` so that the runtime and IL2CPP can replace
virtual dispatch on it with direct calls. That claim was never measured; when it finally
was, the measurement could not resolve it.

A first probe compared a sealed leaf against an unsealed one with a single derived class.
It found no difference, which it was always going to: whole-program analysis devirtualizes
a hierarchy with one implementation whatever the declaration says. Widened to four derived
classes and repeated eight times on IL2CPP:

| | sealed | unsealed |
|---|---|---|
| Mean | 2.70 ns | 3.00 ns |
| Range | 2.18–3.46 (spread 1.28) | 2.81–3.45 (spread 0.64) |

The 0.30 ns difference sits inside a 1.28 ns spread, and in one of the eight runs the
ordering reversed. That is not a refutation — sealing may well help in cases this probe
does not reach — but it is not a demonstration either, and a rule that reports at type
granularity across a whole codebase should be able to show what it buys.

Sealing leaf classes remains reasonable design, and stating that a type is not meant to be
extended still communicates something. This package no longer warns about it.

## If you want it back

Set the severity explicitly and the original behaviour returns: concrete classes (not
`abstract`, not `static`) with no derived types in the compilation and no `virtual` members
of their own.

```ini
dotnet_diagnostic.UPA1000.severity = warning
```

For a Unity build the severity must come from a ruleset rather than `.editorconfig`; see
the ruleset presets shipped with the package.

Turned on, the exclusions and the limitation still hold: classes declaring their own
`virtual` members are skipped (sealing them is CS0549), `abstract` and `static` classes are
skipped, structs are implicitly sealed, and the analysis sees one compilation at a time —
a `public` type derived from another assembly looks like a leaf from here.

## Related rules

- None. `UNT####` rules do not cover sealing.
