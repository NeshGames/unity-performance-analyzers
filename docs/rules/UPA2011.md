# UPA2011 — Coroutine IEnumerator Unity message or method

> English | [繁體中文](UPA2011.zh-TW.md)

| | |
|---|---|
| Category | Ecosystem |
| Default severity | Warning |
| Enabled by default | No |
| Active only when | the assembly references UniTask |

## Cause

A method declared on a `MonoBehaviour`-derived type returns the non-generic
`System.Collections.IEnumerator` — the coroutine shape, including coroutine-form Unity
messages such as `IEnumerator Start()`.

## Rule description

Starting a coroutine allocates its compiler-generated enumerator state machine every
time, and each `StartCoroutine` call allocates a `Coroutine` handle object on top;
value-type yields (`yield return 0`) box. For code that starts coroutines frequently —
per-spawn effects, repeated UI transitions — this is steady garbage. Coroutines also
silently stop with their host object and cannot return values or propagate exceptions,
which async alternatives handle cleanly.

The diagnostic is reported **once, at the declaration** — `StartCoroutine` call sites
are deliberately not reported, so one coroutine produces one diagnostic no matter how
many places start it.

Not reported:

- `IEnumerator` methods on non-`MonoBehaviour` types — the ordinary enumerator pattern.
- Methods returning `IEnumerator<T>` — typical data iteration, not a coroutine.

The rule **runs only when the assembly references UniTask** (as of 0.2.0): without an
allocation-free replacement to point at, the advice would not be actionable. It also
stays **disabled by default** — whether to migrate off coroutines is a codebase stack
choice.

## How to fix violations

Pick per situation:

- **No `yield` needed** — make it a plain method.
- **Frame/time sequencing** — convert it to an `async UniTask` / `async UniTaskVoid`
  method driven by the player loop.
- **Keep the coroutine** where it is cold (started once, e.g. a scene-lifetime loop) —
  and suppress locally.

## When to suppress warnings

Suppress for coroutines started once per object lifetime, or in codebases that
deliberately standardize on coroutines.

## How to configure or suppress

- Enable the rule (it is off by default): `dotnet_diagnostic.UPA2011.severity = warning` in `.editorconfig`
- Single method: wrap the declaration in `#pragma warning disable UPA2011` / `#pragma warning restore UPA2011`
- Whole project: set `dotnet_diagnostic.UPA2011.severity = none`

## Configuration

None.
