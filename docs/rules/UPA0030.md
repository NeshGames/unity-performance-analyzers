# UPA0030 — Known-allocating BCL API in per-frame method

> English | [繁體中文](UPA0030.zh-TW.md)

| | |
|---|---|
| Category | Performance |
| Default severity | Warning |
| Enabled by default | Yes |

## Cause

One of a closed list of .NET base class library members that allocate on every call is called
inside a per-frame hot path: a hot Unity message such as `Update`, `FixedUpdate` or
`LateUpdate` on a `MonoBehaviour`-derived type, or a method marked with a hot-path attribute
such as `[HotPath]`.

| Member | Allocates | Replacement |
|---|---|---|
| `string.Split` | array plus each substring | `ReadOnlySpan<char>` slicing, or cache the result |
| `string.ToCharArray` | `char[]` | same |
| `string.Substring` | string | same |
| `string.ToLower` / `ToLowerInvariant` / `ToUpper` / `ToUpperInvariant` | string | compare with `StringComparison.OrdinalIgnoreCase` instead of changing case |
| `string.Trim` / `TrimStart` / `TrimEnd` | string, **only when there is something to trim** | `ReadOnlySpan<char>.Trim`, or move the call off the hot path |
| `Enum.GetValues` / `Enum.GetNames` | array | cache in a `static readonly` field |

## Rule description

Deciding whether an arbitrary method allocates requires escape analysis across method
boundaries. That is expensive on the Roslyn version this package targets, and not accurate
enough to report on. So this rule does not infer: it checks a curated list of members whose
allocation is a documented, verifiable fact, trading coverage for zero false positives.

The facts behind the list:

- [`System.String`](https://learn.microsoft.com/dotnet/api/system.string) is immutable, so
  every operation that appears to modify a string returns a new instance instead.
- [`Enum.GetValues`](https://learn.microsoft.com/dotnet/api/system.enum.getvalues) returns a
  new array on each call, which is why caching it is the standard advice.

Every entry was also measured in this project's sandbox on Unity 2022.3 and Unity 6, across
Mono and IL2CPP, before being listed — and the measurements decided how each one is worded.

**`Trim` and its variants return the original instance when there is nothing to trim**, and
allocate nothing in that case. They are reported with a message that says "whenever it has
work to do" rather than "on every call", because the contents of a string are not knowable at
compile time. The case conversions are *not* in that group: measurement shows they allocate on
Unity's runtimes even when the string is already in the target case, so their message is
unconditional.

`Substring(0)` is documented to return the receiver unchanged, so it is not reported at all —
a start index the analyzer cannot evaluate still is.

The list is closed by design. Entries are added deliberately, each one measured first, rather
than by widening a pattern — which is what keeps the false-positive count at zero. If a
member you expect to see is missing, that is a gap to report, not an oversight to work
around.

UnityEngine members with the same problem belong to UPA0018 instead. That split — BCL here,
`UnityEngine.*` there — is what keeps a single call from being reported by both rules.

## How to fix violations

Cache what does not change:

Before:

```csharp
void Update()
{
    foreach (var name in Enum.GetNames(typeof(State)))
    {
        Draw(name);
    }
}
```

After:

```csharp
static readonly string[] StateNames = Enum.GetNames(typeof(State));

void Update()
{
    foreach (var name in StateNames)
    {
        Draw(name);
    }
}
```

For case-insensitive comparison, compare instead of converting:

```csharp
// Before: allocates a lowercase copy of both operands
if (a.ToLowerInvariant() == b.ToLowerInvariant()) { }

// After: no allocation
if (string.Equals(a, b, StringComparison.OrdinalIgnoreCase)) { }
```

For parsing work that happens every frame, the usual answer is to stop doing it every frame:
parse once when the data arrives and keep the result.

## When to suppress warnings

Suppress on cold branches inside hot methods where the call provably runs infrequently, in
editor tooling, or when the allocation is small and the readability of the direct call is
worth more than the garbage.

Existing projects turning this rule on for the first time may see a burst of `Substring` and
`ToLower` reports. Running it at `warning` for a release before considering `error` is a
reasonable way to work through them.

## How to configure or suppress

- Single call site: wrap it in `#pragma warning disable UPA0030` / `#pragma warning restore UPA0030`
- Whole project: set `dotnet_diagnostic.UPA0030.severity = suggestion` (or `none`) in `.editorconfig`
- By path: the shipped presets relax rules under `[**/Editor/**/*.cs]`
- Hot-path classification: adjust the `upa_hot_path_*` options below

## Configuration

The hot-path classification is shared and configurable via `.editorconfig`:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerformanceCritical
upa_hot_path_include_lambdas = true
```

## Related rules

- UPA0018 owns the `UnityEngine.*` members that allocate arrays. The two lists do not
  overlap: new entries are placed by what they belong to, not by when they were added.
- UPA0013 owns LINQ use on hot paths, including `ToArray` and `ToList`. They are deliberately
  absent from this list — keeping them here, in a rule that is on by default, would work
  around the design that makes LINQ reporting opt-in.
- UPA0022 owns `Enum.HasFlag`; UPA0026 owns the boxing from `Enum.ToString`.
- `UNT0018` (Microsoft.Unity.Analyzers) owns reflection inside Unity messages, which is why
  the `System.Type` reflection members are not listed here.
