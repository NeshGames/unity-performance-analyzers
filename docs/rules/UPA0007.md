# UPA0007 — Capturing lambda in per-frame method

> English | [繁體中文](UPA0007.zh-TW.md)

| | |
|---|---|
| Category | Performance |
| Default severity | Warning |
| Enabled by default | Yes |

## Cause

A lambda or anonymous method whose capture set is non-empty — it references local
variables, parameters, or `this` from the enclosing scope — appears on a per-frame hot
path: a hot Unity message such as `Update`, `FixedUpdate`, or `LateUpdate` on a
`MonoBehaviour`-derived type, or a method marked with a hot-path attribute.

## Rule description

A capturing lambda must allocate a closure object holding the captured state, plus a fresh
delegate pointing at it, every time the enclosing code executes. On a per-frame path that
is garbage every frame.

A lambda that captures **nothing** is compiled to a cached static delegate — it allocates
once on first use and never again — so capture-free lambdas are not reported.

Note that calling any instance method or touching any field inside the lambda captures
`this`, which is enough to trigger the rule. This makes the rule fire often in real code;
that is intentional — implicit `this` capture is the largest source of per-frame delegate
allocations, and the fix (cache the delegate in a field) is mechanical.

The report is placed on the lambda expression itself: that is where the allocation
happens, regardless of the `upa_hot_path_include_lambdas` setting (which governs code
*inside* lambda bodies, not the lambda's own creation).

## How to fix violations

Cache the delegate in a field, or restructure to avoid capturing.

Before:

```csharp
void Update()
{
    _button.Schedule(() => Refresh());
}
```

After:

```csharp
Action _refresh;

void Awake()
{
    _refresh = Refresh;
}

void Update()
{
    _button.Schedule(_refresh);
}
```

## When to suppress warnings

Suppress when the lambda sits on a cold branch of a hot method, or when the receiving API
requires a fresh delegate per call by design.

## How to configure or suppress

- Single call site: wrap it in `#pragma warning disable UPA0007` / `#pragma warning restore UPA0007`
- Whole project: set `dotnet_diagnostic.UPA0007.severity = suggestion` (or `none`) in `.editorconfig`
- By path: the shipped presets relax rules under `[**/Editor/**/*.cs]`; add similar sections for tooling or generated code
- Hot-path classification: adjust the `upa_hot_path_*` options below

## Configuration

The hot-path classification is shared and configurable via `.editorconfig`:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerfCritical
upa_hot_path_include_lambdas = true
```

## Related rules
