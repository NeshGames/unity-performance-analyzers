# UPA0025 — Finalizer declared in runtime code

> English | [繁體中文](UPA0025.zh-TW.md)

| | |
|---|---|
| Category | Performance |
| Default severity | Warning |
| Enabled by default | Yes |

## Cause

A finalizer (destructor, `~TypeName()`) declared on any type in a player assembly.

Editor assemblies are skipped by assembly name: `Assembly-CSharp-Editor`, or any assembly
whose name ends in `.Editor` (case-insensitive).

## Rule description

Unity's programming best practices are direct on this point: "Don't use C# finalizers in
runtime code" —
[Programming best practices, Unity 6 Manual](https://docs.unity3d.com/6000.5/Documentation/Manual/programming-best-practices.html).

The costs are structural, not per-call:

- A finalizable object survives at least one extra garbage-collection cycle before its
  memory is reclaimed, so declaring a finalizer delays reclamation for every instance of
  the type.
- The finalizer runs on a dedicated finalizer thread, at a time you do not control and
  with no ordering guarantees between objects.
- The extra bookkeeping makes collection pauses less predictable.

Deterministic cleanup belongs in `IDisposable.Dispose`, called at a moment the game code
chooses.

The rule reports the declaration itself; an empty finalizer carries the same
garbage-collection cost as one with a body.

Editor detection is name-based. An editor assembly with an unconventional name — one that
is not `Assembly-CSharp-Editor` and does not end in `.Editor` — is treated as player code
and will be reported; suppress locally in that case, or rename the assembly to match the
convention.

## How to fix violations

Implement `IDisposable`, move the cleanup into `Dispose`, and remove the finalizer.

Before:

```csharp
public class NativeBufferOwner
{
    IntPtr _buffer = Allocate();

    ~NativeBufferOwner()
    {
        Free(_buffer);
    }
}
```

After:

```csharp
public sealed class NativeBufferOwner : IDisposable
{
    IntPtr _buffer = Allocate();

    public void Dispose()
    {
        if (_buffer != IntPtr.Zero)
        {
            Free(_buffer);
            _buffer = IntPtr.Zero;
        }
    }
}
```

For operating-system handles, derive from `System.Runtime.InteropServices.SafeHandle`
instead of writing a finalizer by hand — it provides the last-resort release path without
adding a finalizer to your own type.

## When to suppress warnings

- A type that directly owns an unmanaged resource and deliberately keeps a finalizer as a
  safety net for missed `Dispose` calls; prefer `SafeHandle` where it fits, and suppress
  where it does not.
- Finalizers in editor tooling that lives in an assembly with an unconventional name
  (see above).

## How to configure or suppress

- Single declaration: wrap it in `#pragma warning disable UPA0025` / `#pragma warning restore UPA0025`
- Whole project: set `dotnet_diagnostic.UPA0025.severity = suggestion` (or `none`) in `.editorconfig`
- By path: the shipped presets relax rules under `[**/Editor/**/*.cs]`; add similar sections for tooling or generated code

## Configuration

None. Editor assemblies are identified by assembly name, not by a configurable option.

## Related rules

- UPA0023 uses the same name-based editor-assembly detection and, like this rule, reports
  a declaration rather than a call site.
- `CA1821` (.NET code-quality rules) flags finalizers with empty or no-op bodies; this
  rule reports finalizers in Unity runtime code regardless of body.
