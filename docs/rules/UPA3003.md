# UPA3003 — Process API unsupported on WebGL

> English | [繁體中文](UPA3003.zh-TW.md)

| | |
|---|---|
| Category | Platform |
| Default severity | Warning |
| Enabled by default | No |
| Active only when | the compilation defines `UPA_TARGET_WEBGL` |

## Cause

Use of `System.Diagnostics.Process` — method calls, instance construction, or static
member access — in a compilation that defines `UPA_TARGET_WEBGL`.

## Rule description

Browsers cannot launch or inspect operating-system processes, so every `Process` API
fails at runtime in Unity WebGL builds. Such code in a game assembly is usually a
desktop-only helper (opening a folder, launching an external tool) that was never
platform-gated.

The rule group runs only when `UPA_TARGET_WEBGL` is defined and is disabled by default —
enable it via the `webgl-addon` preset.

## How to fix violations

- Opening a URL → `Application.OpenURL`, which works on every platform including WebGL.
- Desktop-only helpers → gate them behind `#if UNITY_STANDALONE` (or move them to an
  Editor assembly) and provide a WebGL-appropriate fallback or omit the feature.

## When to suppress warnings

Suppress code paths already gated behind `#if !UNITY_WEBGL` platform defines.

## How to configure or suppress

- Enable the rule (it is off by default): `dotnet_diagnostic.UPA3003.severity = warning` in `.editorconfig` (the `webgl-addon` preset does this)
- Single site: `#pragma warning disable UPA3003` / `#pragma warning restore UPA3003`
- Whole project: set `dotnet_diagnostic.UPA3003.severity = none`

## Configuration

None beyond the `UPA_TARGET_WEBGL` define.

## Related rules

- UPA3000 (threading), UPA3001 (sockets), UPA3002 (synchronous file IO) — the same WebGL
