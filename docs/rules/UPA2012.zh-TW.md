# UPA2012 — Async void or unawaited fire-and-forget

> [English](UPA2012.md) | 繁體中文

| | |
|---|---|
| 類別 | Ecosystem |
| 預設嚴重度 | Warning |
| 預設啟用 | 否 |

## 成因

兩種形態之一,以同一個規則 ID 回報:

- **A.** 任何 `async void` 的東西:以此宣告的方法或區域函式,或是被轉換成回傳 `void`
  委派(`Action`、`Action<T>`、`UnityAction` 或其他任何一種)的 `async` lambda 或匿名方法。
- **B.** 以運算式陳述式呼叫並回傳 `Task`、`Task<T>`、`UniTask` 或
  `UniTask<T>`,而結果被捨棄——沒有 await、沒有存起來、也沒有 `.Forget()`。
  null 條件呼叫 `loader?.LoadAsync();` 同樣捨棄了 task,也會回報。

## 規則說明

`async void` 方法擲出的例外無法被任何呼叫端捕捉,其完成狀態也無法被觀測。
在呼叫點被捨棄的 task 同樣會無聲地吞掉例外,並隱藏執行順序的錯誤——呼叫端在工作
完成之前就繼續往下走。兩者都是除錯黑洞,表現為「什麼都沒發生,也沒有錯誤」。

本規則永遠執行;引用 UniTask 的 assembly 只會切換建議的措辭
(`Task`/await 的說法,或 `UniTaskVoid`/`Forget` 的說法)。

不回報:

- **事件處理常式簽章的 async void**(`(object sender, EventArgs e)`,包含
  `EventArgs` 的衍生型別)——這是 .NET 的既定慣例。方法、區域函式與 lambda 一體適用。
- **轉換成回傳 task 的委派的 async lambda**——`Func<Task>`、`Task.Run(async () => ...)`。
  lambda 會回傳 task,呼叫端可以觀測它。
- **有 await 的呼叫**,以及**被指派、回傳或往下傳遞**的結果——已被觀測。
- **`.Forget()`**——UniTask 明確的射後不理寫法。
- **`_ = FooAsync();`**——discard 明確表達了意圖。

刻意的範圍限制:形態 B 只檢查裸的運算式陳述式。存進變數、只在部分路徑 await 的
task 需要控制流分析才能判斷,超出本規則刻意保持簡單的範圍。

## 如何修正

```csharp
// A: async void → awaitable return type
async void Fire() { ... }              // Before
async Task FireAsync() { ... }         // After (await or store at call sites)
async UniTaskVoid Fire() { ... }       // After, with UniTask — call Fire().Forget()

// B: discarded call → observe or make the intent explicit
FooAsync();                            // Before
await FooAsync();                      // After
FooAsync().Forget();                   // After, with UniTask, when fire-and-forget is intended
```

### 轉成 void 委派的 async lambda

`button.onClick.AddListener(async () => await LoadAsync());` 是 Unity UI 程式碼啟動非同步
工作最常見的寫法,而它會被回報:`UnityAction` 回傳 `void`,所以這個 lambda 是
`async void`,在第一個 `await` 之後擲出的例外到不了任何呼叫端。委派型別通常不是你能改的,
因此修法與形態 A 不同:

```csharp
button.onClick.AddListener(async () => await LoadAsync());               // Before

// With UniTask: the lambda becomes async UniTaskVoid, whose exceptions reach
// UniTaskScheduler instead of disappearing
button.onClick.AddListener(UniTask.UnityAction(async () => await LoadAsync()));
button.onClick.AddListener(() => LoadAsync().Forget());                  // LoadAsync returns UniTask

// Without UniTask: a Task-returning method that owns its exceptions, discarded explicitly
button.onClick.AddListener(() => _ = LoadAndReportAsync());

async Task LoadAndReportAsync()
{
    try { await LoadAsync(); }
    catch (Exception e) { Debug.LogException(e); }
}
```

那裡的 `_ =` 就是形態 B 接受的明確 discard:之所以成立,是因為被捨棄的方法本身不會無聲失敗。
lambda 沒有自己的名稱,所以訊息中列出的是它被轉換成的委派型別。

### `.Forget()` 與 `_ =` 的差別

`.Forget()` 只定義在 `UniTask`、`UniTask<T>` 與 `UniTaskVoid` 上——`Task` 沒有——而且需要
`using Cysharp.Threading.Tasks;`,呼叫點可能從未具名 UniTask。那正是 UniTask 為
fire-and-forget 定義的寫法:例外會進到 UniTask 的未處理例外通道,而不是消失。
`_ = FooAsync();` 等於說「例外消失是我決定的」;只有真的是決定時才這樣寫。
改 `async void` 的簽章會連鎖到每個呼叫端,請在同一次變更中一併更新。

## 何時抑制

很少需要——上述每一項排除都是明確表達意圖的方式,而且隨時可以改寫成
`_ = FooAsync();`。只在無法改寫的產生程式碼或 interop 程式碼中抑制。

## 如何設定或抑制

- 啟用本規則(預設關閉):在 `Assets/Default.ruleset` 設定 `<Rule Id="UPA2012" Action="Warning" />`
- 單一位置:以 `#pragma warning disable UPA2012` / `#pragma warning restore UPA2012` 包住
- 整個專案:在 `Assets/Default.ruleset` 設定 `<Rule Id="UPA2012" Action="None" />`

## 可設定項

無。UniTask 建議措辭的切換以引用的 assembly 名稱(`UniTask`)判斷。

## 相關規則

- UPA2010 建議 async 方法宣告以 UniTask 取代 `Task`。
- CS4014(編譯器)會對 async 方法內未 await 的呼叫發出警告;本規則額外涵蓋
  非 async 的呼叫端與 UniTask,並對明確的 discard 保持沉默。
