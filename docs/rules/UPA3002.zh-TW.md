# UPA3002 — Synchronous file IO unsupported on WebGL

> [English](UPA3002.md) | 繁體中文

| | |
|---|---|
| 類別 | Platform |
| 預設嚴重度 | Warning |
| 預設啟用 | 否 |
| 啟用條件 | 編譯定義了 `UPA_TARGET_WEBGL` |

## 成因

在定義了 `UPA_TARGET_WEBGL` 的編譯中,呼叫 `System.IO.File` 或
`System.IO.Directory` 的靜態方法,或建構 `FileStream`。

## 規則說明

Unity WebGL 建置沒有真正的檔案系統。瀏覽器沙盒只提供一個虛擬的記憶體內檔案系統,
其持久化需要明確的非同步同步(sync)動作——同步的 `File`/`Directory` 呼叫與
`FileStream` 建構要麼直接失敗,要麼無聲地寫進會隨分頁關閉而消失的記憶體。

以下刻意仍然允許:`Path`(純字串處理)與 `MemoryStream`(記憶體內,不涉及檔案系統)。

本規則群組只在定義了 `UPA_TARGET_WEBGL` 時執行,且預設停用——請透過
`webgl-addon` preset 啟用。

## 如何修正

- 小型設定/存檔資料 → `PlayerPrefs`(在 WebGL 上以瀏覽器儲存為後端)。
- 較大的資料 → 適合你技術棧的非同步儲存層(例如以 IndexedDB 為後端的外掛),
  或透過 `UnityWebRequest` 做伺服器端持久化。
- 隨建置出貨的唯讀內容 → 透過 `UnityWebRequest` 載入的
  `Addressables`/`StreamingAssets`,而非 `File.ReadAllBytes`。

## 何時抑制

對已經以 `#if !UNITY_WEBGL` 平台 define 隔離的程式碼路徑,或編譯進同一個
assembly 的 editor-only 工具程式碼,可予以抑制。

## 如何設定或抑制

- 啟用本規則(預設關閉):在 `.editorconfig` 設定 `dotnet_diagnostic.UPA3002.severity = warning`(`webgl-addon` preset 已代為設定)
- 單一位置:`#pragma warning disable UPA3002` / `#pragma warning restore UPA3002`
- 整個專案:設定 `dotnet_diagnostic.UPA3002.severity = none`

## 可設定項

除 `UPA_TARGET_WEBGL` define 外,無其他設定。

## 相關規則

- UPA3000(threading)、UPA3001(sockets)、UPA3003(processes)——同一個
  WebGL 群組,共用同一個 define。
