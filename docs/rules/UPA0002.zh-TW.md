# UPA0002 — Object name or tag accessed in per-frame method

> [English](UPA0002.md) | 繁體中文

| | |
|---|---|
| 類別 | 效能 |
| 預設嚴重度 | 警告(Warning) |
| 預設啟用 | 是 |

## 成因

在每幀熱路徑內讀取了 `UnityEngine.Object.name`、`UnityEngine.GameObject.tag` 或
`UnityEngine.Component.tag` 的 getter。所謂每幀熱路徑,是指
`MonoBehaviour` 衍生型別上的熱門 Unity 訊息(如 `Update`、`FixedUpdate`、`LateUpdate`),
或標記了熱路徑屬性(如 `[HotPath]`)的方法。

## 規則說明

這兩個 getter 都會呼叫進 Unity 的原生引擎程式碼,且每次存取都回傳一個新配置的
managed 字串——其值不會在 managed 端被快取。因此每幀讀取它們,
每幀都會產生垃圾(garbage),並增加原生呼叫的額外負擔。

作為 `==` 或 `!=` 運算元、與字串比較的讀取刻意**不**回報:
該模式由 `UNT0002`(Microsoft.Unity.Analyzers)涵蓋,它會建議改用
`CompareTag`。先把值讀進區域變數(`var t = tag; if (t == "A")`)則脫離了這個分工,
會由本規則回報。

對 `tag` 做 `switch` 在 v0.1 會被回報;此行為之後可能依回饋重新檢討。

## 如何修正

比較 tag 時使用 `CompareTag`,或在熱路徑外讀取一次值並快取。

修正前:

```csharp
void Update()
{
    if (other.gameObject.name == cachedName || Check(gameObject.name))
    {
    }
}
```

修正後:

```csharp
string _name;

void Awake()
{
    _name = gameObject.name;
}

void Update()
{
    if (_name == cachedName || Check(_name))
    {
    }
}
```

## 何時抑制

當物件確實會在幀與幀之間被重新命名或重設 tag、每幀都真的需要目前的值,
或位於每幀成本無關緊要的 editor 專用工具程式碼中時,可以抑制此警告。

## 如何設定或抑制

- 單一呼叫點:以 `#pragma warning disable UPA0002` / `#pragma warning restore UPA0002` 包住
- 整個專案:在 `.editorconfig` 設定 `dotnet_diagnostic.UPA0002.severity = suggestion`(或 `none`)
- 依路徑:隨附的 preset 已放寬 `[**/Editor/**/*.cs]` 下的規則;可為工具程式碼或產生的程式碼加入類似區段
- 熱路徑判定:調整下方的 `upa_hot_path_*` 選項

## 可設定項

熱路徑判定是共用的,可透過 `.editorconfig` 設定:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerformanceCritical
upa_hot_path_include_lambdas = true
```

## 相關規則

- `UNT0002`(Microsoft.Unity.Analyzers)涵蓋 `tag == "..."` / `name == "..."`
  形式的比較,並提供 `CompareTag` 的 code fix。UPA0002 在該模式上讓位給它。
