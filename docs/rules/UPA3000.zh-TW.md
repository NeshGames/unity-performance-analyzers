# UPA3000 — Threading API unsupported on WebGL

> [English](UPA3000.md) | 繁體中文

| | |
|---|---|
| 類別 | Platform |
| 預設嚴重度 | Warning |
| 預設啟用 | 否 |
| 啟用條件 | 編譯定義了 `UPA_TARGET_WEBGL` |

## 成因

在定義了 `UPA_TARGET_WEBGL` 的編譯中使用執行緒 API:建構或呼叫 `Thread`、
`ThreadPool`、`System.Threading.Timer`、`Mutex`、`Semaphore`、`SemaphoreSlim`、
`Barrier` 或 `EventWaitHandle`(包含 `AutoResetEvent` 等衍生型別);使用
`System.Threading.Tasks.Parallel`;或呼叫 `Task.Run`、`Task.Delay`、
`TaskFactory.StartNew`。

## 規則說明

Unity WebGL 建置在單一執行緒上執行。建立執行緒與執行緒集區排程會在執行期失敗,
而阻塞式同步原語會把唯一的執行緒卡死。`Task.Run` 與 `TaskFactory.StartNew`
會排程到執行緒集區;`Task.Delay` 依賴的計時器機制已知在 WebGL 上不會完成。

以下刻意仍然允許:`lock`/`Monitor`、`Interlocked`、`CancellationToken`,
以及搭配 `Task` 本身的一般 `async`/`await`——這些在單執行緒執行中都可使用。

本規則群組只在定義了 `UPA_TARGET_WEBGL` 時執行(這是專案層級的 define,
當 WebGL 是你的目標平台之一時加入,規則就會在每次 Editor 建置中保持啟用),
且預設停用——請透過 `webgl-addon` preset 啟用。

## 如何修正

- `Task.Run(work)` → 在主執行緒上執行該工作、用 coroutine 分攤,或在支援之處使用
  Job System。
- `Task.Delay(ms)` → 使用 `yield return new WaitForSeconds(...)` 的 coroutine,或
  `UniTask.Delay`(其 player-loop 計時器可在 WebGL 上運作)。
- 同步原語 → 在單執行緒執行中通常可以直接刪除。

## 何時抑制

對已經以 `#if !UNITY_WEBGL` 平台 define 隔離的程式碼路徑,或編譯進同一個
assembly 的 editor-only 工具程式碼,可予以抑制。

## 如何設定或抑制

- 啟用本規則(預設關閉):在 `.editorconfig` 設定 `dotnet_diagnostic.UPA3000.severity = warning`(`webgl-addon` preset 已代為設定)
- 在 Project Settings > Player > Scripting Define Symbols 為每個建置目標定義
  `UPA_TARGET_WEBGL`,規則才不會在非 WebGL 建置時失效
- 單一位置:`#pragma warning disable UPA3000` / `#pragma warning restore UPA3000`
- 整個專案:設定 `dotnet_diagnostic.UPA3000.severity = none`

## 可設定項

除 `UPA_TARGET_WEBGL` define 外,無其他設定。

## 相關規則

- UPA3001(sockets)、UPA3002(同步檔案 IO)、UPA3003(processes)——同一個
  WebGL 群組,共用同一個 define。
