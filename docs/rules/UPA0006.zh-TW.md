# UPA0006 — Reference type allocated in per-frame method

> [English](UPA0006.md) | 繁體中文

| | |
|---|---|
| 類別 | 效能 |
| 預設嚴重度 | 警告(Warning) |
| 預設啟用 | 是 |

## 成因

在每幀熱路徑內發生了 managed 堆積(heap)配置:建立參考型別物件
(`new List<int>()`)、建立陣列(`new int[16]`),或對值型別做 boxing 轉換
(`object o = 42;`,或把 struct 傳給 `object` 或介面型別的參數)。

## 規則說明

Unity 的垃圾回收器是非分代式(non-generational)的:回收成本隨整個 managed 堆積
的大小增長,而回收時機由配置速率決定。因此每幀配置會表現為週期性的幀尖峰,
且其發生時機不受你控制。讓熱路徑保持零配置是標準紀律,本規則就是在落實它。

boxing 之所以納入,是因為它是最隱形的配置——原始碼裡沒有 `new`。
它常藏在轉換成 `object` 或介面參數、非泛型集合,
以及把 `enum` 值傳給非泛型 API 的地方。

刻意劃定的範圍界線:

- **值型別的 `new` 不回報**——struct 不在 managed 堆積上配置。
- **`throw new Exception(...)` 不回報**——例外路徑理應罕見;
  每幀丟例外是另一種 bug。
- **lambda 與閉包**屬於 UPA0007 的範圍;**字串串接與插值**屬於 UPA2000;
  方法群組(method group)產生的委派建立與 `params` 陣列展開在 v0.1 不在範圍內。
- 注意一個交互作用:隱含的 `params` 陣列本身不回報,但被 box 進該陣列的值型別
  仍會回報——那次 boxing 是真實的配置。
- 同樣地,被 box 進字串串接的值型別(`"x" + n`)會由本規則回報,
  即使串接本身屬於 UPA2000。兩者是不同的配置,
  而 ZString 式的改寫可以一次消除兩者。

這是本套件中觸發範圍最廣的規則。熱方法內的冷分支
(一次性的延遲初始化、罕見的除錯快照)即使很少執行也會被回報——
analyzer 不做流程分析。這些情況請使用下方的抑制選項。

## 如何修正

把配置提升到熱路徑之外,並重複使用該實例。

修正前:

```csharp
void Update()
{
    var results = new List<RaycastHit>();
    Scan(results);
}
```

修正後:

```csharp
readonly List<RaycastHit> _results = new List<RaycastHit>();

void Update()
{
    _results.Clear();
    Scan(_results);
}
```

對於 boxing,優先使用泛型多載(以 `Consume<T>(T value)` 取代
`Consume(object value)`)或泛型集合。

## 何時抑制

在可證明極少執行的冷分支上(延遲初始化的守衛、僅供除錯的路徑),
或在特定位置採用池化/快取設計所增加的複雜度超過該配置的代價時,
可以抑制此警告。

## 如何設定或抑制

- 單一呼叫點:以 `#pragma warning disable UPA0006` / `#pragma warning restore UPA0006` 包住
- 整個專案:在 `.editorconfig` 設定 `dotnet_diagnostic.UPA0006.severity = suggestion`(或 `none`)
- 依路徑:隨附的 preset 已放寬 `[**/Editor/**/*.cs]` 下的規則;可為工具程式碼或產生的程式碼加入類似區段
- 熱路徑判定:調整下方的 `upa_hot_path_*` 選項

## 可設定項

熱路徑判定是共用的,可透過 `.editorconfig` 設定:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerfCritical
upa_hot_path_include_lambdas = true
```

## 相關規則

- UPA0007 涵蓋捕捉式 lambda 造成的委派與閉包配置。
- UPA2000 涵蓋熱路徑上的字串串接與插值。
