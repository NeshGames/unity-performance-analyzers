# UPA0026 — Value type boxed by inherited method call

> English | [繁體中文](UPA0026.zh-TW.md)

| | |
|---|---|
| Category | Performance |
| Default severity | Warning |
| Enabled by default | Yes |

## Cause

Inside a per-frame hot path (a hot Unity message such as `Update`, `FixedUpdate`, or
`LateUpdate` on a `MonoBehaviour`-derived type, or a method marked with a hot-path
attribute such as `[HotPath]`), `GetType()` is called on a struct or enum receiver.

## Rule description

`GetType()` is declared on `System.Object` and cannot be overridden, so a value type has no
implementation of its own to dispatch to. The CLR's constrained-call rules spell out what
happens instead: if the value type "does not implement `method` then `ptr` is dereferenced,
boxed, and passed as the 'this' pointer" —
[OpCodes.Constrained, Microsoft Learn](https://learn.microsoft.com/en-us/dotnet/api/system.reflection.emit.opcodes.constrained).
That box is a heap allocation, and it buys an answer the compiler already had.

Measured on an IL2CPP player, both supported Unity versions: a `GetType()` call on a struct
or enum receiver allocates, while `ToString()`, `GetHashCode()` and `Equals(object)` on the
same receivers allocate nothing.

**On Mono those three do allocate** — 0.23 B per call on Unity 2022.3 and 1.11 B on Unity 6,
for the receiver box the constrained call performs. This package treats IL2CPP as the backend
that decides, because it is what most shipped games run, so this rule does not report them.
A Mono build pays that cost and will not hear about it here; overriding `Equals` and
`GetHashCode` on a struct remains worth doing for the reasons `CA1815` gives.

### What this rule used to report

Until it was measured, this rule also named `ToString()`, `GetHashCode()` and
`Equals(object)` when the value type did not override them, on the reasoning above plus
"the JIT optimizations that remove such boxing do not apply to Unity's Mono". The reasoning
is sound and the conclusion was wrong: all three read zero on IL2CPP, with the argument
boxed once outside the measurement loop so that the receiver was the only thing left that
could allocate.

What does allocate in `value.Equals(other)` is the **argument** — `Equals(object)` takes an
`object`, so the operand is boxed at the call. That is a different conversion in a different
place, and [UPA0006](UPA0006.md) reports it there.

Note that overriding `Equals` and `GetHashCode` on a struct remains worth doing for reasons
this rule no longer speaks to: the inherited implementations compare and hash fields through
reflection, which is slow even when it allocates nothing
([CA1815, Microsoft Learn](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca1815)),
and a struct used as a dictionary key without `IEquatable<T>` is reported by
[UPA0028](UPA0028.md).

What is and is not reported:

- Receivers whose type is a generic type parameter are not reported — whether the
  constrained call boxes depends on the type the parameter is instantiated with.
- Reference-type receivers are not reported: there is nothing to box.

Only the body of the hot-path method itself (including its lambdas and local functions) is
analyzed. Calls inside helper methods invoked from a hot path are deliberately not reported
— this analyzer prefers missed reports over false positives.

## How to fix violations

Use `typeof`. The type is a compile-time fact wherever the receiver's static type is known,
which is exactly when this rule fires.

```csharp
// Before
void Update()
{
    var t = _cursor.GetType();   // boxes the struct; the answer was known at compile time
}

// After
void Update()
{
    var t = typeof(Cursor);
}
```

If the receiver's runtime type genuinely differs from its static type, the receiver is not a
value type and this rule does not report it.

### The code fix

The IDE offers this rewrite where dropping the receiver cannot change what runs: a bare
local, parameter or field, `this`, `this.field`, or no receiver at all. A longer chain is not
offered — `holder.Value.GetType()` would lose the `NullReferenceException` that dereferencing
a null `holder` throws, and `StaticHolder.Value.GetType()` would stop running a type
initializer. It is also not offered when the receiver is

- a **property** — a getter may do anything, and the rewrite would stop calling it;
- a **method call** — it is evaluated once today and not at all afterwards;
- an **indexer** — the rewrite would also remove the bounds check that can throw;
- a **nullable value type** — `((int?)x).GetType()` returns `typeof(int)` when there is a
  value and throws `NullReferenceException` when there is not, and no `typeof` spelling
  keeps both.

The diagnostic is still reported in those cases. Hoist the receiver into a local first, or
write the `typeof` by hand once you know the receiver is safe to drop.

## When to suppress warnings

Suppress on cold branches inside hot methods — rare state transitions, or logging and
error paths that provably run infrequently.

## How to configure or suppress

- Single call site: wrap it in `#pragma warning disable UPA0026` / `#pragma warning restore UPA0026`
- Whole project: set `dotnet_diagnostic.UPA0026.severity = suggestion` (or `none`) in `.editorconfig`
- By path: the shipped presets relax rules under `[**/Editor/**/*.cs]`; add similar sections for tooling or generated code
- Hot-path classification: adjust the `upa_hot_path_*` options below

## Configuration

The hot-path classification is shared and configurable via `.editorconfig`:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerformanceCritical
upa_hot_path_include_lambdas = true
```

## Related rules

- [UPA0022](UPA0022.md) covered `Enum.HasFlag`, a member of the same family. It is
  deprecated: the call boxes nothing on any supported runtime.
- `CA1815` (.NET code-quality rules) asks value types to override `Equals` and `==` for
  the same underlying reason, in any calling context; this rule fires only on hot paths.
