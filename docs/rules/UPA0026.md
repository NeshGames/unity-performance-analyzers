# UPA0026 — Value type boxed by inherited method call

> English | [繁體中文](UPA0026.zh-TW.md)

| | |
|---|---|
| Category | Performance |
| Default severity | Warning |
| Enabled by default | Yes |

## Cause

Inside a per-frame hot path (a hot Unity message such as `Update`, `FixedUpdate`, or
`LateUpdate` on a `MonoBehaviour`-derived type, or a method marked with a hot-path
attribute such as `[HotPath]`), a call on a struct or enum receiver resolves to a method
inherited from `System.Object`, `System.ValueType`, or `System.Enum`:

- `ToString()`, `GetHashCode()`, or `Equals(object)` that the value type does not
  override
- `GetType()`, which cannot be overridden

## Rule description

When the value type does not provide its own implementation, the runtime cannot dispatch
the call on the unboxed value. The CLR's constrained-call rules spell this out: if the
value type "does not implement `method` then `ptr` is dereferenced, boxed, and passed as
the 'this' pointer", and this case can occur only for methods defined on `Object`,
`ValueType`, or `Enum` that the type does not override —
[OpCodes.Constrained, Microsoft Learn](https://learn.microsoft.com/en-us/dotnet/api/system.reflection.emit.opcodes.constrained).
The box is a heap allocation on every call. Modern .NET removes some of this boxing
through JIT optimizations; those optimizations do not apply to Unity's Mono runtime, so
on Unity these calls allocate.

For non-blittable structs there is a second cost: the inherited `ValueType.Equals` and
`GetHashCode` compare and hash the fields through reflection, which is computationally
expensive —
[CA1815, Microsoft Learn](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca1815).

What is and is not reported:

- A type that overrides the member resolves to its own declaration and is naturally
  excluded — `intValue.ToString()` binds to `Int32.ToString()` and does not report.
- `Equals(T)` through `IEquatable<T>` binds to the interface implementation and does not
  report.
- Receivers whose type is a generic type parameter are not reported — whether the
  constrained call boxes depends on the type the parameter is instantiated with.
- `GetType()` reports on every value-type receiver: it cannot be overridden, it boxes the
  receiver, and its result is known at compile time anyway.

Only the body of the hot-path method itself (including its lambdas and local functions) is
analyzed. Calls inside helper methods invoked from a hot path are deliberately not reported
— this analyzer prefers missed reports over false positives.

## How to fix violations

The fix depends on the receiver:

- **Struct**: override `ToString`, `GetHashCode`, and `Equals(object)` on the struct; for
  equality, also implement `IEquatable<T>` and compare through `Equals(T)` or `==`.
- **Enum**: there is no override to add — cache or precompute the results (display names,
  hash values) outside the hot path, and compare enum values with `==` instead of
  `Equals(object)`.
- **`GetType()`**: the result is known at compile time — use `typeof(TheType)`.

```csharp
// Before
void Update()
{
    _label.text = _state.ToString();          // enum: boxes the receiver each frame
    if (_slot.Equals(other)) { Consume(); }   // struct without overrides: boxes both sides
    var t = _cursor.GetType();                // struct: boxes; result is known statically
}

// After
static readonly Dictionary<UnitState, string> s_stateNames = BuildStateNames(); // filled once

void Update()
{
    _label.text = s_stateNames[_state];
    if (_slot == other) { Consume(); }        // ==/IEquatable<T> on the struct
    var t = typeof(Cursor);
}
```

## When to suppress warnings

Suppress on cold branches inside hot methods — rare state transitions, or logging and
error paths that provably run infrequently.

## How to configure or suppress

- Single call site: wrap it in `#pragma warning disable UPA0026` / `#pragma warning restore UPA0026`
- Whole project: set `dotnet_diagnostic.UPA0026.severity = suggestion` (or `none`) in `.editorconfig`
- By path: the shipped presets relax rules under `[**/Editor/**/*.cs]`; add similar sections for tooling or generated code
- Hot-path classification: adjust the `upa_hot_path_*` options below

## Configuration

The hot-path classification is shared and configurable via `.editorconfig`:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerfCritical
upa_hot_path_include_lambdas = true
```

## Related rules

- UPA0022 covers `Enum.HasFlag`, a specific member of the same boxing family, and ships a
  dedicated code fix.
- `CA1815` (.NET code-quality rules) asks value types to override `Equals` and `==` for
  the same underlying reason, in any calling context; this rule fires only on hot paths.
