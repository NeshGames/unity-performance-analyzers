# UPA3000 — Threading API unsupported on WebGL

> English | [繁體中文](UPA3000.zh-TW.md)

| | |
|---|---|
| Category | Platform |
| Default severity | Warning |
| Enabled by default | No |
| Active only when | the compilation defines `UPA_TARGET_WEBGL` |

## Cause

Use of a threading API in a compilation that defines `UPA_TARGET_WEBGL`: constructing or
calling `Thread`, `ThreadPool`, `System.Threading.Timer`, `Mutex`, `Semaphore`,
`SemaphoreSlim`, `Barrier`, or `EventWaitHandle` (including derived handles such as
`AutoResetEvent`); using `System.Threading.Tasks.Parallel`; or calling `Task.Run`,
`Task.Delay`, or `TaskFactory.StartNew`.

## Rule description

Unity WebGL builds run on a single thread. Thread creation and thread-pool scheduling
fail at runtime, and blocking synchronization primitives hang the only thread there is.
`Task.Run` and `TaskFactory.StartNew` schedule onto the thread pool; `Task.Delay` relies
on timer machinery known not to complete on WebGL.

Deliberately still allowed: `lock`/`Monitor`, `Interlocked`, `CancellationToken`, and
plain `async`/`await` with `Task` itself — all usable in single-threaded execution.

The rule group runs only when `UPA_TARGET_WEBGL` is defined (a project-level define you
add when WebGL is one of your targets, so the rules stay active in every Editor build),
and is disabled by default — enable it via the `webgl-addon` preset.

## How to fix violations

- `Task.Run(work)` → run the work on the main thread, spread it with a coroutine, or use
  the Job System where supported.
- `Task.Delay(ms)` → a coroutine with `yield return new WaitForSeconds(...)`, or
  `UniTask.Delay` (its player-loop timer works on WebGL).
- Synchronization primitives → usually deletable outright in single-threaded execution.

## When to suppress warnings

Suppress code paths already gated behind `#if !UNITY_WEBGL` platform defines, or
editor-only tooling compiled into the same assembly.

## How to configure or suppress

- Enable the rule (it is off by default): `dotnet_diagnostic.UPA3000.severity = warning` in `.editorconfig` (the `webgl-addon` preset does this)
- Define `UPA_TARGET_WEBGL` in Project Settings > Player > Scripting Define Symbols for every build target, so the rule does not switch off outside WebGL builds
- Single site: `#pragma warning disable UPA3000` / `#pragma warning restore UPA3000`
- Whole project: set `dotnet_diagnostic.UPA3000.severity = none`

## Configuration

None beyond the `UPA_TARGET_WEBGL` define.
