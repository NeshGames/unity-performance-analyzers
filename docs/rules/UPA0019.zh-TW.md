# UPA0019 — Coroutine yield 了會裝箱的值

> [English](UPA0019.md) | 繁體中文

| | |
|---|---|
| 類別 | Performance |
| 預設嚴重度 | Warning |
| 預設啟用 | 是 |

## 成因

在 `MonoBehaviour` 衍生型別上、回傳型別為非泛型
`System.Collections.IEnumerator` 的方法中,`yield return` 了實值型別運算式——
例如 `yield return 0`、`yield return false` 或 `yield return someStruct`。

以下情況不會回報:

- `yield return null`——不配置的等待一幀寫法
- yield `YieldInstruction`(`WaitForSeconds`、`WaitForFixedUpdate` 等)或
  `CustomYieldInstruction`(`WaitUntil`、`WaitWhile` 等)——它們是參考型別,
  也是 coroutine 的正規詞彙
- 非 `MonoBehaviour` 衍生型別上的 `IEnumerator` 方法——資料列舉器,
  其 yield 出的值對消費端有意義

本規則不限於逐幀熱路徑;coroutine 一旦啟動,便照自己的排程恢復執行,
與啟動位置無關。

## 規則說明

非泛型 `IEnumerator.Current` 的型別是 `object`,因此 yield 實值型別會在每次恢復時
將其裝箱:「boxing and unboxing are computationally expensive processes. When a value
type is boxed, a new object must be allocated and constructed」——
[Microsoft Learn, Boxing and Unboxing](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/types/boxing-and-unboxing)。

這筆配置換不到任何東西:Unity 的 coroutine 排程器把不是 yield instruction 的
裝箱值當成 `null` 處理,也就是等待一幀。手冊明確點出不配置的寫法:
「A `yield return null` does not allocate but yield instructions like
`new WaitForSeconds` do」——
[Unity Manual, Write and run coroutines](https://docs.unity3d.com/6000.5/Documentation/Manual/Coroutines.html)。
在跨多幀執行的 coroutine 裡,裝箱的 yield 是穩定產生的垃圾,
而行為與 `yield return null` 沒有差異。

診斷訊息為:「Yielding '{0}' boxes the value on every resume, and Unity treats it the
same as null. Yield null to wait one frame.」

## 修正方式

套用隨附的 code fix(「Yield null instead」),或手動修改:

修正前:

```csharp
IEnumerator FadeOut()
{
    while (_alpha > 0f)
    {
        _alpha -= Time.deltaTime;
        yield return 0;   // 每次恢復都裝箱一個 int
    }
}
```

修正後:

```csharp
IEnumerator FadeOut()
{
    while (_alpha > 0f)
    {
        _alpha -= Time.deltaTime;
        yield return null;
    }
}
```

## 何時可以抑制

當該 `IEnumerator` 方法恰好位於 `MonoBehaviour` 上、卻不是作為 coroutine 啟動——
由你自己的程式碼列舉並讀取 yield 出的值時,可以抑制。
也可以考慮把這類列舉器搬到一般型別上,回報同樣會消失。

## 設定與抑制方式

- 單一呼叫位置:以 `#pragma warning disable UPA0019` / `#pragma warning restore UPA0019` 包住
- 整個專案:在 `.editorconfig` 設定 `dotnet_diagnostic.UPA0019.severity = suggestion`(或 `none`)
- 依路徑:隨附的 preset 已放寬 `[**/Editor/**/*.cs]` 下的規則;可為工具程式碼或產生的程式碼加入類似區段

## 可設定項

無。
