# UPA0020 — 以 lambda 建構 WaitUntil / WaitWhile

> [English](UPA0020.md) | 繁體中文

| | |
|---|---|
| 類別 | Performance |
| 預設嚴重度 | Warning |
| 預設啟用 | 否 |

## 成因

以 lambda 或匿名方法作為 predicate 參數的 `new WaitUntil(...)` 或
`new WaitWhile(...)`:

```csharp
yield return new WaitUntil(() => _ready);
```

方法群組參數(`new WaitUntil(IsReady)`)不會回報。本規則不限於逐幀熱路徑——
在迴圈中反覆建構這種寫法的 coroutine,不論從哪裡啟動,每次迭代都會重新配置。

## 規則說明

每次建構都會配置 yield instruction、delegate,以及任何被捕捉的閉包。
Unity 的 coroutine 指引直接建議快取的替代寫法:「Cache commonly reused ones and
avoid lambdas in `WaitUntil` and `WaitWhile` to prevent delegate and capture
allocations」——
[Unity Manual, Write and run coroutines](https://docs.unity3d.com/6000.5/Documentation/Manual/Coroutines.html)。

本規則不做流程分析,因此可證明只執行一次的建構——欄位初始器,或 `Awake` 中的
一次性設定——仍會回報。這個取捨讓規則保持簡單、可預期,也是它**預設停用**的原因:
`strict` preset 以 `Warning` 啟用,`cysharp-stack` preset 則設為 `Error`。

診斷訊息為:「Constructing this {0} with a lambda allocates the delegate (and any
closure) each time this code runs. Cache the yield instruction and its predicate in
fields.」

## 修正方式

把 yield instruction 與其 predicate 快取到欄位;用方法群組即可避免 lambda。

修正前:

```csharp
IEnumerator WaitForReady()
{
    yield return new WaitUntil(() => _ready);
}
```

修正後:

```csharp
WaitUntil _waitReady;

void Awake()
{
    _waitReady = new WaitUntil(IsReady);
}

bool IsReady() => _ready;

IEnumerator WaitForReady()
{
    yield return _waitReady;
}
```

快取後的 instruction 只建構一次,之後所有 yield 它的 coroutine 都重複使用同一個實例。

## 何時可以抑制

當建構可證明只執行一次——欄位初始器或一次性設定路徑——可以抑制。
本規則因為不做流程分析,在這些位置仍會回報;就地 `#pragma` 能記錄這個意圖。
若 predicate 沒有捕捉任何東西,照上面的方式快取通常和抑制一樣省事。

## 設定與抑制方式

- 啟用本規則(預設為關閉):在你的 ruleset 中把 UPA0020 設為 `Warning`(`strict` preset 已包含;`cysharp-stack` 提升為 `Error`),或在 `.editorconfig` 設 `dotnet_diagnostic.UPA0020.severity = warning`
- 單一呼叫位置:以 `#pragma warning disable UPA0020` / `#pragma warning restore UPA0020` 包住
- 整個專案:把 UPA0020 設為 `None`

## 可設定項

無。
