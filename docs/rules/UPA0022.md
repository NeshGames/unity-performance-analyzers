# UPA0022 — Enum.HasFlag in per-frame method

> English | [繁體中文](UPA0022.zh-TW.md)

| | |
|---|---|
| Category | Performance |
| Default severity | Warning |
| Enabled by default | Yes |

## Cause

A call to `System.Enum.HasFlag` inside a per-frame hot path: a hot Unity message such as
`Update`, `FixedUpdate`, or `LateUpdate` on a `MonoBehaviour`-derived type, or a method
marked with a hot-path attribute such as `[HotPath]`.

## Rule description

`HasFlag` is declared on the `System.Enum` base class and its parameter is typed as
`System.Enum`. On Unity's Mono runtime, calling it on an enum value therefore boxes both
the receiver and the argument — two heap allocations per call for a test that compiles
down to a single bitwise instruction when written by hand. Newer .NET runtimes recognize
`HasFlag` as a JIT intrinsic and remove the boxing, but that optimization does not apply
to Unity's Mono runtime, and IL2CPP behavior varies by Unity version — on Unity, treat
the call as allocating.

The replacement loses nothing: the documented result of `HasFlag` is exactly the Boolean
expression `(thisInstance & flag) == flag` —
[Enum.HasFlag, Microsoft Learn](https://learn.microsoft.com/en-us/dotnet/api/system.enum.hasflag).
Both forms return `true` when the flag argument is zero, so the rewrite preserves that
edge case as well.

Only the body of the hot-path method itself (including its lambdas and local functions) is
analyzed. Calls inside helper methods invoked from a hot path are deliberately not reported
— this analyzer prefers missed reports over false positives.

## How to fix violations

Replace the call with an explicit bitwise check. A code fix ("Use a bitwise check") is
available that rewrites `x.HasFlag(y)` to `(x & y) == y`. Because the rewrite repeats
the flag expression, the fix is offered only when that expression is a constant, local,
parameter, or field; for a method call or property access, apply the rewrite by hand
with the flag stored in a local first.

Before:

```csharp
void Update()
{
    if (_state.HasFlag(UnitState.Stunned))
    {
        return;
    }
}
```

After:

```csharp
void Update()
{
    if ((_state & UnitState.Stunned) == UnitState.Stunned)
    {
        return;
    }
}
```

## When to suppress warnings

Suppress on cold branches inside hot methods (rare state transitions, debug-only paths)
where the call provably runs infrequently.

## How to configure or suppress

- Single call site: wrap it in `#pragma warning disable UPA0022` / `#pragma warning restore UPA0022`
- Whole project: set `dotnet_diagnostic.UPA0022.severity = suggestion` (or `none`) in `.editorconfig`
- By path: the shipped presets relax rules under `[**/Editor/**/*.cs]`; add similar sections for tooling or generated code
- Hot-path classification: adjust the `upa_hot_path_*` options below

## Configuration

The hot-path classification is shared and configurable via `.editorconfig`:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerfCritical
upa_hot_path_include_lambdas = true
```

## Related rules

- UPA0026 reports the broader family of value-type calls that box their receiver because
  they resolve to methods inherited from `Object`/`ValueType`/`Enum`; UPA0022 covers the
  `HasFlag` case specifically and ships a dedicated code fix.
