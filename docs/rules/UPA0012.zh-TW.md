# UPA0012 — TextMeshPro text assignment instead of SetText

> [English](UPA0012.md) | 繁體中文

| | |
|---|---|
| 類別 | Performance |
| 預設嚴重度 | Warning |
| 預設啟用 | 否 |

## 成因

在每幀熱路徑內對 `TMPro.TMP_Text` 衍生元件(`TextMeshProUGUI`、`TextMeshPro`)的
`text` 屬性進行指派:所謂熱路徑,指的是 `MonoBehaviour` 衍生型別上的熱 Unity message
(例如 `Update`),或標記了熱路徑 attribute 的方法。

## 規則說明

每次對 `text` 的指派都會儲存字串並把文字標記為 dirty,觸發網格重新產生。常見的每幀
寫法——`label.text = value.ToString()` 或字串串接——還會在每幀額外配置一個新的中介
字串。`SetText` 的多載會把數值引數直接格式化到元件的內部緩衝區,完全避開中介配置。

本規則**預設停用**:在熱路徑上指派常數字串也會被回報(dirty 旗標的成本仍然存在),
但本規則的主要價值在於格式化數值的模式,因此交由 `strict` / `cysharp-stack` preset
來啟用。

只回報 setter 的使用;對 `text` 的讀取一律忽略。本規則只在 compilation 中存在
`TMPro.TMP_Text` 時才會註冊,因此未使用 TextMeshPro 的專案不會有任何成本。

## 如何修正

修正前:

```csharp
void Update()
{
    _scoreLabel.text = _score.ToString();
}
```

修正後:

```csharp
void Update()
{
    _scoreLabel.SetText("{0}", _score);
}
```

更好的做法是只在數值真正改變時才更新 label,而不是每幀更新。

## 何時抑制

當指派已有防護、只在值變更時才執行,或文字確實是 `SetText` 格式化無法套用的動態
非數值內容時,可以抑制。

## 如何設定或抑制

- 啟用本規則(預設為關閉):在 `.editorconfig` 設定 `dotnet_diagnostic.UPA0012.severity = warning`
- 單一呼叫位置:以 `#pragma warning disable UPA0012` / `#pragma warning restore UPA0012` 包住
- 整個專案:設定 `dotnet_diagnostic.UPA0012.severity = none`
- 熱路徑判定:調整下方的 `upa_hot_path_*` 選項

## 可設定項

熱路徑判定為共用設定,可透過 `.editorconfig` 調整:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerformanceCritical
upa_hot_path_include_lambdas = true
```
