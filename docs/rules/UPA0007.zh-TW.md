# UPA0007 — Capturing lambda in per-frame method

> [English](UPA0007.md) | 繁體中文

| | |
|---|---|
| 類別 | 效能 |
| 預設嚴重度 | 警告(Warning) |
| 預設啟用 | 是 |

## 成因

捕捉集合非空的 lambda 或匿名方法——它參考了外圍範圍的區域變數、參數或 `this`——
出現在每幀熱路徑上:`MonoBehaviour` 衍生型別上的熱門 Unity 訊息
(如 `Update`、`FixedUpdate`、`LateUpdate`),或標記了熱路徑屬性的方法。

## 規則說明

捕捉式 lambda 在外圍程式碼每次執行時,都必須配置一個保存被捕捉狀態的閉包物件,
外加一個指向它的新委派。在每幀路徑上,這就是每幀的垃圾。

**完全不捕捉**任何東西的 lambda 會被編譯成快取的 static 委派——
只在第一次使用時配置一次,之後不再配置——因此無捕捉的 lambda 不會被回報。

注意,在 lambda 內呼叫任何實例方法或觸碰任何欄位都會捕捉 `this`,
這就足以觸發本規則。這使得本規則在真實程式碼中經常觸發;這是刻意的——
隱含的 `this` 捕捉是每幀委派配置最大的來源,
而修正方式(把委派快取到欄位)是機械化的。

回報位置放在 lambda 運算式本身:那裡才是配置發生的地方,
與 `upa_hot_path_include_lambdas` 設定無關(該設定管的是 lambda 主體*內部*的程式碼,
不是 lambda 自身的建立)。

## 如何修正

把委派快取到欄位,或重構以避免捕捉。

修正前:

```csharp
void Update()
{
    _button.Schedule(() => Refresh());
}
```

修正後:

```csharp
Action _refresh;

void Awake()
{
    _refresh = Refresh;
}

void Update()
{
    _button.Schedule(_refresh);
}
```

## 何時抑制

當 lambda 位於熱方法的冷分支上,或接收端 API 依設計就要求每次呼叫提供新委派時,
可以抑制此警告。

## 如何設定或抑制

- 單一呼叫點:以 `#pragma warning disable UPA0007` / `#pragma warning restore UPA0007` 包住
- 整個專案:在 `.editorconfig` 設定 `dotnet_diagnostic.UPA0007.severity = suggestion`(或 `none`)
- 依路徑:隨附的 preset 已放寬 `[**/Editor/**/*.cs]` 下的規則;可為工具程式碼或產生的程式碼加入類似區段
- 熱路徑判定:調整下方的 `upa_hot_path_*` 選項

## 可設定項

熱路徑判定是共用的,可透過 `.editorconfig` 設定:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerformanceCritical
upa_hot_path_include_lambdas = true
```
