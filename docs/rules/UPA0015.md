# UPA0015 — Camera.main accessed in per-frame method

> English | [繁體中文](UPA0015.zh-TW.md)

| | |
|---|---|
| Category | Performance |
| Default severity | Info |
| Enabled by default | Yes |

## Cause

The `UnityEngine.Camera.main` property is read inside a per-frame hot path: a hot Unity
message such as `Update`, `FixedUpdate`, or `LateUpdate` on a `MonoBehaviour`-derived
type, or a method marked with a hot-path attribute such as `[HotPath]`.

The diagnostic message is:

> 'Camera.main' performs a lookup comparable to GetComponent on every access. Cache the camera in a field during Awake or Start.

## Rule description

`Camera.main` returns the first enabled camera tagged `MainCamera`. Every access performs
a lookup: Unity's documentation states that "accessing this property has a small CPU
overhead, comparable to calling `GameObject.GetComponent`", and recommends that "where
CPU performance is important, consider caching this property"
([Unity Scripting API, Camera.main](https://docs.unity3d.com/ScriptReference/Camera-main.html)).

Unity 2020.2 and later cache the main-camera lookup internally — the same documentation
page notes that "internally, Unity caches all GameObjects with the MainCamera tag" and
returns the first valid result from that cache. The residual per-access cost is therefore
small, which is why this rule reports at **Info** severity rather than Warning: it points
at an easy micro-optimization, not a serious problem. On Unity versions before 2020.2 the
access is a full tag search and the advice carries more weight.

Only the body of the hot-path method itself (including its lambdas and local functions) is
analyzed. Accesses inside helper methods invoked from a hot path are deliberately not
reported — this analyzer prefers missed reports over false positives.

## How to fix violations

Cache the camera in a field during `Awake` or `Start`, and use the field on the hot path.

Before:

```csharp
public class Billboard : MonoBehaviour
{
    void LateUpdate()
    {
        transform.rotation = Camera.main.transform.rotation;
    }
}
```

After:

```csharp
public class Billboard : MonoBehaviour
{
    Camera _mainCamera;

    void Awake()
    {
        _mainCamera = Camera.main;
    }

    void LateUpdate()
    {
        transform.rotation = _mainCamera.transform.rotation;
    }
}
```

If the main camera can change at runtime (camera switching, scene loads), refresh the
cached field at the switch point instead of re-reading `Camera.main` every frame.

## When to suppress warnings

Suppress when the main camera changes at runtime and no convenient refresh point exists —
re-reading `Camera.main` is then the simpler and, on Unity 2020.2+, reasonably cheap
option. Projects that consider the residual cached-lookup cost acceptable can also lower
the rule to `none` project-wide.

## How to configure or suppress

- Single call site: wrap it in `#pragma warning disable UPA0015` / `#pragma warning restore UPA0015`
- Whole project: set `<Rule Id="UPA0015" Action="None" />` in `Assets/Default.ruleset` (or raise it to `Warning` where the team wants it enforced)
- By assembly: place a custom `Default.ruleset` in that asmdef folder and set this rule to `None`; it overrides the project-wide ruleset for that assembly
- Hot-path classification: adjust the `upa_hot_path_*` options below

## Configuration

The hot-path classification is shared and set in the universal options file `Assets/Rules.UnityPerformanceAnalyzers.additionalfile` (the same `key = value` lines also work in an `.editorconfig` passed to `upa-cli --editorconfig`):

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerformanceCritical
upa_hot_path_include_lambdas = true
```
