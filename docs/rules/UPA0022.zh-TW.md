# UPA0022 — Enum.HasFlag in per-frame method(已廢止)

> [English](UPA0022.md) | 繁體中文

| | |
|---|---|
| 類別 | Performance |
| 預設嚴重度 | Warning |
| 預設啟用 | 否 |

## 狀態

**已廢止。除非專案自行開啟,否則不回報任何東西;隨套件出貨的每一份 preset 都設為 `none`。**
編號保留,因為規則編號永不回收。

## 廢止的原因

本規則主張 `HasFlag` 會裝箱接收者與引數,依據是「.NET 5+ 移除該裝箱的 JIT intrinsic
不適用 Unity 的 Mono」。關於 .NET 的那個前提是正確的,**但由它推出的結論不成立**:
Mono 自 4.0、IL2CPP 自 Unity 2021.2 起,各自對同型別呼叫做了特例處理,把它換成位元 AND。

四個支援組合實測,20 萬次迭代、三次重跑,散布小於 0.05 ns:

| 執行環境 | `x.HasFlag(y)` 配置 | `x.HasFlag(y)` | `(x & y) == y` |
|---|---|---|---|
| Unity 2022.3, Mono | 無 | 5.20 ns | 5.38 ns |
| Unity 6, Mono | 無 | 5.55 ns | 5.02 ns |
| Unity 2022.3, IL2CPP | 無 | 1.20 ns | 1.58 ns |
| Unity 6, IL2CPP | 無 | 1.18 ns | 1.59 ns |

沒有任何一處配置,而在 IL2CPP——實際出貨的遊戲所執行的後端——上,**這個呼叫比本規則
原本提供的修正寫法更快**。CodeFix 因此一併移除:它讓程式碼變長、變難讀,而且更慢。

## 還有成本的部分

`HasFlag` 的參數型別是 `System.Enum`,所以傳入 enum 值在 IL 層會裝箱引數。只要引數是
**單純的載入**,該裝箱就與呼叫一起被消除;載入與呼叫之間夾了分支才會留下來:

```csharp
flags.HasFlag(Rights.Read)          // 無配置(常數)
flags.HasFlag(flag)                 // 無配置(區域變數、參數、欄位、屬性)
flags.HasFlag(cond ? A : B)         // 會配置
```

兩個支援版本的 IL2CPP 實測,且同一個迴圈裡的對照組確實會配置——所以那些 0 是消除,
不是被提升出量測範圍的 box。

**Mono 消除得比較少**:那裡只有常數那一種是零,區域變數、欄位、屬性引數在 Unity 2022.3 上
每次配置 0.8 B、在 Unity 6 上 2.4 B。UPA0006 依 IL2CPP 的結果,對這些一律不報。

最後一種由 [UPA0006](UPA0006.zh-TW.md) 回報,報在裝箱轉換實際發生之處;前兩種它不再回報。

## 想要它回來

明確指定嚴重度即可恢復原本行為:

```ini
dotnet_diagnostic.UPA0022.severity = warning
```

Unity build 的嚴重度必須來自 ruleset 而非 `.editorconfig`,請參考隨套件出貨的 preset。
