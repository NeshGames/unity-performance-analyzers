# UPA0020 — Lambda in WaitUntil / WaitWhile construction

> English | [繁體中文](UPA0020.zh-TW.md)

| | |
|---|---|
| Category | Performance |
| Default severity | Warning |
| Enabled by default | No |

## Cause

A `new WaitUntil(...)` or `new WaitWhile(...)` whose predicate argument is a lambda or
anonymous method:

```csharp
yield return new WaitUntil(() => _ready);
```

Method-group arguments (`new WaitUntil(IsReady)`) are not reported. The rule is not
limited to per-frame hot paths — a coroutine that loops over such a construction
re-allocates on every iteration regardless of where it was started.

## Rule description

Each construction allocates the yield instruction, the delegate, and any captured
closure. Unity's coroutine guidance recommends the cached alternative directly: "Cache
commonly reused ones and avoid lambdas in `WaitUntil` and `WaitWhile` to prevent delegate
and capture allocations" —
[Unity Manual, Write and run coroutines](https://docs.unity3d.com/6000.5/Documentation/Manual/Coroutines.html).

The rule performs no flow analysis, so a construction that provably runs once — a field
initializer, or a one-time setup in `Awake` — still reports. That trade-off keeps the
rule simple and predictable, and it is why the rule ships **disabled by default**: the
`strict` preset enables it as `Warning` and the `cysharp-stack` preset as `Error`.

The diagnostic message reads: "Constructing this {0} with a lambda allocates the delegate
(and any closure) each time this code runs. Cache the yield instruction and its predicate
in fields."

## How to fix violations

Cache the yield instruction and its predicate in fields; a method group keeps the
predicate lambda-free.

Before:

```csharp
IEnumerator WaitForReady()
{
    yield return new WaitUntil(() => _ready);
}
```

After:

```csharp
WaitUntil _waitReady;

void Awake()
{
    _waitReady = new WaitUntil(IsReady);
}

bool IsReady() => _ready;

IEnumerator WaitForReady()
{
    yield return _waitReady;
}
```

The cached instruction is constructed once, and every coroutine that yields it reuses the
same instance.

## When to suppress warnings

Suppress when the construction provably runs once — a field initializer or one-time setup
path. The rule reports there anyway because it performs no flow analysis; a local
`#pragma` documents the intent. If the predicate captures nothing, caching it as shown
above is usually just as easy as suppressing.

## How to configure or suppress

- Enable the rule (it is off by default): set UPA0020 to `Warning` in your ruleset (the `strict` preset does this; `cysharp-stack` raises it to `Error`), or set `dotnet_diagnostic.UPA0020.severity = warning` in `.editorconfig`
- Single call site: wrap it in `#pragma warning disable UPA0020` / `#pragma warning restore UPA0020`
- Whole project: set UPA0020 to `None`

## Configuration

None.
