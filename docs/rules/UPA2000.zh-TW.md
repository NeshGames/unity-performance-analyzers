# UPA2000 — String concatenation in per-frame method

> [English](UPA2000.md) | 繁體中文

| | |
|---|---|
| 類別 | Ecosystem |
| 預設嚴重度 | Warning |
| 預設啟用 | 否 |

## 成因

在每幀熱路徑內建構字串:結果為字串的 `+` 串接、`+=` 附加,或字串插值(`$"..."`)。

## 規則說明

.NET 中的每個字串都是不可變的,因此串接、附加與插值在每次執行時都會配置一個新字串。
在 Unity 每幀執行的方法裡——分數顯示、計時器、除錯 overlay——這會每幀產生垃圾,
與 UPA0006 所回報的配置一樣,持續餵養非分代式的 GC。

訊息中的建議會依專案調整(規則本身一律執行):

- **未引用 ZString**:快取不會變動的字串,或在熱路徑之外用可重複使用的
  `StringBuilder` 建構會變動的字串。
- **已引用 ZString**:使用 ZString 進行格式化,避免中介字串配置。

刻意劃定的範圍邊界:

- **編譯期常數折疊不回報**——`"a" + "b"` 與 `const` 的組合會被編譯器折疊,
  在執行期不產生任何配置。
- **`string.Format` / `string.Concat` / `string.Join` 呼叫**不在 v0.1 的範圍內。
- 鏈式串接(`"a: " + a + b`)只回報一次,位置在整個運算式上。
- **實值型別運算元的 boxing**(`"x" + n` 對 `n` 的 boxing)由 UPA0006 另行回報。
  重複回報是刻意的:它們是兩筆不同的配置,而 ZString 式的改寫可以一次移除兩者。

本規則**預設停用**(生態相依區塊政策):是否在熱路徑上禁止建構字串,屬於 codebase
紀律的選擇。由各 preset 啟用。

## 如何修正

修正前:

```csharp
void Update()
{
    scoreLabel.text = "score: " + score;
}
```

修正後(快取並只在變更時重建):

```csharp
void OnScoreChanged(int score)
{
    scoreLabel.SetText("score: {0}", score);   // TMP_Text.SetText formats without garbage
}
```

或使用 ZString:

```csharp
using Cysharp.Text;

void OnScoreChanged(int score)
{
    scoreLabel.text = ZString.Concat("score: ", score);
}
```

最好的修正往往是把字串建構完全移出每幀路徑——只在底層數值變更時才重建文字。

## 何時抑制

在熱方法內的冷分支(罕見的狀態轉換、僅限除錯的路徑)上,若可證明字串建構極少發生,
可以抑制。

## 如何設定或抑制

- 啟用本規則(預設為關閉):在 `.editorconfig` 設定 `dotnet_diagnostic.UPA2000.severity = warning`
- 單一呼叫位置:以 `#pragma warning disable UPA2000` / `#pragma warning restore UPA2000` 包住
- 整個專案:設定 `dotnet_diagnostic.UPA2000.severity = none`
- 熱路徑判定:調整共用的 `upa_hot_path_*` 選項(見 UPA0006)

## 可設定項

熱路徑判定為共用設定,可透過 `.editorconfig` 調整:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate
upa_hot_path_attributes = HotPath,PerformanceCritical
upa_hot_path_include_lambdas = true
```
