# UPA0018 — 逐幀方法內使用會配置陣列的 Unity API

> [English](UPA0018.md) | 繁體中文

| | |
|---|---|
| 類別 | Performance |
| 預設嚴重度 | Warning |
| 預設啟用 | 是 |

## 成因

在逐幀熱路徑內讀取了下列 Unity 屬性之一。所謂逐幀熱路徑,是指
`MonoBehaviour` 衍生型別上的熱門 Unity 訊息(如 `Update`、`FixedUpdate`、`LateUpdate`),
或標記了熱路徑屬性(如 `[HotPath]`)的方法。

| 屬性 | 不配置的替代方案 |
|---|---|
| `Input.touches` | `Input.touchCount` 搭配 `Input.GetTouch(i)` |
| `Animator.parameters` | `Animator.parameterCount` 搭配 `Animator.GetParameter(i)` |
| `Renderer.sharedMaterials` | `Renderer.GetSharedMaterials(List<Material>)` |
| `Camera.allCameras` | `Camera.GetAllCameras(Camera[])` |

只有讀取會被回報。對可寫入的項目賦值(例如
`renderer.sharedMaterials = array`)不會配置,也不會被回報。

## 規則說明

Unity 的垃圾回收指引說得很明確:「All Unity APIs that return arrays create a new copy
of the array each time they're accessed」——
[Unity Manual, Garbage collection best practices](https://docs.unity3d.com/2022.3/Documentation/Manual/performance-garbage-collection-best-practices.html)。
因此在逐幀路徑上讀取這類屬性會穩定產生垃圾,即使結果只被檢視一下就立刻丟棄。

本規則檢查的是一份封閉的黑名單,而不是試圖攔下所有回傳陣列的 API:
名單上的每個項目都有官方文件記載、可避免複製的對應方案——
或是改用索引存取([`Animator.parameterCount`](https://docs.unity3d.com/ScriptReference/Animator-parameterCount.html)
搭配 `GetParameter`),或是改為填入呼叫端提供的緩衝
([`Renderer.GetSharedMaterials`](https://docs.unity3d.com/ScriptReference/Renderer.GetSharedMaterials.html):
「if you ... want to avoid allocating a new array with every access」;
[`Camera.GetAllCameras`](https://docs.unity3d.com/ScriptReference/Camera.GetAllCameras.html):
「without allocating a new array」)。診斷訊息會直接指名該項目的替代方案。

幾個知名的回傳陣列 API 刻意不收進來,因為已有其他規則負責——見相關規則。

## 修正方式

改用訊息中指名的對應方案。索引存取的寫法:

修正前:

```csharp
void Update()
{
    foreach (var touch in Input.touches)
    {
        Handle(touch);
    }
}
```

修正後:

```csharp
void Update()
{
    for (var i = 0; i < Input.touchCount; i++)
    {
        Handle(Input.GetTouch(i));
    }
}
```

`Renderer.GetSharedMaterials(List<Material>)` 與 `Camera.GetAllCameras(Camera[])`
則應傳入快取在欄位中的 list 或陣列,讓緩衝跨幀重複使用。注意
`GetAllCameras` 在傳入的陣列小於 `Camera.allCamerasCount` 時會擲出例外。

## 何時可以抑制

熱方法內可證明極少執行的冷分支(罕見狀態轉換、僅供除錯的路徑),
或不在意逐幀配置壓力的編輯器工具程式碼,可以就地抑制。

## 設定與抑制方式

- 單一呼叫位置:以 `#pragma warning disable UPA0018` / `#pragma warning restore UPA0018` 包住
- 整個專案:在 `.editorconfig` 設定 `dotnet_diagnostic.UPA0018.severity = suggestion`(或 `none`)
- 依路徑:隨附的 preset 已放寬 `[**/Editor/**/*.cs]` 下的規則;可為工具程式碼或產生的程式碼加入類似區段
- 熱路徑判定:調整下方的 `upa_hot_path_*` 選項

## 可設定項

熱路徑判定是共用的,可透過 `.editorconfig` 設定:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerfCritical
upa_hot_path_include_lambdas = true
```
