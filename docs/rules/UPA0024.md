# UPA0024 — Resources.Load in per-frame method

> English | [繁體中文](UPA0024.zh-TW.md)

| | |
|---|---|
| Category | Performance |
| Default severity | Warning |
| Enabled by default | No |

## Cause

A call to `UnityEngine.Resources.Load`, `Resources.LoadAll`, or `Resources.LoadAsync` —
any overload, generic or non-generic — inside a per-frame hot path: a hot Unity message
such as `Update`, `FixedUpdate`, or `LateUpdate` on a `MonoBehaviour`-derived type, or a
method marked with a hot-path attribute such as `[HotPath]`.

## Rule description

Every call performs an asset lookup and load through the Resources system; `LoadAsync`
still does per-call work to locate the asset and start the request. The result for a
given path does not change from frame to frame, so repeating the call every frame repeats
that work for nothing.

Unity's asset-management guidance goes further than this rule: it treats not using the
Resources system at all as the best practice ("Don't use it"), with narrow exceptions
such as rapid prototyping —
[Assets, Resources and AssetBundles, Unity Learn](https://learn.unity.com/tutorial/assets-resources-and-assetbundles).
That guidance concerns the Resources system as a whole; restricting this rule to
per-frame hot paths is this analyzer's own narrower scope, aimed at the most costly usage
pattern in projects that do use Resources folders.

The rule is disabled by default: projects that follow the general guidance and avoid
Resources folders have nothing for it to find. Enable it in projects that still load
through Resources.

Only the body of the hot-path method itself (including its lambdas and local functions) is
analyzed. Calls inside helper methods invoked from a hot path are deliberately not reported
— this analyzer prefers missed reports over false positives.

## How to fix violations

Load the asset once outside the hot path — in `Awake`, `Start`, or a dedicated loading
phase — cache the reference in a field, and use the field on the hot path.

Before:

```csharp
public class SparkSpawner : MonoBehaviour
{
    void Update()
    {
        var prefab = Resources.Load<GameObject>("Effects/Spark");
        Instantiate(prefab, transform.position, Quaternion.identity);
    }
}
```

After:

```csharp
public class SparkSpawner : MonoBehaviour
{
    GameObject _sparkPrefab;

    void Awake()
    {
        _sparkPrefab = Resources.Load<GameObject>("Effects/Spark");
    }

    void Update()
    {
        Instantiate(_sparkPrefab, transform.position, Quaternion.identity);
    }
}
```

## When to suppress warnings

Suppress on cold branches inside hot methods (rare state transitions, debug-only paths)
where the call provably runs infrequently.

## How to configure or suppress

- Enable the rule (it is off by default): set UPA0024 to `Warning` in your ruleset
- Single call site: wrap it in `#pragma warning disable UPA0024` / `#pragma warning restore UPA0024`
- Hot-path classification: adjust the `upa_hot_path_*` options below
- Whole project: set UPA0024 to `None`

## Configuration

The hot-path classification is shared and configurable via `.editorconfig`:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerformanceCritical
upa_hot_path_include_lambdas = true
```
