# UPA0023 — OnGUI declared in player code

> English | [繁體中文](UPA0023.zh-TW.md)

| | |
|---|---|
| Category | Performance |
| Default severity | Info |
| Enabled by default | No |

## Cause

An `OnGUI` method — instance, `void`-returning, parameterless — declared on a
`MonoBehaviour`-derived type in a player assembly.

Editor assemblies are skipped by assembly name: `Assembly-CSharp-Editor`, or any assembly
whose name ends in `.Editor` (case-insensitive).

## Rule description

`OnGUI` drives IMGUI, Unity's immediate-mode GUI system. Unity invokes it every frame,
and typically more than once per frame — separate passes for layout and repaint, plus one
call per input event. Unity's manual states that IMGUI "is not generally intended to be
used for normal in-game user interfaces"; its listed uses are in-game debugging displays,
custom inspectors, and editor tooling —
[IMGUI (Immediate Mode GUI), Unity Manual](https://docs.unity3d.com/Manual/GUIScriptingGuide.html).

Declaring the method is enough for Unity to start invoking it, so the rule reports the
declaration itself rather than any particular call inside it.

The rule is Info severity and disabled by default: development-time overlays are a
legitimate and common use of IMGUI, so a stray `OnGUI` is a prompt to double-check intent
rather than a defect. Enable it in projects that want player-facing UI kept out of IMGUI
by policy.

Editor detection is name-based. An editor assembly with an unconventional name — one that
is not `Assembly-CSharp-Editor` and does not end in `.Editor` — is treated as player code
and will be reported; suppress locally in that case, or rename the assembly to match the
convention.

## How to fix violations

Build player-facing UI with UI Toolkit or uGUI. Keep debug overlays, but gate them behind
a define so the declaration disappears from release players:

```csharp
public class StatsOverlay : MonoBehaviour
{
#if ENABLE_DEBUG_OVERLAY
    void OnGUI()
    {
        GUILayout.Label(_frameStats);
    }
#endif
}
```

Move editor tooling (custom inspectors, editor windows) into an editor assembly, where
the rule does not run.

## When to suppress warnings

- Debug or cheat overlays that are intentionally kept in development players.
- `OnGUI` declarations in editor tooling that lives in an assembly with an
  unconventional name (see above).

## How to configure or suppress

- Enable the rule (it is off by default): set UPA0023 to `Info` or higher in your ruleset
- Single declaration: wrap it in `#pragma warning disable UPA0023` / `#pragma warning restore UPA0023`
- Whole project: set UPA0023 to `None`

## Configuration

None. Editor assemblies are identified by assembly name, not by a configurable option.

## Related rules

- UPA0025 uses the same name-based editor-assembly detection and, like this rule, reports
