# UPA3004 — 阻塞等待非同步作業

> [English](UPA3004.md) | 繁體中文

| | |
|---|---|
| 類別 | Platform |
| 預設嚴重度 | Warning |
| 預設啟用 | 否 |
| 生效條件 | 編譯定義了 `UPA_TARGET_WEBGL` |

## 成因

在定義了 `UPA_TARGET_WEBGL` 的編譯中,以阻塞方式等待非同步作業:

- `AsyncOperationHandle.WaitForCompletion()` / `AsyncOperationHandle<TObject>.WaitForCompletion()`
  (Addressables;只在專案引用該套件時檢查)
- `Task.Wait()`、`Task.WaitAll(...)`、`Task.WaitAny(...)`
- `Task<TResult>.Result`
- `Task`/`ValueTask` awaiter 家族上的 `GetAwaiter().GetResult()`,
  含 `ConfigureAwait(...)` 變體

## 規則說明

Unity WebGL 播放器在單一執行緒上運行。主執行緒一旦阻塞等待非同步作業,
負責完成該作業的 continuation 就永遠沒有機會執行——這不是變慢,而是死鎖,
應用程式直接凍結。

這些寫法在桌面平台常常「看起來能動」,因為有執行緒池在背景完成作業;
正因如此它是移植陷阱:程式碼照常出貨,只有 WebGL 版本會卡死。
UPA3000 回報「建立執行緒」的 API;本規則回報互補的另一種錯誤——
同步等待非同步結果。

本規則只在定義 `UPA_TARGET_WEBGL` 時執行,預設關閉——
透過 `webgl-addon` preset 啟用。

## 修正方式

改為 await,不要阻塞:

```csharp
// 錯誤:WebGL 播放器直接凍結。
var sprite = handle.WaitForCompletion();
var data = LoadAsync().Result;

// 正確:主執行緒持續運轉,作業才有機會完成。
var sprite = await handle.Task;
var data = await LoadAsync();
```

在 coroutine 中改為以 `IsDone`/`IsCompleted` 逐幀 yield,而非阻塞。

## 何時可以抑制

- 存取點可證明 task 已完成(例如已用 `task.IsCompleted` 防護)。
  本規則不做流程分析,這種安全寫法仍會回報——請就地抑制。
- 已被 `#if !UNITY_WEBGL` 平台 define 隔離的程式碼路徑。

## 設定與抑制方式

- 啟用規則(預設關閉):在 `.editorconfig` 設 `dotnet_diagnostic.UPA3004.severity = warning`(`webgl-addon` preset 已包含)
- 單一位置:`#pragma warning disable UPA3004` / `#pragma warning restore UPA3004`
- 整個專案:設 `dotnet_diagnostic.UPA3004.severity = none`

## 可設定項

除 `UPA_TARGET_WEBGL` define 外無其他設定。

## 相關規則

- UPA3000(執行緒)——WebGL 上建立執行緒;本規則涵蓋的是阻塞等待非同步結果。
- UPA3001(sockets)、UPA3002(同步檔案 IO)、UPA3003(process)——同一個 WebGL
  規則群,共用同一個 define。
