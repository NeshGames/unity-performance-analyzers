# UPA2001 — System.Linq usage in per-frame method

> [English](UPA2001.md) | 繁體中文

| | |
|---|---|
| 類別 | Ecosystem |
| 預設嚴重度 | Warning |
| 預設啟用 | 否 |

## 成因

**在逐幀熱路徑內**呼叫了宣告在 `System.Linq.Enumerable` 或 `System.Linq.Queryable`
上的擴充方法——無論是方法語法或查詢語法(`from x in list select x`),
後者會編譯成相同的方法。

## 規則說明

LINQ operator 在每次求值時都會配置 enumerator 物件、delegate 實例,且經常還有中介
集合。在一般的 .NET 程式碼中,這種成本換取可讀性是划算的;但在 Unity 每幀執行的
方法裡,它是穩定產生的垃圾,而且在呼叫位置上完全看不出來。

本規則只檢查熱路徑(`Update`、`FixedUpdate` 與共用熱路徑判定涵蓋的其他方法)——
一次性與初始化用途的 LINQ 不受影響。它仍**預設停用**,由 `cysharp-stack` preset
啟用,因為即使只在熱路徑禁用 LINQ,也屬於程式碼庫的紀律選擇。

你自己型別上的同名擴充方法(自訂的 `Where`)會透過宣告型別比對排除。

## 如何修正

把 operator 鏈改寫為明確的迴圈:

```csharp
// Before
var active = units.Where(u => u.IsActive).ToList();

// After
var active = new List<Unit>();
for (var i = 0; i < units.Count; i++)
{
    if (units[i].IsActive)
    {
        active.Add(units[i]);
    }
}
```

並把結果 list 提出到方法之外重複使用(見 UPA0006)。

## 何時抑制

熱方法內可證明極少執行的冷分支(罕見狀態轉換、僅供除錯的路徑)可以就地抑制。

## 如何設定或抑制

- 啟用本規則(預設為關閉):在你的 ruleset 中把 UPA2001 設為 `Warning`
- 單一呼叫位置:以 `#pragma warning disable UPA2001` / `#pragma warning restore UPA2001` 包住
- 熱路徑判定:調整共用的 `upa_hot_path_*` 選項(僅 IDE 生效;見 UPA0006)
- 整個專案:把 UPA2001 設為 `None`

## 可設定項

熱路徑判定為共用設定,經 `.editorconfig` 調整(僅 IDE 生效):

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate
upa_hot_path_attributes = HotPath,PerfCritical
upa_hot_path_include_lambdas = true
```
