# UPA2032 — String tween ID

> English | [繁體中文](UPA2032.zh-TW.md)

| | |
|---|---|
| Category | Ecosystem |
| Default severity | Info |
| Enabled by default | No |
| Active only when | the assembly references DOTween |

## Cause

A `string` argument is passed to `SetId(...)`, or to one of the static `DOTween`
filtered operations: `Kill`, `Play`, `Pause`, `Restart`, `Rewind`, `Complete`, `Flip`,
`Goto`, `TogglePause`, `IsTweening`.

## Rule description

DOTween's static filtered operations act on the subset of active tweens matching an ID
or a target. Per the DOTween documentation, filtering by an `int` or `string` ID makes
these operations much faster, with `int` faster than `string`
([DOTween documentation](https://dotween.demigiant.com/documentation.php)). String IDs
are therefore the slowest of the fast filter options — and, as ordinary literals, they
carry no compile-time protection against typos.

This is an **Info**-severity rule: string IDs are a supported DOTween usage, and the
difference only matters where filtered operations run frequently.

Not reported:

- `int` IDs and object IDs.
- Filtering by target reference (`DOTween.Kill(transform)`, `transform.DOKill()`).
- The receiver of a reduced extension-method call — it is the tween or target, not an
  ID argument.

The rule **runs only when the assembly references DOTween** (both the free and the Pro
distribution ship an assembly with that name) and stays **disabled by default**
(ecosystem block policy); presets enable it.

## How to fix violations

```csharp
// Reported: string IDs are the slowest of the fast filter options.
tween.SetId("player-move");
DOTween.Kill("player-move");

// Preferred: int IDs.
const int PlayerMoveId = 1;
tween.SetId(PlayerMoveId);
DOTween.Kill(PlayerMoveId);

// Or filter by the target reference instead of an ID.
transform.DOKill();
```

## When to suppress warnings

Keep string IDs where readability or debugging convenience matters more than filter
speed, or where the filtered operations run rarely — scene teardown, one-off UI
transitions.

## How to configure or suppress

- Enable the rule (it is off by default): `dotnet_diagnostic.UPA2032.severity = suggestion` in `.editorconfig`
- Single call site: wrap it in `#pragma warning disable UPA2032` / `#pragma warning restore UPA2032`
- Whole project: set `dotnet_diagnostic.UPA2032.severity = none`

## Configuration

None.
