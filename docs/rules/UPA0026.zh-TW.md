# UPA0026 — Value type boxed by inherited method call

> [English](UPA0026.md) | 繁體中文

| | |
|---|---|
| 類別 | 效能 |
| 預設嚴重度 | 警告(Warning) |
| 預設啟用 | 是 |

## 成因

在每幀熱路徑內(`MonoBehaviour` 衍生型別上的熱門 Unity 訊息,如 `Update`、
`FixedUpdate`、`LateUpdate`,或標記了熱路徑屬性如 `[HotPath]` 的方法),
以 struct 或 enum 為接收者的呼叫解析到了繼承自 `System.Object`、
`System.ValueType` 或 `System.Enum` 的方法:

- 該值型別未覆寫的 `ToString()`、`GetHashCode()` 或 `Equals(object)`
- 無法被覆寫的 `GetType()`

## 規則說明

當值型別沒有提供自己的實作時,執行時期無法在未裝箱的值上分派這個呼叫。
CLR 的 constrained 呼叫規則寫得很清楚:若值型別「does not implement `method`
then `ptr` is dereferenced, boxed, and passed as the 'this' pointer」,
且這種情況只會發生在定義於 `Object`、`ValueType` 或 `Enum`
而未被該型別覆寫的方法上——
[OpCodes.Constrained,Microsoft Learn](https://learn.microsoft.com/en-us/dotnet/api/system.reflection.emit.opcodes.constrained)。
這個裝箱是每次呼叫一筆的堆積配置。現代 .NET 以 JIT 最佳化移除了其中一部分裝箱;
這些最佳化不適用於 Unity 的 Mono 執行時期,所以在 Unity 上這些呼叫會配置記憶體。

非 blittable 的 struct 還有第二層代價:繼承來的 `ValueType.Equals` 與
`GetHashCode` 會透過反射逐欄位比較與雜湊,計算成本很高——
[CA1815,Microsoft Learn](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca1815)。

會回報與不會回報的情況:

- 覆寫了該成員的型別會解析到自己的宣告,自然被排除——
  `intValue.ToString()` 繫結到 `Int32.ToString()`,不會回報。
- 經由 `IEquatable<T>` 的 `Equals(T)` 繫結到介面實作,不會回報。
- 接收者型別是泛型型別參數時不回報——constrained
  呼叫是否裝箱,取決於實例化時代入的型別。
- `GetType()` 對每個值型別接收者都會回報:它無法被覆寫、會把接收者裝箱,
  而且其結果在編譯期本來就已知。

只有熱路徑方法本身的主體(包含其中的 lambda 與區域函式)會被分析。
從熱路徑呼叫的輔助方法內部的呼叫刻意不回報——
本 analyzer 寧可漏報,也不誤報。

## 如何修正

修正方式依接收者而定:

- **Struct**:在 struct 上覆寫 `ToString`、`GetHashCode` 與 `Equals(object)`;
  相等比較另外實作 `IEquatable<T>`,並改用 `Equals(T)` 或 `==`。
- **Enum**:沒有可加的覆寫——把結果(顯示名稱、雜湊值)在熱路徑外
  快取或預先計算;enum 值的相等比較改用 `==`,不要用 `Equals(object)`。
- **`GetType()`**:結果在編譯期已知——改用 `typeof(TheType)`。

```csharp
// Before
void Update()
{
    _label.text = _state.ToString();          // enum: boxes the receiver each frame
    if (_slot.Equals(other)) { Consume(); }   // struct without overrides: boxes both sides
    var t = _cursor.GetType();                // struct: boxes; result is known statically
}

// After
static readonly Dictionary<UnitState, string> s_stateNames = BuildStateNames(); // filled once

void Update()
{
    _label.text = s_stateNames[_state];
    if (_slot == other) { Consume(); }        // ==/IEquatable<T> on the struct
    var t = typeof(Cursor);
}
```

## 何時抑制

熱方法內可證明極少執行的冷分支——罕見狀態轉換,
或記錄與錯誤處理路徑——可以就地抑制。

## 如何設定或抑制

- 單一呼叫點:以 `#pragma warning disable UPA0026` / `#pragma warning restore UPA0026` 包住
- 整個專案:在 `.editorconfig` 設定 `dotnet_diagnostic.UPA0026.severity = suggestion`(或 `none`)
- 依路徑:隨附的 preset 已放寬 `[**/Editor/**/*.cs]` 下的規則;可為工具程式碼或產生的程式碼加入類似區段
- 熱路徑判定:調整下方的 `upa_hot_path_*` 選項

## 可設定項

熱路徑判定是共用的,可透過 `.editorconfig` 設定:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerformanceCritical
upa_hot_path_include_lambdas = true
```

## 相關規則
