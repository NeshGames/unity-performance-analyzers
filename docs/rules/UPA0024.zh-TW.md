# UPA0024 — Resources.Load in per-frame method

> [English](UPA0024.md) | 繁體中文

| | |
|---|---|
| 類別 | 效能 |
| 預設嚴重度 | 警告(Warning) |
| 預設啟用 | 否 |

## 成因

在每幀熱路徑內呼叫了 `UnityEngine.Resources.Load`、`Resources.LoadAll` 或
`Resources.LoadAsync`——不論泛型或非泛型多載。所謂每幀熱路徑,是指
`MonoBehaviour` 衍生型別上的熱門 Unity 訊息(如 `Update`、`FixedUpdate`、`LateUpdate`),
或標記了熱路徑屬性(如 `[HotPath]`)的方法。

## 規則說明

每次呼叫都會經由 Resources 系統執行資產查找與載入;`LoadAsync`
同樣要在每次呼叫時定位資產並啟動請求。同一路徑的結果不會逐幀改變,
因此每幀重複呼叫等於白白重複這些工作。

Unity 的資產管理指引比本規則更進一步:它把完全不使用 Resources 系統
視為最佳實務(「Don't use it」),僅保留快速雛形開發等少數例外——
[Assets, Resources and AssetBundles,Unity Learn](https://learn.unity.com/tutorial/assets-resources-and-assetbundles)。
該指引針對的是 Resources 系統整體;把本規則限縮在每幀熱路徑,
是本 analyzer 自行選擇的較窄範圍,目的是在仍使用 Resources 資料夾的專案中
攔下代價最高的使用模式。

本規則預設停用:遵循上述一般指引、不使用 Resources 資料夾的專案沒有東西可回報。
仍透過 Resources 載入的專案可以啟用它。

只有熱路徑方法本身的主體(包含其中的 lambda 與區域函式)會被分析。
從熱路徑呼叫的輔助方法內部的呼叫刻意不回報——
本 analyzer 寧可漏報,也不誤報。

## 如何修正

在熱路徑之外載入資產一次——在 `Awake`、`Start` 或專門的載入階段——
把參考快取到欄位,並在熱路徑上使用該欄位。

修正前:

```csharp
public class SparkSpawner : MonoBehaviour
{
    void Update()
    {
        var prefab = Resources.Load<GameObject>("Effects/Spark");
        Instantiate(prefab, transform.position, Quaternion.identity);
    }
}
```

修正後:

```csharp
public class SparkSpawner : MonoBehaviour
{
    GameObject _sparkPrefab;

    void Awake()
    {
        _sparkPrefab = Resources.Load<GameObject>("Effects/Spark");
    }

    void Update()
    {
        Instantiate(_sparkPrefab, transform.position, Quaternion.identity);
    }
}
```

## 何時抑制

熱方法內可證明極少執行的冷分支(罕見狀態轉換、僅供除錯的路徑)可以就地抑制。

## 如何設定或抑制

- 啟用本規則(預設為關閉):在你的 ruleset 中把 UPA0024 設為 `Warning`
- 單一呼叫點:以 `#pragma warning disable UPA0024` / `#pragma warning restore UPA0024` 包住
- 熱路徑判定:調整下方的 `upa_hot_path_*` 選項
- 整個專案:把 UPA0024 設為 `None`

## 可設定項

熱路徑判定是共用的,可透過 `.editorconfig` 設定:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerformanceCritical
upa_hot_path_include_lambdas = true
```
