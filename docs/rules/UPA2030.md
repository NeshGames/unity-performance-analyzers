# UPA2030 — Tween created in per-frame method

> English | [繁體中文](UPA2030.zh-TW.md)

| | |
|---|---|
| Category | Ecosystem |
| Default severity | Warning |
| Enabled by default | No |
| Active only when | the assembly references DOTween |

## Cause

A tween-creating call executes inside a per-frame hot path: any call whose return type
derives from `DG.Tweening.Tween` — the shortcut extensions (`transform.DOMove(...)`),
`DOTween.To(...)`, `DOTween.Sequence()`, and the DOTween Pro / module extensions.

## Rule description

Every tween-creating call allocates a new tween object and registers it in DOTween's
active list. Doing this in a method Unity runs every frame produces steady garbage and
churns the active list — each frame adds a tween that makes the previous frame's copy
redundant.

DOTween's own API is built for reuse: with auto-kill disabled via `SetAutoKill(false)`,
a tween survives completion and can be driven again with `Restart`, or redirected with
`ChangeEndValue` / `ChangeValues`
([DOTween documentation](https://dotween.demigiant.com/documentation.php)).

Detection is by return type, not by method name, so the shortcut extensions,
`DOTween.To`, sequences, and Pro / module extensions are all covered uniformly.
Configuration calls whose receiver is itself a `Tween` (`SetLoops`, `SetEase`,
`SetAutoKill`, ...) are not reported — a fluent chain reports once, at its creation
root.

The rule **runs only when the assembly references DOTween** — both the free and the Pro
distribution ship an assembly with that name, and detection is by assembly name only.
It stays **disabled by default** (ecosystem block policy); presets enable it.

## How to fix violations

The structural fix is usually to start a tween on a state change instead of creating
one per frame.

Before:

```csharp
void Update()
{
    transform.DOMove(target.position, 0.5f);   // a new tween every frame
}
```

After (create once, reuse):

```csharp
Tweener _move;

void Awake()
{
    _move = transform.DOMove(transform.position, 0.5f)
        .SetAutoKill(false)
        .Pause();
}

void OnTargetChanged(Vector3 destination)
{
    _move.ChangeEndValue(destination, true).Restart();
}
```

## When to suppress warnings

Suppress on cold branches inside hot methods — for example a tween started from a rare
state transition whose handler happens to live in `Update`.

## How to configure or suppress

- Enable the rule (it is off by default): `dotnet_diagnostic.UPA2030.severity = warning` in `.editorconfig`
- Single call site: wrap it in `#pragma warning disable UPA2030` / `#pragma warning restore UPA2030`
- Whole project: set `dotnet_diagnostic.UPA2030.severity = none`
- Hot-path classification: adjust the shared `upa_hot_path_*` options (see UPA0006)

## Configuration

Hot-path classification is shared and configurable via `.editorconfig`:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate
upa_hot_path_attributes = HotPath,PerformanceCritical
upa_hot_path_include_lambdas = true
```
