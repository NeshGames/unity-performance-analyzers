# UPA0016 — SendMessage / BroadcastMessage call

> English | [繁體中文](UPA0016.zh-TW.md)

| | |
|---|---|
| Category | Performance |
| Default severity | Warning |
| Enabled by default | Yes |

## Cause

A call to `SendMessage`, `SendMessageUpwards`, or `BroadcastMessage` declared on
`UnityEngine.Component` or `UnityEngine.GameObject` — anywhere in the code. Unlike most
rules in this package, this one is **not limited to per-frame hot paths**: the cost and
the correctness hazard apply wherever the call sits.

The diagnostic message is:

> '{0}' uses reflection-based message dispatch, which is orders of magnitude slower than a direct call. Call the method directly, or use an interface or UnityEvent.

where `{0}` is the method name, for example `SendMessage`.

## Rule description

These APIs dispatch by method-name string using reflection: the receiver is located at
runtime by scanning components for a method with a matching name. Microsoft's Unity
performance guidance recommends eliminating them, noting that "these functions can be on
the order of 1000x slower than direct function calls"
([Microsoft Learn, Performance recommendations for Unity](https://learn.microsoft.com/en-us/windows/mixed-reality/develop/unity/performance-recommendations-for-unity)).
`BroadcastMessage` and `SendMessageUpwards` additionally walk the transform hierarchy,
multiplying the dispatch cost by the number of objects visited.

The performance cost is only half the problem. String-based dispatch also removes the
compiler from the loop: a renamed or misspelled target method compiles cleanly and fails
only at runtime, and IDE navigation and refactoring tools cannot see the call edge.
Because both concerns exist regardless of call frequency, the rule reports everywhere,
not just on hot paths.

## How to fix violations

Replace the string dispatch with a statically typed mechanism:

Before:

```csharp
void OnHit(GameObject target)
{
    target.SendMessage("ApplyDamage", 10f);
}
```

After — direct call through a component reference:

```csharp
void OnHit(GameObject target)
{
    if (target.TryGetComponent<Health>(out var health))
    {
        health.ApplyDamage(10f);
    }
}
```

When the caller should not depend on a concrete type, dispatch through an interface:

```csharp
public interface IDamageable
{
    void ApplyDamage(float amount);
}

void OnHit(GameObject target)
{
    if (target.TryGetComponent<IDamageable>(out var damageable))
    {
        damageable.ApplyDamage(10f);
    }
}
```

For designer-wired notifications, expose a `UnityEvent` and let the Inspector connect the
listeners.

## When to suppress warnings

Suppress when interoperating with a third-party or legacy component whose only entry
point is a message receiver, or in one-shot editor tooling where the dispatch cost is
irrelevant and the string coupling is contained.

## How to configure or suppress

- Single call site: wrap it in `#pragma warning disable UPA0016` / `#pragma warning restore UPA0016`
- Whole project: set `dotnet_diagnostic.UPA0016.severity = suggestion` (or `none`) in `.editorconfig`
- By path: the shipped presets relax rules under `[**/Editor/**/*.cs]`; add similar sections for tooling or generated code

## Configuration

None. This rule ignores the hot-path classification by design — it reports everywhere.
