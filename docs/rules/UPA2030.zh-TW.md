# UPA2030 — Tween created in per-frame method

> [English](UPA2030.md) | 繁體中文

| | |
|---|---|
| 類別 | Ecosystem |
| 預設嚴重度 | Warning |
| 預設啟用 | 否 |
| 生效條件 | assembly 引用了 DOTween |

## 成因

在每幀熱路徑內執行了建立 tween 的呼叫:任何回傳型別衍生自 `DG.Tweening.Tween`
的呼叫——shortcut 擴充方法(`transform.DOMove(...)`)、`DOTween.To(...)`、
`DOTween.Sequence()`,以及 DOTween Pro / module 的擴充方法。

## 規則說明

每次建立 tween 的呼叫都會配置一個新的 tween 物件,並將其註冊進 DOTween 的
active list。在 Unity 每幀執行的方法裡這麼做,會持續產生垃圾並攪動 active list——
每一幀新增的 tween 都讓上一幀的那份變成多餘。

DOTween 的 API 本身就是為重用而設計:以 `SetAutoKill(false)` 停用 auto-kill 後,
tween 在完成後仍會保留,可用 `Restart` 再次驅動,或用 `ChangeEndValue` /
`ChangeValues` 改變目標值
([DOTween 文件](https://dotween.demigiant.com/documentation.php))。

偵測依據是回傳型別而非方法名稱,因此 shortcut 擴充、`DOTween.To`、Sequence、
Pro / module 擴充都能一體涵蓋。接收者本身已是 `Tween` 的設定呼叫(`SetLoops`、
`SetEase`、`SetAutoKill` 等)不回報——一條 fluent 鏈只在其建立根節點回報一次。

本規則**只在 assembly 引用 DOTween 時執行**——免費版與 Pro 版都附帶同名的
assembly,且偵測只看 assembly 名稱。它同時仍**預設停用**(生態規則群的政策);
由 preset 啟用。

## 如何修正

結構上的修法通常是在狀態變化時啟動 tween,而不是每幀建立一個。

修正前:

```csharp
void Update()
{
    transform.DOMove(target.position, 0.5f);   // 每幀建立一個新 tween
}
```

修正後(建立一次,重複使用):

```csharp
Tweener _move;

void Awake()
{
    _move = transform.DOMove(transform.position, 0.5f)
        .SetAutoKill(false)
        .Pause();
}

void OnTargetChanged(Vector3 destination)
{
    _move.ChangeEndValue(destination, true).Restart();
}
```

## 何時抑制

對熱方法內的冷分支可予以抑制——例如由罕見狀態轉換啟動的 tween,
只是其處理程式碼恰好位於 `Update` 內。

## 如何設定或抑制

- 啟用本規則(預設關閉):在 `.editorconfig` 設定 `dotnet_diagnostic.UPA2030.severity = warning`
- 單一呼叫點:以 `#pragma warning disable UPA2030` / `#pragma warning restore UPA2030` 包住
- 整個專案:設定 `dotnet_diagnostic.UPA2030.severity = none`
- 熱路徑判定:調整共用的 `upa_hot_path_*` 選項(見 UPA0006)

## 可設定項

熱路徑判定是共用的,可透過 `.editorconfig` 設定:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate
upa_hot_path_attributes = HotPath,PerfCritical
upa_hot_path_include_lambdas = true
```

## 相關規則
