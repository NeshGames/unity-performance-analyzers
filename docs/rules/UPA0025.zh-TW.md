# UPA0025 — Finalizer declared in runtime code

> [English](UPA0025.md) | 繁體中文

| | |
|---|---|
| 類別 | 效能 |
| 預設嚴重度 | 警告(Warning) |
| 預設啟用 | 是 |

## 成因

在 player 組件中的任何型別上宣告了 finalizer(解構子,`~TypeName()`)。

編輯器組件依組件名稱跳過:`Assembly-CSharp-Editor`,
或名稱以 `.Editor` 結尾的任何組件(不分大小寫)。

## 規則說明

Unity 的程式設計最佳實務對此說得很直接:「Don't use C# finalizers in
runtime code」——
[Programming best practices,Unity 6 手冊](https://docs.unity3d.com/6000.5/Documentation/Manual/programming-best-practices.html)。

其代價是結構性的,而非按呼叫次數計:

- 可終結(finalizable)物件在記憶體被回收前,至少要多撐過一次垃圾回收週期,
  因此宣告 finalizer 會讓該型別的每個實例都延後回收。
- Finalizer 在專用的 finalizer 執行緒上執行,時機不受你控制,
  物件之間也沒有順序保證。
- 額外的簿記工作讓回收停頓更難預測。

確定性的清理應放在 `IDisposable.Dispose`,由遊戲程式碼在自己選擇的時機呼叫。

本規則回報的是宣告本身;空的 finalizer 與有內容的 finalizer
在垃圾回收上的代價相同。

編輯器組件的判定以名稱為準。若編輯器組件的名稱不合慣例——
既不是 `Assembly-CSharp-Editor`,也不以 `.Editor` 結尾——會被視為 player 程式碼而被回報;
此時請就地抑制,或把組件改名以符合慣例。

## 如何修正

實作 `IDisposable`,把清理移入 `Dispose`,並移除 finalizer。

修正前:

```csharp
public class NativeBufferOwner
{
    IntPtr _buffer = Allocate();

    ~NativeBufferOwner()
    {
        Free(_buffer);
    }
}
```

修正後:

```csharp
public sealed class NativeBufferOwner : IDisposable
{
    IntPtr _buffer = Allocate();

    public void Dispose()
    {
        if (_buffer != IntPtr.Zero)
        {
            Free(_buffer);
            _buffer = IntPtr.Zero;
        }
    }
}
```

作業系統 handle 請改繼承 `System.Runtime.InteropServices.SafeHandle`,
不要手寫 finalizer——它提供最後防線的釋放路徑,
而不必在你自己的型別上加 finalizer。

## 何時抑制

- 直接持有非受控資源、且刻意保留 finalizer 作為漏呼叫 `Dispose`
  時的安全網的型別;適用時優先改用 `SafeHandle`,不適用時再抑制。
- 位於名稱不合慣例的組件中的編輯器工具 finalizer(見上文)。

## 如何設定或抑制

- 單一宣告:以 `#pragma warning disable UPA0025` / `#pragma warning restore UPA0025` 包住
- 整個專案:在 `.editorconfig` 設定 `dotnet_diagnostic.UPA0025.severity = suggestion`(或 `none`)
- 依路徑:隨附的 preset 已放寬 `[**/Editor/**/*.cs]` 下的規則;可為工具程式碼或產生的程式碼加入類似區段

## 可設定項

無。編輯器組件以組件名稱判定,不提供可設定選項。

## 相關規則

- UPA0023 使用相同的名稱式編輯器組件判定,且與本規則一樣回報宣告而非呼叫點。
- `CA1821`(.NET 程式碼品質規則)標記主體為空或無作用的 finalizer;
  本規則則不論主體內容,回報 Unity 執行期程式碼中的 finalizer。
