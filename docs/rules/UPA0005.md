# UPA0005 — Direct UnityEngine.Debug logging call

> English | [繁體中文](UPA0005.zh-TW.md)

| | |
|---|---|
| Category | Performance |
| Default severity | Warning |
| Enabled by default | No |

## Cause

A `UnityEngine.Debug` logging method (`Log`, `LogWarning`, `LogError`, `LogFormat`,
`LogWarningFormat`, `LogErrorFormat`, `LogException`, `LogAssertion`,
`LogAssertionFormat`) is called directly instead of through a wrapper marked with
`[System.Diagnostics.Conditional]`.

## Rule description

Direct `Debug.Log` calls remain in release builds, and their argument expressions —
string concatenation, interpolation, boxing of values — are evaluated and allocated on
every call even when the log output itself is stripped or ignored. When logging goes
through a wrapper method marked with `[Conditional("SYMBOL")]`, the compiler removes the
whole call **including its argument expressions** from builds where the symbol is not
defined, so release builds pay nothing.

`Debug.Assert` / `Debug.AssertFormat` are not reported: Unity already marks them
`[Conditional("UNITY_ASSERTIONS")]`. Calls inside a method that itself carries a
`[Conditional]` attribute are not reported either — that method *is* the wrapper.

This rule is **disabled by default**: it only makes sense once the project has a wrapper
class, otherwise every finding is unfixable noise. Enable it via a preset or
`.editorconfig` once the wrapper exists.

## How to fix violations

Route logging through a conditional wrapper.

Before:

```csharp
void OnPickup(Item item)
{
    Debug.Log("picked up " + item.name);
}
```

After:

```csharp
public static class GameLog
{
    [System.Diagnostics.Conditional("ENABLE_LOG")]
    public static void Info(string message) => Debug.Log(message);
}

void OnPickup(Item item)
{
    GameLog.Info("picked up " + item.name);
}
```

## When to suppress warnings

Suppress in editor-only tooling (the shipped presets already relax `**/Editor/**` paths)
or in temporary diagnostic code that will not ship.

## How to configure or suppress

- Enable the rule (it is off by default): `dotnet_diagnostic.UPA0005.severity = warning` in `.editorconfig`
- Single call site: wrap it in `#pragma warning disable UPA0005` / `#pragma warning restore UPA0005`
- Whole project: set `dotnet_diagnostic.UPA0005.severity = none`
- Wrapper types: list your wrapper class names in `upa_log_wrapper_types` so calls inside them are not reported

## Configuration

```ini
# Types whose bodies are treated as logging wrappers (comma-separated short names)
upa_log_wrapper_types = Log,GameLog
```

## Related rules

- None. `UNT####` rules do not cover conditional logging wrappers.
