# UPA0027 — Params array allocated at call site

> [English](UPA0027.md) | 繁體中文

| | |
|---|---|
| 類別 | 效能 |
| 預設嚴重度 | 警告(Warning) |
| 預設啟用 | 是 |

## 成因

每幀熱路徑內的呼叫解析到 `params` 多載的**展開形式**——引數是逐個傳入而非傳一個陣列——
因此編譯器會在呼叫點每次建立一個新陣列。

熱路徑指 `MonoBehaviour` 衍生型別上的熱門 Unity 訊息(`Update`、`FixedUpdate`、
`LateUpdate` 等),以及標記了熱路徑屬性(如 `[HotPath]`)的方法。

## 規則說明

`params` 參數有兩種呼叫方式:

```csharp
void Foo(params int[] values) { }

Foo(new[] { 1, 2, 3 });   // normal form —— 陣列是你的,而且看得見
Foo(1, 2, 3);             // expanded form —— 編譯器幫你建一個,看不見
```

展開形式每次呼叫配置一個新陣列。原始碼上沒有任何線索,這正是它值得做成編譯期檢查的原因:
成本是真的、每幀重複,而且讀那一行看不出來。

Unity 專案最常踩到的是 `Mathf.Max`。Unity 只提供雙參數多載,所以第三個引數會安靜地選中
[`Mathf.Max(params float[])`](https://docs.unity3d.com/ScriptReference/Mathf.Max.html):

| API | 固定參數多載 | 超過即配置 |
|---|---|---|
| `Mathf.Max` / `Mathf.Min` | 2 個引數 | **3 個引數就已經在配置** |
| `string.Concat`(string 版) | 最多 4 個 | 5 個以上 |
| `string.Concat`(object 版) | 最多 3 個 | 4 個以上,**另加裝箱** |
| `string.Format` | 格式字串 + 最多 3 個 | 格式字串 + 4 個以上,**另加裝箱** |
| `string.Join`、`Debug.LogFormat` | 無 | 一律 |
| `Path.Combine` | 最多 4 個 | 5 個以上 |

當參數型別是 `params object[]` 時,每個實值型別引數進入陣列時還會各裝箱一次。
規則對這種情形改用另一段訊息,並標明有幾個引數裝箱——因為修法不一樣。

兩種情形不回報。傳入既有陣列屬 normal form:配置是你的、由你控制。零引數呼叫會編譯成
[`Array.Empty<T>()`](https://learn.microsoft.com/dotnet/api/system.array.empty),不配置。

## 如何修正

把呼叫巢狀化,讓每次呼叫都走固定參數多載:

修正前:

```csharp
void Update()
{
    var largest = Mathf.Max(a, b, c, d);
}
```

修正後:

```csharp
void Update()
{
    var largest = Mathf.Max(Mathf.Max(Mathf.Max(a, b), c), d);
}
```

若是你自己的方法,為常見引數數量加上固定參數多載,`params` 版留作後備。
若每幀傳入的引數都相同,把陣列提升為欄位,以 normal form 傳入。

`string.Format` 這類的修法通常是**不要在熱路徑上做格式化**——見 UPA2000。

## 何時抑制警告

熱方法內證實極少執行的冷分支(錯誤處理、罕見狀態轉換),或不在意逐幀配置壓力的
編輯器工具程式碼。

## 如何設定或抑制

- 單一呼叫點:以 `#pragma warning disable UPA0027` / `#pragma warning restore UPA0027` 包住
- 整個專案:於 `.editorconfig` 設定 `dotnet_diagnostic.UPA0027.severity = suggestion`(或 `none`)
- 依路徑:內附 preset 已對 `[**/Editor/**/*.cs]` 放寬;可比照為工具或生成程式碼加區段
- 熱路徑判定:調整下方 `upa_hot_path_*` 選項

## 設定

熱路徑判定為共用設定,可經 `.editorconfig` 調整:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerfCritical
upa_hot_path_include_lambdas = true
```

## 相關規則

- UPA0006 一般性地回報熱路徑上的配置,但把 params 展開——陣列本身與進入陣列的裝箱——
  全部讓給本規則,使一筆配置只產生一條診斷。
- UPA0005 回報直接呼叫 `Debug` 日誌 API。`Debug.LogFormat` 可能同時觸發兩者:
  兩者說的是不同的事,而修掉 UPA0005 會連帶解決 UPA0027。
- UPA2000 負責熱路徑字串組建的建議;本規則不對 `string.Format` 或 `string.Concat`
  提供 CodeFix。
