# UPA3002 — Synchronous file IO unsupported on WebGL

> English | [繁體中文](UPA3002.zh-TW.md)

| | |
|---|---|
| Category | Platform |
| Default severity | Warning |
| Enabled by default | No |
| Active only when | the compilation defines `UPA_TARGET_WEBGL` |

## Cause

A static method call on `System.IO.File` or `System.IO.Directory`, or construction of a
`FileStream`, in a compilation that defines `UPA_TARGET_WEBGL`.

## Rule description

Unity WebGL builds have no real file system. The browser sandbox exposes only a virtual,
in-memory file system whose persistence needs explicit asynchronous syncing — synchronous
`File`/`Directory` calls and `FileStream` construction fail outright or silently write to
memory that vanishes with the tab.

Deliberately still allowed: `Path` (pure string manipulation) and `MemoryStream`
(in-memory, no file system involved).

The rule group runs only when `UPA_TARGET_WEBGL` is defined and is disabled by default —
enable it via the `webgl-addon` preset.

## How to fix violations

- Small settings/save data → `PlayerPrefs` (backed by browser storage on WebGL).
- Larger data → an asynchronous storage layer appropriate to your stack (e.g. a
  IndexedDB-backed plugin), or server-side persistence via `UnityWebRequest`.
- Read-only content shipped with the build → `Addressables`/`StreamingAssets` loaded via
  `UnityWebRequest`, not `File.ReadAllBytes`.

## When to suppress warnings

Suppress code paths already gated behind `#if !UNITY_WEBGL` platform defines, or
editor-only tooling compiled into the same assembly.

## How to configure or suppress

- Enable the rule (it is off by default): `dotnet_diagnostic.UPA3002.severity = warning` in `.editorconfig` (the `webgl-addon` preset does this)
- Single site: `#pragma warning disable UPA3002` / `#pragma warning restore UPA3002`
- Whole project: set `dotnet_diagnostic.UPA3002.severity = none`

## Configuration

None beyond the `UPA_TARGET_WEBGL` define.
