# UPA0011 — SetActive used to toggle UI visibility

> [English](UPA0011.md) | 繁體中文

| | |
|---|---|
| 類別 | Performance |
| 預設嚴重度 | Warning |
| 預設啟用 | 否 |

## 成因

透過 UI 元件的 `gameObject` 呼叫 `SetActive`——即
`uiComponent.gameObject.SetActive(...)` 這個確切形式,且接收者的靜態型別為
`UnityEngine.UI.Graphic` 的衍生型別(Image、Text、RawImage 等)或 `TMPro.TMP_Text`
的衍生型別。

## 規則說明

`SetActive(false)` 會停用整個 GameObject。重新啟用時會執行 `OnEnable`,並強制 canvas
重建該元素的幾何資料,這比原本想要的視覺切換多出大量工作。改為停用元件本身
(`enabled = false`)或操作 `CanvasGroup.alpha`,可以在低得多的重新啟用成本下達到
相同的視覺效果。

這個啟發式判斷刻意收窄——**預設停用**,且只在接收者的靜態型別可確定為 UI 元件時
才回報:

- 單純的 `gameObject.SetActive(...)` 一律不回報:無法靜態判斷該物件是否為 UI,
  而且用 `SetActive` 切換整個面板(同時停止 layout 與 raycast)往往是刻意為之。
- 每個分支只在其型別(`UnityEngine.UI.Graphic` / `TMPro.TMP_Text`)存在於 compilation
  中時才會註冊,因此未使用 uGUI 或 TextMeshPro 的專案不會有任何成本。

## 如何修正

修正前:

```csharp
void SetHealthVisible(bool visible)
{
    _healthIcon.gameObject.SetActive(visible);
}
```

修正後:

```csharp
void SetHealthVisible(bool visible)
{
    _healthIcon.enabled = visible;
}

// Or, for groups of elements:
_healthGroup.alpha = visible ? 1f : 0f;
_healthGroup.blocksRaycasts = visible;
```

## 何時抑制

當停用整個 GameObject 正是目的時可以抑制——例如該元素掛有隱藏期間必須停止運作的
腳本或 collider。

## 如何設定或抑制

- 啟用本規則(預設為關閉):在 `.editorconfig` 設定 `dotnet_diagnostic.UPA0011.severity = warning`
- 單一呼叫位置:以 `#pragma warning disable UPA0011` / `#pragma warning restore UPA0011` 包住
- 整個專案:設定 `dotnet_diagnostic.UPA0011.severity = none`

## 可設定項

無。

## 相關規則

- 無。`UNT####` 規則並未涵蓋 UI 可見性切換。
