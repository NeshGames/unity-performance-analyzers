# UPA0027 — Params array allocated at call site

> English | [繁體中文](UPA0027.zh-TW.md)

| | |
|---|---|
| Category | Performance |
| Default severity | Warning |
| Enabled by default | Yes |

## Cause

A call inside a per-frame hot path resolves to a `params` overload in expanded form — the
elements are passed directly rather than as an array — so the compiler creates a new array
at the call site on every call.

Hot paths are the hot Unity messages (`Update`, `FixedUpdate`, `LateUpdate`, …) on a
`MonoBehaviour`-derived type, plus methods marked with a hot-path attribute such as
`[HotPath]`.

## Rule description

A `params` parameter can be called two ways:

```csharp
void Foo(params int[] values) { }

Foo(new[] { 1, 2, 3 });   // normal form — the array is yours, and visible
Foo(1, 2, 3);             // expanded form — the compiler creates one, invisibly
```

Expanded form allocates a new array per call. Nothing in the source says so, which is what
makes it worth a compile-time check: the cost is real, it repeats every frame, and reading
the call tells you nothing.

The case that catches people out most often in Unity is `Mathf.Max`. Unity ships two-argument
overloads only, so a third argument silently selects
[`Mathf.Max(params float[])`](https://docs.unity3d.com/ScriptReference/Mathf.Max.html):

| API | Fixed-arity overloads | Beyond that |
|---|---|---|
| `Mathf.Max` / `Mathf.Min` | 2 arguments | **3 arguments already allocates** |
| `string.Concat` (string) | up to 4 | 5 or more |
| `string.Concat` (object) | up to 3 | 4 or more, **plus boxing** |
| `string.Format` | format + up to 3 | format + 4 or more, **plus boxing** |
| `string.Join`, `Debug.LogFormat` | none | always |
| `Path.Combine` | up to 4 | 5 or more |

When the parameter is `params object[]`, each value-type argument is also boxed on its way
into the array. The rule reports that case with a different message that says how many
arguments box, because that changes what the fix looks like.

Two cases are not reported. Passing an existing array is normal form: the allocation is
yours and under your control. A zero-argument call compiles to
[`Array.Empty<T>()`](https://learn.microsoft.com/dotnet/api/system.array.empty) and
allocates nothing.

## How to fix violations

Nest the calls so every call uses a fixed-arity overload:

Before:

```csharp
void Update()
{
    var largest = Mathf.Max(a, b, c, d);
}
```

After:

```csharp
void Update()
{
    var largest = Mathf.Max(Mathf.Max(Mathf.Max(a, b), c), d);
}
```

For a method you own, add a fixed-arity overload for the common argument counts and keep
the `params` one as the fallback. If the arguments are the same every frame, hoist the array
into a field and pass it in normal form.

For `string.Format` and friends, the fix is usually to stop formatting on the hot path at
all — see UPA2000.

## When to suppress warnings

Suppress on cold branches inside hot methods (error paths, rare state transitions) where the
call provably runs infrequently, or in editor tooling where per-frame allocation pressure is
not a concern.

## How to configure or suppress

- Single call site: wrap it in `#pragma warning disable UPA0027` / `#pragma warning restore UPA0027`
- Whole project: set `dotnet_diagnostic.UPA0027.severity = suggestion` (or `none`) in `.editorconfig`
- By path: the shipped presets relax rules under `[**/Editor/**/*.cs]`; add similar sections for tooling or generated code
- Hot-path classification: adjust the `upa_hot_path_*` options below

## Configuration

The hot-path classification is shared and configurable via `.editorconfig`:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerfCritical
upa_hot_path_include_lambdas = true
```

## Related rules

- UPA0006 reports allocations on hot paths generally, but leaves params expansions — both
  the array and the boxing of what goes into it — to this rule, so one allocation produces
  one diagnostic.
- UPA0005 reports direct `Debug` logging calls. `Debug.LogFormat` can trigger both: they say
  different things, and fixing UPA0005 removes the UPA0027 report with it.
- UPA2000 owns the advice for string building on hot paths; this rule does not offer a fix
  for `string.Format` or `string.Concat`.
