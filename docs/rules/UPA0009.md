# UPA0009 — List Count not hoisted out of for loop

> English | [繁體中文](UPA0009.zh-TW.md)

| | |
|---|---|
| Category | Performance |
| Default severity | Warning |
| Enabled by default | No |

## Cause

The condition of a `for` loop on a per-frame hot path reads
`System.Collections.Generic.List<T>.Count`, and the loop body does not mutate the same
list.

## Rule description

`List<T>.Count` is a property read that repeats on every iteration. When the list size
does not change inside the loop, hoisting the count into a local before the loop removes
that repeated read — a micro-optimization that is only worth enforcing on hot paths, which
is why this rule is **disabled by default** and enabled by the `strict` preset.

Boundaries drawn to avoid wrong or misleading reports:

- **Arrays are excluded.** `i < array.Length` is the exact form the JIT recognizes to
  eliminate bounds checks; hoisting `Length` can make array loops *slower*.
- **A body that mutates the list** (calls `Add`, `Remove`, `Clear`, etc. on the same
  receiver) is excluded — hoisting there would change semantics.
- **Receiver matching is shallow**: a bare identifier or `this.identifier` (the two are
  treated as the same receiver). Deeper chains such as `a.b.Count` are never reported,
  because mutation of those cannot be judged reliably.

## How to fix violations

Before:

```csharp
void Update()
{
    for (int i = 0; i < _targets.Count; i++)
    {
        Process(_targets[i]);
    }
}
```

After:

```csharp
void Update()
{
    int count = _targets.Count;
    for (int i = 0; i < count; i++)
    {
        Process(_targets[i]);
    }
}
```

## When to suppress warnings

Suppress when the list is mutated indirectly (through a method call the analyzer cannot
see) inside the loop — hoisting would then be incorrect — or when profiling shows the read
is irrelevant.

## How to configure or suppress

- Enable the rule (it is off by default): `dotnet_diagnostic.UPA0009.severity = warning` in `.editorconfig`
- Single call site: wrap it in `#pragma warning disable UPA0009` / `#pragma warning restore UPA0009`
- Whole project: set `dotnet_diagnostic.UPA0009.severity = none`
- Hot-path classification: adjust the `upa_hot_path_*` options below

## Configuration

The hot-path classification is shared and configurable via `.editorconfig`:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerfCritical
upa_hot_path_include_lambdas = true
```
