# UPA1001 — Non-exhaustive enum switch

> [English](UPA1001.md) | 繁體中文

| | |
|---|---|
| 類別 | Correctness |
| 預設嚴重度 | Warning |
| 預設啟用 | 是 |

## 成因

針對 enum 的 `switch` 陳述式或 `switch` 運算式未處理所有已宣告的成員——且沒有
`default` 分支 / `_` 捨棄分支(或雖然有,但 `upa_enum_switch_allow_default` 被設為
`false`)。

## 規則說明

新增 enum 成員卻沒有更新所有針對該 enum 的 switch,是遊戲程式碼中最常見的靜默錯誤
來源之一:狀態機跳過新狀態、道具與傷害類型無人處理地漏過、平台分支悄悄地什麼都不做。
不會有任何 crash;行為就只是錯的。

編譯器只會對 switch **運算式**檢查完整性,而且一旦你加上 `_` 分支就不再檢查
(CS8509)。switch **陳述式**則完全不會被檢查。本規則兩者皆涵蓋,並可選擇在已有
default 分支時仍列出缺少的成員。

以下情況刻意不分析:

- **`[Flags]` enum**——位元組合使得完整性檢查失去意義。
- **帶有 `when` guard、關係/範圍 pattern、或非常數 label 的 switch**——
  無法靜態判斷涵蓋範圍,因此整個 switch 直接跳過,而不做猜測。
- **非 enum 的 switch。**

共用同一數值的成員(`Default = 0, Legacy = 0`)視為一併涵蓋,且訊息中的缺少成員
清單在五個名稱後截斷。

## 如何修正

```csharp
// Before: State.Dead was added last sprint, this switch never learned about it
switch (state)
{
    case State.Idle:    Wait();  break;
    case State.Running: Move();  break;
}

// After
switch (state)
{
    case State.Idle:    Wait();  break;
    case State.Running: Move();  break;
    case State.Dead:    Despawn(); break;
}
```

加上 `default` 分支也能滿足本規則(在預設設定下)——當「其餘一律相同處理」確實是
本意時再這麼做,而不是把它當作消音警告的手段。

## 何時抑制

當某個 switch 刻意只處理一小部分相關子集、而加上 default 分支反而會造成誤導時,
可以抑制。優先考慮加上明確的 `default`,而非直接抑制。

## 如何設定或抑制

- 嚴格模式:在 `.editorconfig` 設定 `upa_enum_switch_allow_default = false`,即使已有
  `default`/`_` 分支也會回報缺少的成員(僅限 IDE——Unity 建置一律使用預設值 `true`,
  見 README 的 Q2 說明)
- 單一 switch:以 `#pragma warning disable UPA1001` / `#pragma warning restore UPA1001` 包住
- 整個專案:在你的 ruleset 中將 UPA1001 設為 `None`

## 可設定項

```ini
upa_enum_switch_allow_default = true   # default; false = default/_ arms do not count
```

## 相關規則

- CS8509(編譯器)涵蓋沒有捨棄分支的 switch 運算式;本規則另外涵蓋 switch 陳述式,
  以及嚴格模式下已有捨棄分支的情況。
