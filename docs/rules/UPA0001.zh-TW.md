# UPA0001 — Component lookup in per-frame method

> [English](UPA0001.md) | 繁體中文

| | |
|---|---|
| 類別 | 效能 |
| 預設嚴重度 | 警告(Warning) |
| 預設啟用 | 是 |

## 成因

在每幀熱路徑內呼叫了 `GetComponent` 家族方法(`GetComponent`、`GetComponents`、`GetComponentInChildren`、
`GetComponentsInChildren`、`GetComponentInParent`、`GetComponentsInParent` 或
`TryGetComponent`——不論泛型或非泛型多載,不論定義在
`UnityEngine.Component` 或 `UnityEngine.GameObject` 上)。所謂每幀熱路徑,是指
`MonoBehaviour` 衍生型別上的熱門 Unity 訊息(如 `Update`、`FixedUpdate`、`LateUpdate`),
或標記了熱路徑屬性(如 `[HotPath]`)的方法。

例外是 `GetComponents`、`GetComponentsInChildren`、`GetComponentsInParent` 的回傳陣列多載:
它們改由 [UPA0017](UPA0017.zh-TW.md) 回報,因為每次呼叫配置的陣列才是較大的成本,
而 UPA0017 的修法正好消除它。同名方法的 `List<T>` 多載不配置記憶體,但仍會執行查找,
因此仍屬於本規則。同一個呼叫只會由兩條規則之一回報,不會兩條都報。

## 規則說明

元件查找是在 Unity 的原生引擎程式碼中實作的。每次呼叫都會跨越 managed–native 邊界,
並在該物件的元件清單中搜尋後才回傳結果。除非有元件被新增或移除,查找結果不會改變,
因此每幀重複搜尋是在做多餘的工作。

`TryGetComponent` 常被建議用來避免配置,但那是**編輯器限定**的差別:Unity 文件記載
`GetComponent` 只在「編輯器中執行時」配置記憶體,「建置後的專案裡不會」,而 player build
實測兩者皆無配置。因此 `TryGetComponent` 同樣會被回報——本規則針對的成本是原生呼叫與
型別搜尋,兩種寫法都要付。該做的是把結果快取起來。

只有熱路徑方法本身的主體(包含其中的 lambda 與區域函式)會被分析。
從熱路徑呼叫的輔助方法內部的呼叫刻意不回報——
本 analyzer 寧可漏報,也不誤報。

## 如何修正

在 `Awake` 或 `Start` 中解析元件一次,快取到欄位,並在熱路徑上使用該欄位。

修正前:

```csharp
public class Mover : MonoBehaviour
{
    void Update()
    {
        GetComponent<Rigidbody>().AddForce(Vector3.up);
    }
}
```

修正後:

```csharp
public class Mover : MonoBehaviour
{
    Rigidbody _rigidbody;

    void Awake()
    {
        _rigidbody = GetComponent<Rigidbody>();
    }

    void Update()
    {
        _rigidbody.AddForce(Vector3.up);
    }
}
```

## 何時抑制

當元件組合確實會在幀與幀之間變動(例如元件會在執行期被新增或移除,
必須重新解析目前的實例),或該呼叫位於熱方法中但實際上極少執行的冷分支上時,
可以抑制此警告。

## 如何設定或抑制

- 單一呼叫點:以 `#pragma warning disable UPA0001` / `#pragma warning restore UPA0001` 包住
- 整個專案:在 `Assets/Default.ruleset` 設定 `<Rule Id="UPA0001" Action="Info" />`(或 `None`)
- 依 assembly:把 `editor-relaxed.ruleset` 複製到 Editor asmdef 資料夾並改名為 `Default.ruleset`;工具程式碼或產生的程式碼所在的 asmdef 資料夾也可比照放一份 `Default.ruleset`
- 熱路徑判定:調整下方的 `upa_hot_path_*` 選項

## 可設定項

熱路徑判定是共用的,設定在通用選項檔 `Assets/Rules.UnityPerformanceAnalyzers.additionalfile`(同樣的 `key = value` 行也可寫進透過 `upa-cli --editorconfig` 傳入的 `.editorconfig`):

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerformanceCritical
upa_hot_path_include_lambdas = true
```

## 相關規則

- UPA0017 負責熱路徑上回傳陣列的 `GetComponents*` 多載(見「成因」)。照它的建議改用
  `List<T>` 多載搭配快取的 list 之後,該呼叫會改由本規則回報,進一步追問這次查找是否真的需要每幀執行。
- `UNT0026`(Microsoft.Unity.Analyzers)會標記從未做 null 檢查的 `GetComponent` 結果,
  且不限呼叫情境。兩條規則可以共存:UPA0001 只在熱路徑上觸發。
