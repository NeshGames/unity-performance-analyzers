# UPA0012 — TextMeshPro text assignment instead of SetText

> English | [繁體中文](UPA0012.zh-TW.md)

| | |
|---|---|
| Category | Performance |
| Default severity | Warning |
| Enabled by default | No |

## Cause

The `text` property of a `TMPro.TMP_Text`-derived component (`TextMeshProUGUI`,
`TextMeshPro`) is assigned inside a per-frame hot path: a hot Unity message such as
`Update` on a `MonoBehaviour`-derived type, or a method marked with a hot-path attribute.

## Rule description

Every assignment to `text` stores the string and marks the text dirty, triggering mesh
regeneration. The common per-frame pattern — `label.text = value.ToString()` or string
concatenation — additionally allocates a fresh intermediate string each frame. The `SetText`
overloads format numeric arguments into the component's internal buffer instead, and measured
on IL2CPP that difference is the whole of it:

| Per assignment | `label.text = score.ToString()` | `label.SetText("{0}", score)` |
|---|---|---|
| Unity 2022.3, IL2CPP | 4.51 B | **0 B** |
| Unity 6, IL2CPP | 4.92 B | **0 B** |

20,000 iterations, against a control that allocates the same string in the same loop, so the
zero is the runtime and not the instrument. Assigning a *constant* string allocates nothing
either — that case costs only the dirty flag, which both forms pay.

**In the editor the numbers invert.** Measured in editor batch mode on Mono, `SetText`
allocates 16.79 B on 2022.3 and 78.85 B on Unity 6, against 31 B for the assignment — so
profiling in the editor shows this rule's advice costing more, not less. The numbers above
are from IL2CPP players, which is what a shipped game runs. Profile a build before deciding
this rule is wrong.

The rule is **disabled by default**: assigning a constant string on a hot path is reported
too (the dirty-flag cost still applies), but the rule's main value is the formatted-value
pattern, so it is left to the `strict` / `cysharp-stack` presets to enable.

Only setter usage is reported; reads of `text` are ignored. The rule registers only when
`TMPro.TMP_Text` exists in the compilation, so projects without TextMeshPro pay nothing.

## How to fix violations

Before:

```csharp
void Update()
{
    _scoreLabel.text = _score.ToString();
}
```

After:

```csharp
void Update()
{
    _scoreLabel.SetText("{0}", _score);
}
```

Better still, update the label only when the value actually changes instead of every frame.

## When to suppress warnings

Suppress when the assignment is guarded so it runs only on change, or when the text is
genuinely dynamic non-numeric content where `SetText` formatting does not apply.

## How to configure or suppress

- Enable the rule (it is off by default): `dotnet_diagnostic.UPA0012.severity = warning` in `.editorconfig`
- Single call site: wrap it in `#pragma warning disable UPA0012` / `#pragma warning restore UPA0012`
- Whole project: set `dotnet_diagnostic.UPA0012.severity = none`
- Hot-path classification: adjust the `upa_hot_path_*` options below

## Configuration

The hot-path classification is shared and configurable via `.editorconfig`:

```ini
upa_hot_path_messages = Update,FixedUpdate,LateUpdate,OnTriggerEnter
upa_hot_path_attributes = HotPath,PerformanceCritical
upa_hot_path_include_lambdas = true
```
